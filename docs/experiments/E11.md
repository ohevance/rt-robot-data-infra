# E11 — QoS 0 이면 수집기가 10초 죽을 때 얼마를 잃나 (QoS 0 vs QoS 1 비교줄)
> 한 줄 요약: 수집기와 장치를 모두 QoS 0 으로 두고 수집기를 10초 죽이자 **508 / 1312 유실**(예측 500 = 50대 × 10초, +8 은 종료·재시작 순간). 같은 장애를 QoS 1 + 지속 세션으로 하면 **0 / 1311**([E08](E08.md)). "QoS 1 은 공짜가 아니지만 수집기 재시작을 공짜로 만든다"의 숫자.

[← E08 재측정 0/1400](E08.md) · [E12 큐 상한 →](E12.md) · [실험 목록](../EXPERIMENTS.md)

## 1. 왜 했나 (이유)
- 순서도의 마름모: **"QoS 1 이 아니어도 0 인가?"** → 아니오. [E08](E08.md)에서 수집기 10초 중단의 유실이 0 이 된 것은 **QoS 1 + 지속 세션** 덕인데, 그 보호가 없을 때 얼마를 잃는지 숫자가 없으면 "0" 의 값어치를 설명할 수 없다. 표③-2 에 **보호 있음 / 없음 두 줄**이 나란히 있어야 독자가 차이를 본다.
- 또 하나: 예측값이 있다. 50대 × 1 Hz × 10초 = 500개. 실측이 예측과 맞으면 유실 계산식([E07](E07.md)에서 고친 것)이 옳다는 **두 번째 검증**이 된다.
- 합격선: 이 실험은 "0" 을 기대하는 것이 아니라 **유실 > 0 이어야 정상**이다 — `assert_results.py` 의 collector 규칙: label 에 qos1 이 있으면 유실 0, qos0 이면 유실 > 0. 그리고 그 값이 예측 500 근처여야 한다.

## 2. 어떻게 했나
| 항목 | 값 |
|---|---|
| 환경 | WSL2, 컨테이너 3개, 가상 50대 1 Hz |
| 수집기 | `collector.py`(기본 = **QoS 0**, clean_session=True — 지속 세션 없음) |
| 장치 | `virtual_fleet.py --telemetry-qos 0`(기본값) |
| 장애 | `inject.py --fault collector --duration 10 --label qos0` — 수집기에 SIGTERM → 10초 → 같은 명령·같은 환경(venv, PATH)으로 재시작 |
| 비교 대상 | 같은 장애를 `--qos 1` + `--telemetry-qos 1` 로 한 [E08](E08.md) 의 0 / 1311 |

```bash
python3 fleet/collector/collector.py                                  # 터미널 2 (QoS 0)
python3 fleet/agent/virtual_fleet.py --count 50 --rate 1.0            # 터미널 3 (QoS 0)
python3 fleet/chaos/inject.py --fault collector --duration 10 --label qos0
python3 fleet/chaos/assert_results.py docs/measurements/fault_collector_qos0.json
```
함정: 지속 세션은 **구독자가 QoS 1 로 구독하고 발행자도 QoS 1 로 보내야** 브로커가 큐에 담는다. 한쪽만 1 이면 min(0, 1) = 0 → 유실. 그래서 두 줄의 조건을 "둘 다 0" 과 "둘 다 1" 로 맞췄다.

## 4. 결과 분석 — 처음 읽는 사람을 위한 설명
### 4-1. 용어와 단위
- **QoS(Quality of Service) 0**: "보내고 잊음". 가장 가볍고 확인이 없다. 받는 사람이 없으면 그냥 사라진다.
- **QoS 1**: "적어도 한 번". 받는 쪽의 영수증(PUBACK)이 올 때까지 책임진다. 브로커는 구독자가 없는 동안 메시지를 들고 있을 수 있다 — 단, 구독자가 **지속 세션**으로 등록돼 있을 때만.
- **지속 세션(clean_session=False)**: "내가 잠깐 없어도 내 몫을 들고 있어 달라"는 구독자의 예약. 같은 client_id 로 돌아와야 받는다.
- **SIGTERM 재시작**: 수집기를 곱게 죽이고 같은 명령으로 다시 띄우는 것. 그 사이 10초 동안 수집기가 없다.
- **기대 수신(expected)**: 장애 직전 마지막 seq 부터 집계 시각까지 장치들이 만든 메시지 수. **유실 = 기대 − 실제**.
- 단위: **개** 메시지, **대** 장치, **초** 시간, **Hz** 초당 횟수.

### 4-2. 쉬운 예제
- 비유: QoS 0 은 엽서 — 우편함(수집기)이 없으면 집배원이 그냥 버린다. QoS 1 + 지속 세션은 등기 — 수신자가 부재중이면 우체국(브로커)이 보관함에 넣어 두고, 돌아와서 같은 이름을 대면 내준다.
- 계산: 50대 × 1개/초 × 10초 = **500개**가 수집기 없는 동안 생긴다. QoS 0 이면 전부 버려져야 하므로 예측 500. 실측 508 = 500 + **8** — 8개는 수집기가 SIGTERM 을 받아 종료되는 순간과 재시작되어 구독을 다시 거는 순간의 가장자리(각각 1초 미만)에 지나간 메시지. QoS 1 이면 500 개 모두 브로커 큐에 담겼다가 재접속 때 1~2초 안에 쏟아져 들어온다(그래서 복귀 시간 1.6초는 두 조건이 같다).

### 4-3. 숫자가 말하는 것
- 합격선 **통과**: 유실 > 0 이고 예측 500 과 1.6% 차이(508). 유실 계산식이 예측 가능한 상황에서 예측값을 낸다 → [E07](E07.md)에서 고친 식의 두 번째 검증.
- 확인: QoS 0 과 1 의 차이는 **복귀 속도가 아니라 유실**이다(1.6초 vs 1.6초, 508 vs 0). 즉 QoS 1 의 비용은 시간이 아니라 트래픽(PUBACK 왕복)과 브로커 메모리(큐)다.
- 확인: QoS 1 의 보호는 "수집기 재시작" 에만 해당한다. 브로커 자체가 죽는 경우는 장치 버퍼(store-and-forward)가 맡는다([E05](E05.md)·[E08](E08.md)의 broker 줄).
- 추정: +8 의 정확한 분배(종료 순간 몇 개, 재시작 순간 몇 개)는 재지 않았다. 둘 다 "1초 미만의 가장자리"라는 것만 확인.
- 설계 결론(`DECISIONS.md` D4 "텔레메트리 QoS 기본은 0, 옵션으로 1"): 기본은 가벼운 QoS 0 으로 두되, 수집기 재시작에서 유실 0 이 필요하면 장치·수집기 **둘 다** 1 로. 그 차이를 표③-2 두 줄로 남겨 독자가 고르게 한다.
- 다음 질문: QoS 1 큐는 무한한가? → [E12](E12.md) 큐 상한.

## 5. 면접 한 문장
- "QoS 1 은 공짜가 아니지만 수집기 재시작을 공짜로 만든다 — 같은 10초 장애에서 QoS 0 은 508개(예측 500), QoS 1 지속 세션은 0개, 복귀 시간은 둘 다 1.6초."
