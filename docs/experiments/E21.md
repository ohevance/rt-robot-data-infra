# E21 — 위로보틱스 공개 모델 ALLEX(48 자유도)를 같은 노드로: 물리 한 주기 비용은 6 자유도의 몇 배인가
> 한 줄 요약: 제어 코드·백엔드는 그대로 두고 로봇 프로필만 `robots/allex.yaml` 로 바꿔 **48 자유도 상체 휴머노이드**를 1 kHz 로 돌린다. 합격선은 E15 와 같은 p99 < 900 us. **결과: 아직 실행 전** — 아래 3절의 표는 첫 실행 뒤 채운다(숫자를 미리 적지 않는다).

이전: [E16](E16.md) (물리가 보여 준 새 사실) · 다음: 없음

## 1. 왜 했나 (이유)
- 지원하는 회사가 2026-06-29 에 ALLEX 시뮬레이션 모델을 공개했다(MJCF · USD · URDF, BSD-3). 공고 ④(시뮬레이션)에 "회사의 로봇으로" 답할 수 있는 기회다.
- 이 저장소의 주장 — "로봇을 바꾸는 일은 설정 파일을 바꾸는 일이다"(백엔드 인터페이스 + 이름으로 관절 잇기) — 를 6 자유도 팔이 아닌 **48 자유도 휴머노이드**로 검증한다. 바뀌는 파일이 프로필 하나(+ 모델 받는 스크립트)뿐인지가 첫 번째 확인 항목이다.
- 물리 비용은 자유도와 접촉 수에 따라 커진다. E15 의 0.9 %(6 자유도)가 48 자유도에서 몇 % 가 되는지가 두 번째 확인 항목이다. 1 ms 예산표(설계서 3.7절)의 "제어 + 물리" 줄이 이 값으로 바뀐다.
- 합격선: E15 와 같다. 한 주기(물리 한 걸음 + 상태 읽기) **p99 < 900 us**. 더 엄격한 목표는 예산의 10 % 아래.

## 2. 어떻게 하나
| 항목 | 값 |
|---|---|
| 모델 | `wirobotics-rih/allex_model` 커밋 5e12052(v0.2.0), `mjcf/scene.xml`. 관절 60(수동 12 포함), **position 액추에이터 48**, timestep 2 ms |
| 프로필 | `robots/allex.yaml` — dof 48, `mujoco.joints` 48개(MJCF 액추에이터 순서). 수동 관절(손가락 DIP·IP, 허리 링크)은 등식 제약으로 따라 움직이므로 명령 대상이 아니다 |
| 걸음 맞추기 | 모델 2 ms > 제어 주기 1 ms → 백엔드의 올림 규칙으로 `mj_step` 1번 × 1 ms(걸음을 줄이는 쪽이므로 안정) |
| 바뀐 코드 | `test_mujoco_backend.cpp` 가 관절 수·이름·출력 파일을 환경변수로 받게 한 것뿐(`RT_MUJOCO_DOF` · `RT_MUJOCO_JOINTS` · `RT_MUJOCO_OUT`). `control_step.cpp` · `mujoco_backend.cpp` · 노드는 그대로 |
| 테스트 | 관절 0(R_Shoulder_Pitch) 에 +0.3 rad, 나머지 47 관절은 현재 위치 유지, 1 kHz × 2,000 주기, 한 주기 비용 p50/p99/max |
| 환경 | ① GitHub 러너(CI `mujoco` 잡의 ALLEX 단계, 아티팩트 `mujoco_backend_allex_ci.json`) ② WSL 단독 테스트 ③ WSL ROS 2 노드 안 `work_us` |

```bash
# [WSL 창] 모델 받기 (약 250 MB, 한 번) → 테스트 빌드는 E15 와 같은 build/rt_core_mj
bash scripts/get_allex.sh
cmake --build build/rt_core_mj -j
RT_MUJOCO_MODEL=$PWD/third_party/allex_model/mjcf/scene.xml RT_MUJOCO_DOF=48 \
RT_MUJOCO_JOINTS="$(python3 scripts/profile_joints.py robots/allex.yaml)" RT_MUJOCO_OUT=mujoco_backend_allex_wsl.json \
LD_LIBRARY_PATH=$PWD/third_party/mujoco/lib ./build/rt_core_mj/test_mujoco_backend
```
노드 안에서(③): `backends/mujoco/README.md` §5.

## 4. 처음 읽는 사람을 위한 분석 — 무엇을 보면 되나
- **바뀐 파일 수**가 첫 결과다. 프로필 + 스크립트 + 테스트의 환경변수 처리 외에 제어 코드가 바뀌었다면 "로봇을 바꾸는 일은 설정 파일을 바꾸는 일"이라는 주장이 틀린 것이다.
- p99 가 E15 의 몇 배인지 본다. 자유도 8배(6 → 48)에 손가락 접촉까지 있으므로 수 배 ~ 수십 배를 예상한다. 1 ms 의 10 %(100 us)를 넘으면 1 ms 예산표를 다시 쓰고, 500 Hz 프로필(주기는 프로필의 숫자 하나)을 검토한다.
- 관절 0 이 2초 뒤 목표의 절반 이상 움직였는지(`joint0_moved_rad`)도 함께 본다 — 모델이 명령에 반응한다는 뜻이다. 어깨 관절은 kp 5000 의 강한 서보라 중력에 밀리지 않아야 한다.
- 한계: 중력 보상·관절별 변화량 제한은 없다(E16 과 같은 처짐이 48 관절에서 어떻게 나오는지는 기록 파이프라인(E20)으로 따로 본다).
