# E03 — ROS 2 노드 안에서도 1 kHz 루프가 유지되고 안전장치가 동작하는가
> 한 줄 요약: 측정기가 아니라 진짜 제어 노드(`rt_control_node`) 안에서 1 kHz 를 돌려도 드롭 0, 깨어남 지연 p99 278 / max 679 us(WSL 참고값), 워치독 1회 작동·변화량 제한 10회·`/joint_states` 100.0 Hz → **통과(✓)**. 이어진 질문: 물리 시뮬레이션 비용도 1 ms 안에 드나 → E15.

## 1. 왜 했나 (이유)
- [E02](E02.md) 의 곁가지 질문: **"노드 안에서도 드롭 0 인가?"** — `jitter_bench` 는 혼자 도는 작은 프로그램이다. 진짜 제품은 ROS 2(로봇 소프트웨어의 표준 미들웨어) 노드 안에서 토픽을 받고 보내며 돈다. 그 안에서도 RT 루프가 같은 주기와 같은 지연을 유지하는지, 그리고 제어 단계의 안전장치(워치독·변화량 제한)가 실제로 동작하는지를 봐야 한다.
- 합격선: (1) `/rt_status` 의 드롭(timing_drops, state_drops) 0 (2) 깨어남 지연이 측정기(E02)와 같은 급 (3) 명령을 끊으면 워치독이 "tripped" 로, 다시 주면 "ok" 로 (4) 큰 목표를 주면 변화량 제한이 센다. 왜 이 넷인가 — "루프가 돈다"가 아니라 "루프가 돌면서 로봇을 보호한다"를 보여야 하기 때문.

## 2. 어떻게 했나
| 항목 | 값 |
|---|---|
| 어디서 | WSL2 Ubuntu 24.04 + ROS 2 Jazzy, 커널 `6.18.33.2-microsoft-standard-WSL2`(PREEMPT_RT 아님) |
| 무엇으로 | `rt_control_node`(`rt_control/ros2_adapter`) + 백엔드 `sim_lag`(1차 지연 모델), 파라미터 `robots/so101.yaml` → `so101.params.yaml` |
| 조건 | RT 스레드 1 kHz, `/joint_states` 100 Hz 발행, `/rt_status` 1 Hz 발행, 명령 `/joint_command` 50 Hz, 워치독 50 ms, 변화량 제한 0.05 rad/주기 |

`rt_control/ros2_adapter/README.md` 의 터미널 1·2·3:
```bash
# 터미널 1 — 노드 (WSL 은 SCHED_FIFO 권한이 없어 한도를 먼저 올린다)
sudo prlimit --pid $$ --rtprio=99 --memlock=unlimited
ros2 run rt_control_ros2 rt_control_node --ros-args --params-file ~/rt-robot-data-infra/rt_control/ros2_adapter/config/so101.params.yaml
# 터미널 2 — 관찰
ros2 topic echo /rt_status            # 1초마다 JSON 한 줄
ros2 topic hz /joint_states           # average rate: 100.0 근처
# 터미널 3 — 명령 50 Hz (Ctrl+C 로 끊으면 50 ms 뒤 워치독이 tripped)
ros2 topic pub -r 50 /joint_command sensor_msgs/msg/JointState "{position: [0.3, -0.2, 0.1, 0.0, 0.0, 0.5]}"
```

## 4. 결과 분석 — 처음 읽는 사람을 위한 설명
### 4-1. 용어와 단위
- **ROS 2 / 노드 / 토픽**: 로봇 프로그램들을 "노드"라는 조각으로 나누고, 조각끼리 "토픽"이라는 이름 붙은 통로로 메시지를 주고받는 틀. `/joint_command`(목표 각도, 들어오는 것), `/joint_states`(현재 각도, 나가는 것), `/rt_status`(통계, 나가는 것).
- **Hz(헤르츠)**: 1초에 몇 번. 1 kHz = 1,000 Hz = 1 ms 마다. 100 Hz = 10 ms 마다. 50 Hz = 20 ms 마다.
- **rad(라디안)**: 각도 단위. 1 rad ≈ 57.3°. 0.05 rad ≈ 2.9°, 0.5 rad ≈ 28.6°.
- **워치독(watchdog)**: "명령이 50 ms 동안 안 오면 멈춘다"는 안전장치. 상위 컴퓨터가 죽거나 선이 빠졌을 때 로봇이 마지막 명령대로 계속 움직이는 사고를 막는다(`../GLOSSARY.md` "워치독").
- **변화량 제한(step limit)**: 목표가 갑자기 크게 바뀌어도 한 주기에 0.05 rad 까지만 움직인다. 급변 명령(오타, 버그)이 팔을 휘두르지 못하게.
- **드롭(drops)**: RT 스레드가 상태를 발행 스레드로 넘기는 벨트(링 버퍼)에서 버려진 개수. 0 = 발행 쪽이 RT 를 따라가고 있다.
- **prlimit / RLIMIT_RTPRIO**: 일반 사용자가 SCHED_FIFO 를 쓸 수 있게 한도를 올리는 명령. 빼먹으면 `rt_status` 의 `sched_fifo` 가 false 로 나온다.

### 4-2. 쉬운 예제
- 비유: 무전기로 1초에 50번 "오른쪽으로 조금" 을 듣는 운전사. 무전이 0.05초(50 ms) 끊기면 즉시 브레이크(워치독). "오른쪽으로 90° 꺾어" 라는 말이 와도 한 번에 2.9° 씩만 꺾는다(변화량 제한).
- 계산: 그리퍼 목표 0.5 rad, 한 주기 최대 0.05 rad → 0.5 / 0.05 = **10 주기** = 10 ms 에 걸쳐 도달. `step_limited` 가 정확히 10 인 이유다. 워치독 50 ms 는 50 Hz 명령(20 ms 간격)의 2.5배 — 명령 한두 개가 늦어도 오작동하지 않고, 진짜 끊기면 50 ms 안에 선다.

### 4-3. 숫자가 말하는 것
- 합격선 넷 모두 **통과**: 드롭 0 · 지연이 E02 의 FIFO 조건(p99 273 / max 937)과 같은 급(p99 278 / max 679) · 워치독 tripped→ok→tripped 1회 · step_limited 10.
- 확인: ROS 2 의 콜백 스레드와 RT 스레드를 **락 없는 벨트(SPSC 링)** 로만 잇는 구조가 노드 안에서도 1 kHz 를 지켰다. `/joint_states` 가 정확히 100.0 Hz 인 것은 발행 스레드가 RT 스레드를 밀어내지 않는다는 뜻.
- 확인(함정): `kill $NODE` 가 `ros2 run` 껍데기만 죽이고 노드가 고아로 남아 두 번째 실행의 통계에 섞여 나왔다 → `pkill -f rt_control_node` 로 바꿈. "죽였다"는 프로세스 트리를 확인해야 성립한다.
- 추정: max 679 us 는 WSL2 가상 커널의 한계(E02 와 같은 모양)이며 노드 구조의 문제가 아니다. 근거: 같은 코드가 Pi 4 RT 커널에서는 다른 숫자를 낸다([E19-a](E19a.md)).
- 그래서 다음 질문: "물리 시뮬레이션(MuJoCo)을 붙여도 한 주기 작업이 1 ms 안에 드나?" → E15 (`docs/EXPERIMENTS.md`).

## 5. 면접 한 문장
- "RT 루프를 ROS 2 노드 안에 넣어도 락 없는 벨트 두 개로만 연결해서 1 kHz·드롭 0 을 유지했고, 워치독 50 ms 와 변화량 제한 0.05 rad 가 `/rt_status` 숫자(trips 1, step_limited 10)로 동작을 증명한다."
