# E15 — 물리 시뮬레이션(MuJoCo) 한 주기 비용: 1 ms 예산의 몇 % 인가
> 한 줄 요약: "제어 루프 안에서 진짜 물리(중력·관절 한계·모터)를 매 주기 계산해도 1 kHz 가 지켜지나?" → 6축 팔(SO-ARM100) 한 걸음이 **p50 6.4 / p99 8.5 / max 29.4 us** (GitHub 러너) = 1 ms 예산의 **0.9 %**. WSL 단독 4.9 / 6.3 / 20.8 us, ROS 2 노드 안 제어+물리 `work_us` 41 / 145 / 247 us.

이전: [E03](E03.md) (노드 안 RT 루프) · 다음: [E16](E16.md) (물리가 보여 주는 새 사실)

## 1. 왜 했나 (이유)
- [E03](E03.md)까지의 "로봇"은 `SimLagBackend` — "목표를 천천히 따라간다"는 수식 한 줄이었다. 노드 흐름 검증에는 충분하지만 "시뮬레이션"이라 부르기는 어렵다. 공고 ④(시뮬레이션·CI)에 답하려면 **물리 엔진 위**에서 같은 제어 코드가 돌아야 한다.
- 순서도의 점선 화살표: E03 통과 뒤 **"물리 비용도 1 ms 안에 드나?"** 물리 계산이 주기의 상당 부분을 먹으면 깨어남 지연(표①)과 합쳐 1 ms 를 넘길 수 있다.
- 합격선: 한 주기(물리 한 걸음 + 상태 읽기) **p99 < 900 us**(주기의 90 %, `test_mujoco_backend.cpp` 가 기계적으로 검사). 더 엄격한 목표로는 **예산의 10 % 아래** — 그래야 깨어남 지연에 쓸 여유가 남는다.

## 4. 결과 분석 — 처음 읽는 사람을 위한 설명
### 4-1. 용어와 단위
- **MuJoCo**: 로봇·물체의 움직임을 뉴턴 역학으로 계산하는 물리 엔진. 모델 파일(XML)에 관절·질량·모터를 적어 두면 "힘을 주면 어떻게 움직이나"를 계산해 준다.
- **Menagerie**: DeepMind 가 검증해 모아 둔 로봇 모델 모음. 우리는 SO-ARM100(실물 SO-101 과 같은 계열의 6자유도 팔)을 쓴다.
- **mj_step / timestep**: 물리를 "한 걸음(예: 1 ms)" 진행시키는 함수와 그 걸음 크기. 제어 주기 1 ms 안에 걸음을 몇 번 밟을지(substeps)는 올림으로 정한다 — 걸음을 키우면 물리가 불안정해지므로 작게만 바꾼다(`DECISIONS.md` 11/03 D5).
- **qpos / qvel / ctrl**: 관절 위치 배열 / 관절 속도 배열 / 모터 명령 배열. `ctrl` 에 목표각을 쓰고 `mj_step` 뒤 `qpos` 를 읽는다.
- **액추에이터(position 타입)**: "이 각도로 가라"고 하면 내부 PD 제어로 토크를 내는 모터 모델. 토크를 직접 주는 motor 타입과 다르다 — 이 모델이 position 타입인지가 D5 의 "미검증 3번"이었고 CI 가 확인했다(관절 0 이 2초에 0.2988 rad 이동).
- **us(마이크로초)**: 1/1,000,000 초. 1 ms = 1,000 us. 1 kHz = 1초에 1,000번 = 주기 1 ms.
- **p50 / p99 / max**: 2,000주기 중 가운데 / 99 % 지점 / 가장 느린 한 번.
- **work_us**: ROS 2 노드의 `rt_status` 에 찍는, 매 주기 "일한 시간"(깨어남 지연은 `wake_us` 로 따로). 제어 단계(최신 명령·워치독·변화량 제한·상태 머신) + 물리 + 상태를 벨트(SPSC 링)에 올리는 시간.
- **rad(라디안)**: 각도 단위. 1 rad ≈ 57.3°. 0.3 rad ≈ 17°.

### 4-2. 쉬운 예제
- 비유: 1 ms 주기는 "1초짜리 식사 시간"이고, 물리 계산은 그중 **0.009초(0.9 %)** 만 쓴다. 나머지 99 % 는 "제시간에 식탁에 앉는 것"(깨어남 지연)에 달려 있다 — 그래서 표①(RT 커널)이 핵심이다.
- 계산 예: 노드 안 `work_us` p99 145 us 는 단독 테스트 p99 6.3 us 의 20배가 넘는다. 차이의 재료(추정): 1 kHz 로 돌면서 캐시가 식는 것, WSL 가상 커널의 선점, RT 우선순위 없이 돌린 터미널(`sched_fifo=false`). 그래도 1 ms 의 **15 %** 안이라 예산은 남는다.
- 계산 예(여유): 깨어남 max(표① Pi RT 격리 189 us) + 일 max(247 us) = 436 us < 1,000 us. 2 kHz(500 us 주기)였다면 턱밑이다.

### 4-3. 숫자가 말하는 것
- 합격선: **통과**. 테스트 기준(p99 < 900 us)은 100배 여유, 엄격 기준(예산 10 % 아래)도 러너 0.9 %, WSL 0.6 % 로 통과. 노드 안 전체 일(물리 포함)도 15 %.
- 확인: 러너(6.4 / 8.5 / 29.4)와 WSL(4.9 / 6.3 / 20.8)이 같은 급 — 환경이 아니라 모델 크기(6자유도)가 비용을 정한다. 관절이 수십 개인 휴머노이드(ALLEX 자리)에서는 다시 재야 한다 — 이 수치를 그대로 옮기면 안 된다.
- 확인: 제어 코드(`control_step.cpp`)와 노드는 **한 줄도 안 바뀌고** 로봇이 수식 한 줄에서 물리로 바뀌었다. Backend 인터페이스를 둔 이유가 실행으로 증명된 것(`DECISIONS.md` 11/03 D5).
- 확인(함정 2건, LOG): colcon install 뒤 `libmujoco.so` 를 못 찾는 rpath 소실 → `CMAKE_INSTALL_RPATH_USE_LINK_PATH TRUE`; 다른 RMW 로 떠 있던 ros2 데몬 때문에 `topic echo` 가 토픽을 못 봄 → `ros2 daemon stop`.
- 그래서 다음에 무엇을 물었나: 물리는 싸다는 것을 알았다. 그럼 **물리가 있어야만 보이는 새 사실**이 있나? → [E16](E16.md) 중력 처짐.

## 5. 면접 한 문장
- "6축 팔의 MuJoCo 한 걸음은 p99 8.5 us, 1 kHz 예산의 0.9 % 였다 — 물리는 공짜에 가깝고 예산의 나머지는 전부 '제때 깨어나는 것'의 몫이라, 표①의 RT 커널 실측이 왜 핵심인지가 숫자로 설명된다."
