# E19-c — RT 커널 + CPU 3 격리(isolcpus): 그 CPU 의 다른 일을 치우면
> 한 줄 요약: 커널 부팅 인자 `isolcpus=3 nohz_full=3 rcu_nocbs=3` 으로 CPU 3 을 일반 스케줄링에서 떼어 내고 RT 스레드만 올렸다 → 부하 max **311 → 189.3 us**, `work time` max **86 → 53.1**(일하는 동안 거의 안 밀림). "부하 max < 200? 일하는 동안 안 밀리나?" 에 **예** → **표① 통과**. 일반 커널 781 에서 출발해 4.1배.

## 1. 왜 했나 (이유)
- [E19-b](E19b.md) 의 질문: **"그 CPU 의 다른 일(stress·IRQ·커널 스레드) 때문인가?"** — 고정은 효과가 없었다. 그렇다면 CPU 3 에 올라오는 다른 것들을 **아예 못 올라오게** 하면 어떻게 되나.
- 순서도의 마름모: **"부하 max < 200? 일하는 동안 안 밀리나?"** — 두 번째 조건이 중요하다. `work time` 이 50 us 그대로 나오면 "그 CPU 에 경쟁자가 없다"는 직접 증거가 된다.
- 합격선 200 us: E18 §1 과 같다(1 ms 예산에서 지연에 줄 몫 + Pi 4 RT 의 알려진 수준).

## 2. 어떻게 했나
| 항목 | 값 |
|---|---|
| 어디서 | Pi 4B, `6.8.0-2054-raspi-realtime`, `/sys/kernel/realtime` = 1 |
| 바꾼 것 | `/boot/firmware/cmdline.txt` 끝에 `isolcpus=3 nohz_full=3 rcu_nocbs=3` 추가 → 재부팅 → `/sys/devices/system/cpu/isolated` = 3 |
| 측정 | `jitter_run.sh pi4_rt_stress_isol 60 stress 3` — RT 스레드는 `--cpu 3` 으로 격리된 CPU 에, stress-ng 4개는 CPU 0~2 에서만 돈다(격리된 CPU 에는 커널이 일반 작업을 올리지 않으므로) |
| 열 | 재부팅으로 식은 상태에서 시작, 44.8 → 63.8 °C, 스로틀 0 |

`docs/SETUP_RT_MEASURE.md` 7단계:
```bash
sudo cp /boot/firmware/cmdline.txt /boot/firmware/cmdline.txt.bak
sudo sed -i '1 s/$/ isolcpus=3 nohz_full=3 rcu_nocbs=3/' /boot/firmware/cmdline.txt    # 한 줄 파일의 끝에 덧붙인다
sudo reboot
cat /sys/devices/system/cpu/isolated          # 3
sudo scripts/jitter_run.sh pi4_rt_stress_isol 60 stress 3
```
되돌리기: `sudo cp /boot/firmware/cmdline.txt.bak /boot/firmware/cmdline.txt && sudo reboot`.

## 4. 결과 분석 — 처음 읽는 사람을 위한 설명
### 4-1. 용어와 단위
- **isolcpus=3**: 커널 부팅 인자. "CPU 3 은 일반 스케줄링 대상에서 빼라". 그 뒤로는 우리가 `--cpu 3` 으로 직접 올린 스레드만 거기서 돈다.
- **nohz_full=3**: CPU 3 에서 스레드가 하나만 돌 때 주기적 스케줄러 틱(보통 1초에 수백 번 울리는 커널의 시계 인터럽트)을 끈다. **rcu_nocbs=3**: 커널의 RCU 뒷정리 작업을 CPU 3 에서 하지 않고 다른 CPU 에 맡긴다. 셋을 같이 써야 "비운 CPU"가 된다.
- **고정 vs 격리**: 고정(pin)은 "내 스레드는 여기서만", 격리(isolcpus)는 "여기엔 아무도 오지 마". E19-b 와 E19-c 가 그 차이를 숫자로 보여 준다.
- **`/boot/firmware/cmdline.txt`**: Pi 가 부팅할 때 커널에 넘기는 한 줄짜리 인자 파일. 줄바꿈 없이 끝에 덧붙여야 한다(그래서 `sed '1 s/$/ …/'`).
- **work time**: 매 주기 50 us 바쁘게 도는 데 실제 걸린 시간. 50 에 가까우면 그 CPU 에서 아무도 끼어들지 않았다는 뜻.
- 단위: us = 100만분의 1초, 1 ms = 1,000 us.

### 4-2. 쉬운 예제
- 비유: 3번 계산대를 "직원 전용·손님 줄 금지·매장 방송 수신 안 함"으로 만들었다. 직원(RT 스레드)은 거의 안 끊기고(work 53), 손님 호출(깨어남)에 늦어도 0.19 ms 안에 응답한다.
- 계산: 1 ms 예산에서 깨어남 지연 max 189 us → 189 / 1,000 = **18.9%**. 여기에 우리 제어+물리 작업 p99 145 us(E15)를 더해도 334 us = 33%. 일반 커널은 781 + 145 = 926 us = 93% 였다. 2 kHz(500 us)로 가도 RT+격리는 334 < 500 으로 버틴다.

### 4-3. 숫자가 말하는 것
- 마름모 **"부하 max < 200? 일하는 동안 안 밀리나?" → 예**(189.3, work 53.1). **표① 통과.**
- 확인: 격리가 "보통 나쁜 경우"까지 내렸다 — p99 185(RT) → 108, p99.9 242 → 146. RT 커널이 최악을 자르고(781 → 301), 격리가 나머지를 눌렀다(→ 189). 전체 4.1배.
- 확인: `work time` max 135 → 98 → 86 → **53**. 50 us 일하는 동안 3 us 밖에 안 밀렸다 = CPU 3 에서 경쟁자가 사라졌다는 직접 증거. E19-b 의 추정("그 CPU 위의 다른 일이 범인")이 맞았다.
- 추정: 남은 189 us 는 격리된 CPU 에도 오는 것들 — 타이머 인터럽트 자체의 처리, 전 CPU 공통 동기화(IPI; 메모리 압박 부하가 만든다), Pi 4 SoC 의 메모리 지연. Pi 4 + PREEMPT_RT 의 알려진 바닥(100~200 us)과 맞는다. 더 줄이려면 부하 쪽(`--vm`)을 빼고 재거나 Pi 5 로 — 2주 계획 밖.
- 확인(열): 격리 측정은 44.8 → 63.8 °C 로 제일 덜 더웠다(stress 가 CPU 3 개에서만 돌아서). 스로틀 0.
- 이 가지는 여기서 끝난다. 남은 것은 [E19-d](E19d.md) — 두 도구(cyclictest 132 vs jitter_bench 301)가 왜 다른가.

## 5. 면접 한 문장
- "일반 커널 781 → RT 커널 301 → CPU 고정 311 → CPU 격리 189 us: 커널이 최악을 자르고 격리가 나머지를 눌렀으며, `work time` 이 135 에서 53 us 로 내려온 것이 '그 CPU 에 경쟁자가 없다'는 직접 증거다 — 1 ms 예산의 19%."
