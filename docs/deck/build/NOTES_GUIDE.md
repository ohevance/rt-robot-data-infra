# 장표 설명 문서 작성 규칙 (notes_md/NNN.md → pandoc → notes/NNN.docx)

대상 독자: 왕초보 — 리눅스·ROS·실시간·MQTT 를 처음 듣는 사람도 이 문서를 읽고 장표를 다른 사람에게 설명할 수 있어야 한다.
목표: "이 장표로 다른 사람에게 설명할 수 있다면 다 이해한 것" — 장표의 모든 요소(상자·줄·코드 블록·표 행·숫자)를 빠짐없이 풀어 쓴다.

## 파일
- 경로: `notes_md/NNN.md` (NNN = 장표 번호 3자리). 장표 내용은 `python3 dump_slide.py NNN` 으로 확인한다(이 디렉터리에서 실행)
- 첫 줄: `# 장표 NNN — <장표 제목 그대로>`
- 둘째 줄: `*위치: <crumb 값, 없으면 섹션 이름>*`

## 차례 (절 제목을 그대로 쓴다. 해당 없는 절은 "해당 없음" 한 줄)
### 1. 이 장표가 왜 있나
- 바로 앞 장표에서 무엇을 알게 됐고, 그래서 어떤 질문이 생겼으며, 이 장표가 무엇을 답하는지 (3~6문장). 순서도 논리: 앞 장의 답 → 이 장의 질문
### 2. 장표를 하나씩 읽기
- 장표의 요소를 **순서대로 전부**: 상자/마름모 하나하나, 글머리표 한 줄 한 줄, 표의 행 하나하나, 코드는 줄(또는 2~3줄 묶음)마다
- 각 요소마다: 무엇을 말하나 → 왜 그렇게 했나(이유) → 숫자가 있으면 그 숫자의 뜻과 단위
- 코드 장표: 코드를 통째로 다시 베끼지 말고 "N줄: `…`" 식으로 짚어 가며 설명. 변수·함수 이름의 뜻을 풀어 쓴다. 장표의 "읽는 포인트"도 하나씩
- 표 장표: 열(헤더)의 뜻을 먼저, 그 다음 행마다
- 순서도(chain) 장표: 상자 → 마름모(기준) → 화살표 글(답) 순서대로. "왜 이 기준인가" 와 "왜 이 답이 다음 상자로 이어지나"를 꼭 쓴다
- 들머리(gate) 장표: 들어온 것 / 문제 / 기준 / 확인 방법 / 결과 / 판단 여섯 상자를 각각 풀고, "넘어가는 조건"이 왜 그것인지
- section(장 구분) 장표: [앞에서 안 것] → [이 장의 질문] → [이 장의 답] 과 "이 장의 차례"를 풀어 쓴다
- 그림(image) 장표: 그림 안의 상자와 화살표를 위에서 아래로(또는 왼쪽에서 오른쪽으로) 따라가며 설명 — 그림은 `diagrams/<이름>.mmd` 원본(Mermaid)을 읽으면 글자가 전부 있다
### 3. 용어와 단위
- 이 장표에 나오는 용어마다 한두 문장(처음 읽는 사람 기준). 단위(us, ms, Hz, rad, °C, MB, B …)는 환산 예와 함께 (예: 1 ms = 1,000 us, 1 rad = 57.3°)
### 4. 쉬운 예시
- 실생활 비유 1개 이상(우체국·식당 주문·버스 시간표·택배 등) + 숫자를 넣은 구체 예시 1개
### 5. 숫자의 출처와 다시 확인하는 법
- 숫자마다 어느 파일(docs/measurements/…, docs/experiments/E??.md, docs/LOG.md 날짜, docs/DECISIONS.md 항목 …)에서 왔고, 어떤 명령으로 다시 볼 수 있나
- 확인된 실측과 추정을 구분: 줄 앞에 "확인:" / "추정:"
### 6. 자주 하는 오해·함정
- 초보가 헷갈리기 쉬운 점, 실제 작업 중 겪은 함정(LOG/EXPERIMENTS 의 사고 표) 1~4개
### 7. 면접 한 문장
- 이 장표를 30초로 말한다면 — 한두 문장(따옴표 안에)
### 8. 관련 파일과 다음 장표
- 코드/문서 경로 목록 (저장소 기준 상대 경로), 그리고 "다음 장표 NNN: <제목>" 한 줄 (다음 장표 제목은 SLIDES.md 에서)

## 사실 규칙 (가장 중요)
- 장표에 적힌 내용과 저장소 파일(경로는 저장소 뿌리 기준)에서 확인되는 것만 쓴다. 기억이 애매하면 파일을 열어 본다(sed -n, grep). 확인 못 하면 "추정:" 을 붙이거나 쓰지 않는다
- 숫자는 장표의 숫자와 글자 하나까지 같게. 단위를 반드시 붙인다. 측정 환경(WSL2 참고값 / Pi 4 실측 / GitHub 러너)을 같이 적는다
- 코드 줄 번호는 장표의 file 필드(파일:시작-끝) 기준. 코드 장표를 쓸 때는 반드시 그 파일의 그 줄을 `sed -n '시작,끝p'` 로 다시 읽고 쓴다
- 과장·광고 문구 금지. 모르는 것은 모른다고. "~일 것이다"는 "추정:" 으로
- 보안: 토큰·비밀번호·주소(사설 IP, 서버 주소)·계정 이름·개인 폴더 경로는 쓰지 않는다 — 자리표시(`<사용자>`, `<Pi IP>`, `<서버>`)로 적는다. 다 쓴 뒤 저장소 뿌리에서 `python3 scripts/check_public.py`(docx 안까지 본다)

## 문체·분량
- 한국어 평서체("~한다"). 전문용어는 처음 나올 때 괄호로 풀어 쓴다. 숫자와 단위 사이 한 칸(189 us, 50 Hz)
- 분량: 보통 장표 1,500~3,500자(한글 기준), 코드·순서도·표 장표는 더 길어도 된다. 표지·닫는 장·단순 그림 장표는 800자 내외
- Markdown: 절 제목은 `## 1. …` 처럼 번호 포함, 목록은 `-`, 코드·파일명·명령은 백틱. 표(| |)는 쓰지 않는다(변환 단순화). 수식·이미지 삽입 없음

## 다 쓴 뒤 (이 디렉터리에서)
- `python3 check_notes.py` — 문서 수 = 장표 수, 첫 줄 제목 = 장표 제목, 8개 절, "다음 장표 N+1: <제목>", 옛 숫자·옛 이름이 남지 않았는지. 통과해야 한다
- `./make_notes.sh NNN [NNN …]` — 고친 번호만 docx 로(전부 다시 만들면 내용이 같은 문서도 파일이 바뀐다)
- 장표를 고쳤으면 먼저 `./build.sh`(slides.json · pptx · SLIDES.md), 줄 번호가 밀린 코드 장표는 `python3 dump_slide.py NNN` 으로 코드가 맞는지 본다
