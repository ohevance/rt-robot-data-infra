# 발표 장표 — `rt-robot-data-infra.pptx` (145장) 와 장표마다 하나씩인 설명 문서

이 폴더는 저장소 전체를 **처음 보는 사람에게 처음부터 끝까지 설명하기 위한** 자료다.
"이 장표로 다른 사람에게 설명할 수 있으면 이 저장소를 다 이해한 것" 이 목표라서,
**로봇을 움직이기까지의 과정을 맨 앞에**(왕초보 바탕 지식부터), 단계마다 **핵심 소스 코드를 파일:줄과 함께**, 시험·검증은 뒤로 빼고 과정 안에서는 장표 번호만 가리킨다.
장표 한 장마다 왕초보 기준의 설명 문서가 한 개씩 붙어 있다.

| 무엇 | 어디 |
|---|---|
| 장표 (PowerPoint, 145장, 16:9) | `rt-robot-data-infra.pptx` |

같은 꼴이 세 층에서 반복된다.

- **부(장)의 첫 장표**: `[앞에서 안 것] → ◇[이 장의 질문] → [이 장의 답]` + 이 장의 차례
- **단계(1부 10단계 · 2부 6묶음)의 첫 장표 = 들머리**: `들어온 것 → 문제 → ◇기준 → 확인 방법 → 결과 → 판단 → 다음`.
  그 뒤에 그림 한 장(도형), 핵심 코드 장표(상자 위에 파일:줄), 판단 장표. 실험은 '확인 방법' 상자에 **3부 장표 번호**로만.
- **모든 장표**: 위 오른쪽 알약 = 지금 어디(부 · 단계 · 그림/코드/확인/판단), 아래 `다음 ▶` 다리 = 왜 다음 장으로 넘어가는지.

그림 약속: 회색 상자 = 앞 단계에서 들어온 것, 민트 상자 = 코드/실험, **마름모 = 판단 기준**, 파란 상자 = 확인 방법,
화살표 글 = 그 기준에 대한 답(실제 값), 진한 둥근 상자 = 결론, 붉은 상자 = 실패·원인.

## 2. 발표하는 법 (권장)

1. 3번(목차 순서도)에서 전체 길을 한 번 보여 준다.
2. 1부는 바탕 지식(6번) → 한 장 그림(7번) → 소스 코드 지도(9번)로 '어디에 무엇이 있나'를 먼저 잡고, 단계마다 들머리 → 그림 → 코드 순서로 간다.
   `다음 ▶` 다리의 문장을 그대로 읽으면 다음 단계로 자연스럽게 넘어간다. 시험 이야기가 나오면 "그 실험은 3부 N번에서"라고만 한다.
3. 숫자를 말할 때는 반드시 **어디서 잰 값인지**(WSL2 참고값 / Pi 4 실측 / GitHub 러너)를 같이 말한다.
4. 막히면 그 장표의 `notes/NNN.docx` — 요소 하나하나의 뜻, 용어, 단위, 쉬운 예시, 숫자의 출처, 면접 한 문장이 있다.

## 3. 설명 문서(notes)의 꼴

모든 `notes/NNN.docx` 는 같은 여덟 절이다 (규칙 전문: `build/NOTES_GUIDE.md`).

1. 이 장표가 왜 있나 (앞 장표에서 넘어온 것, 이 장표가 답하는 질문)
2. 장표를 하나씩 읽기 (상자·줄·표 행·코드 줄마다: 무엇 → 왜 → 숫자의 뜻과 단위)
3. 용어와 단위
4. 쉬운 예시 (실생활 비유 + 숫자 예시)
5. 숫자의 출처와 다시 확인하는 법 (`확인:` / `추정:` 구분)
6. 자주 하는 오해·함정
7. 면접 한 문장
8. 관련 파일과 다음 장표

## 4. 다시 만들기 (`build/`)

```
docs/deck/build/
  make_slides.py      내용 모듈들 → slides.json. crumb·next·들머리·그림 끼우기·검증 장표를 3부로 옮기기·{{first:…}}/{{range:…}} 번호 채우기
  content_a.py        0 표지·읽는 법·목차(순서도), 4부 출발, 5부 어디서
  content_b.py        1부 로봇을 움직이는 길 (코드는 cu.code() 로 저장소 파일에서 그대로). 시험 장표는 "verify": True
  content_c.py        2부 데이터의 길 (표③ 사슬·표는 "verify": True)
  content_d.py        6부 측정·테스트·CI, 7부 결정·사고·일정·AI·용어·덧붙임(ALLEX + addenda_1110() 의 여섯 장), 끝
  gates.py            들머리 장표 16장 (1부 10 + 2부 6)
  diagrams_front.py   그림 한 장 장표 9장 + 막대 그래프 1장 (좌표로 그린 도형)
  cu.py               code(파일, 시작, 끝) · ref() — 손으로 베끼지 않으므로 코드가 틀릴 수 없다
  build_deck.js       slides.json → pptx (pptxgenjs). 장표 종류(kind) 16가지와 공통 요소(crumb·next·foot)
  theme_colors.js     테마 색을 pptx 에 써 넣는 도우미 (pptxgenjs 는 테마에 글꼴만 적는다)
  diagrams/*.mmd      그림 원본(Mermaid) → render_diagrams.sh → img/*.png
  dump_slide.py       장표 N 의 내용을 출력 (설명 문서 쓸 때 참고)
  NOTES_GUIDE.md      설명 문서 작성 규칙
  build.sh            장표 전체 다시 만들기: make_slides.py → build_deck.js → make_slides_md.py(../SLIDES.md 장표 목록)
  make_notes.sh       notes_md → notes (pandoc). 번호를 주면 그 문서만. 만든 시각을 고정해 같은 md 는 같은 docx 가 된다
  make_reference.py   설명 문서의 바탕 문서(reference.docx)를 만든다 — pandoc 기본 바탕에 한글 설정 두 가지
  check_notes.py      설명 문서 점검(장표 수만큼 있나, 번호·제목·여덟 절·다음 장표의 번호와 제목·자리표시·옛 숫자)
  .gitignore          다시 만들 수 있는 것(slides.json · reference.docx)은 저장소에 넣지 않는다
```

```bash
cd docs/deck/build
npm i pptxgenjs            # 처음 한 번 (node 18+. 11/11 의 빌드는 pptxgenjs 4.0.1)
./build.sh                 # → ../rt-robot-data-infra.pptx, ../SLIDES.md
./make_notes.sh 079 137    # 고친 설명 문서만 docx 로 (pandoc 필요. 번호 없이 부르면 전부 — 내용이 같아도 예전 파일은 한 번 바뀐다)
python3 check_notes.py     # 설명 문서가 장표와 맞는지
./render_diagrams.sh       # Mermaid 그림을 고쳤을 때만 (mmdc 필요)
cd ../../.. && python3 scripts/check_public.py     # 공개하면 안 되는 글자가 pptx·docx 안에 없는지 (커밋 전)
```

**11/11 까지 이 폴더는 저장소에 없었다.** 맨 위 `.gitignore` 의 `build/`(빌드 산출물용)가 `docs/deck/build/` 까지 가렸기 때문이다 — 문서는 이 폴더를 가리키는데 받아 간 사람은 장표를 다시 만들 수 없었다. 같은 날, 공개한 pptx 의 한 장에 계정 이름이 남아 있는 것을 찾았다(커밋 전 점검이던 `git grep` 은 pptx 안을 보지 못한다). 그래서 생성 코드를 저장소에 넣고, 점검을 pptx·docx 안까지 보는 `scripts/check_public.py` 로 바꿨다(DECISIONS 11/11).

코드 장표의 줄 번호는 `content_*.py` 안의 `code(파일, 시작, 끝)` 과 `diagrams_front.py` 의 legend 에 적혀 있다. 소스가 바뀌어 줄이 밀리면 그 숫자를 고치고 다시 빌드한다
(장표에 보이는 코드는 항상 빌드 시점의 저장소 파일 그대로다). 장표를 끼우거나 빼도 `{{first:…}}` 로 적은 장표 번호는 자동으로 맞는다.
11/10~11 에 실제로 그랬다 — 여러 파일의 줄이 밀려 코드 장표 10장이 같은 번호로 다른 코드를 보여 주고 있었고, 11/11 에 범위와 읽는 포인트를 다시 맞췄다. 소스를 고친 뒤에는 `./build.sh` → `python3 dump_slide.py NNN` 으로 코드 장표를 한 번 본다. 설명 문서의 줄 번호는 손으로 적은 것이라 같이 고쳐야 한다.

## 5. 작성 방식

장표 구성·순서도 논리·"이런 것이 있어야 한다"는 요구(과정을 앞에, 시험은 뒤에 번호만, 소스 위치, 도형과 그림)는 작성자(오문규)가 정했고,
장표와 설명 문서의 초안은 AI(Claude)가 작성했다(AI 가 쓴 커밋에 `Co-Authored-By` 로 표기). 장표의 모든 숫자와 코드는 저장소의 파일에서 나왔으며,
설명 문서는 저장소 파일과 대조해 썼다 — 확인하지 못한 것은 `추정:` 으로 표시했다. 본편은 2026-11-05, 덧붙임과 줄 번호는 2026-11-11 main 기준.
