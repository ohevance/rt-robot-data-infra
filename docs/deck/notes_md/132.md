# 장표 132 — 남은 일 — 지원(11/17)까지, 그리고 그 뒤
*위치: 7부 왜·사고·방식 · 남은 일*

## 1. 이 장표가 왜 있나

앞 장표(131)는 "무엇이 작성자의 것인가"를 답하면서 "그래서 분석 기간이 있다"고 끝났다. 이 장표는 그 남은 일을 **우선순위 순으로** 적고, 면접에서 "다음 단계는?"이라는 질문에 꺼낼 선택 과제를 따로 둔다. 포트폴리오는 11/05 시점의 스냅샷이지 끝이 아니다 — 무엇이 끝났고(코드·측정·문서·CI 가 서로 맞는 상태) 무엇이 남았는지(영상, 분석 기간, 이력서 문장)를 밝혀야 "약 80%" 라는 진행률이 뜻을 가진다. 다음 장표(133)는 면접에서 바로 꺼내 쓰는 한 문장 12개다.

## 2. 장표를 하나씩 읽기

글머리표 두 묶음(굵은 제목 + 하위 항목)과 오른쪽 아래 설명 상자.

첫 묶음 "지원 전 (우선순위 순)":
- "작성자의 분석 기간 5회차 — 표① 사슬 → 제어·물리 → 관제 → 장애 → OTA·CI. 각 회차 끝에 혼자 하는 과제 1건(예: 2 kHz 측정 줄 추가, 테스트 1개, 패널 1개)": 가장 먼저 할 일. 이 장표 138장과 설명 문서를 교재로 작성자가 다섯 번에 걸쳐 직접 설명해 본다. 회차 순서는 저장소의 길과 같다 — ① 표① 사슬(1 ms 루프, Pi 실측), ② 제어 단계와 물리(ControlStep, MuJoCo), ③ 관제(브로커·수집기·DB), ④ 장애 주입·판정, ⑤ OTA 와 CI. 회차마다 끝에 AI 없이 혼자 커밋하는 작은 과제 하나(예시: jitter_bench 를 2 kHz 로 돌려 표①에 줄 추가, 단위 테스트 1개 추가, Grafana 패널 1개 추가). 막히는 장표는 `notes_md/NNN.md` 를 고치고 다시 만든다(HANDOVER §6).
- "2분 영상 — 대본 v2·자막 상자(cue.sh)·순서표(CHEATSHEET) 준비됨. 원테이크 직접 타이핑 + Clipchamp TTS": 재료는 다 있다 — `docs/VIDEO_SCRIPT.md`(v2, 장면 6개 + 제목 카드, 내레이션 약 770자), `docs/video/cue.sh`(터미널에 자막 상자를 띄우는 스크립트), `docs/video/CHEATSHEET.md`(칠 명령 순서표). 녹화는 자동화 없이 작성자가 직접 명령을 치는 원테이크, 목소리는 Clipchamp 의 텍스트 음성 변환(TTS)으로 얼굴·육성 없이. 분석 기간 **뒤**에 한다(LOG 11/05).
- "이력서 문장(docs/RESUME_LINES.md): 경력 숫자 5개 채우기 · 재직자 접촉 문구(D9)": `docs/RESUME_LINES.md` 에 이력서 항목·자기소개서 단락·30초 자기소개가 있고 [대괄호] 자리 5개가 비어 있다 — 작성자의 통신 SW 28년 경력 쪽 숫자(시스템 규모·초당 처리량·소켓 프로토콜·관제 주기·DB 일 처리량). 재직자 접촉은 HANDOVER §1 의 "D9쯤 재직자 접촉 → 추천 경로 우선" 계획의 문구.

둘째 묶음 "선택 (면접에서 '다음 단계'로 말할 것)":
- "512M 부하로 cyclictest -S 한 번 더(E19-d 의 부하 정의 vs 격리 전후 가르기) · 방열판 달고 300초 부하": 표① 쪽 두 가지. E19-d 에서 cyclictest 와 jitter_bench 의 차이 중 "부하 정의(512M vs 256M)"와 "격리 전후"가 아직 한 덩어리(약 80 us)로 남아 있다 — 512M 부하로 `cyclictest -S` 를 한 번 더 돌리면 둘이 갈라진다. 방열판을 달면 300초 부하 측정이 스로틀 없이 가능하지만 조건이 바뀌므로 일반 커널도 다시 재야 한다(DECISIONS 2026-11-04).
- "수동 ACK(DB 적재 뒤 PUBACK) · 브로커 로그로 천둥 떼 가설 확정 · 기록 요약을 관제로 1 Hz 올리기": 관제 쪽 셋(EXPERIMENTS "남은 것"). 수동 ACK = 수집기가 메시지를 받은 즉시가 아니라 DB 에 적재한 뒤 PUBACK 을 보내 수집기가 죽어도 브로커가 재전송하게 하는 것(D5 실측에서 보류). 천둥 떼(thundering herd) = E07 에서 50대가 동시에 재접속하며 유실이 더 난 현상이 브로커 단일 스레드의 큐 방류 때문인지 브로커 로그로 확정하는 일. 기록 요약을 관제로 = E20 의 bag 요약(Hz·틈·추종 오차)을 1 Hz 로 MQTT 에 올려 Grafana 에서 보기.
- "중력 보상(토크 피드포워드) · 관절 한계 클램프 · 실물 Feetech 시리얼 백엔드 · TLS 인증 · JUnit 리포트": 더 먼 것들. 중력 보상은 E16 의 어깨 처짐 1.1° 를 없애는 제어 항(팔 무게만큼의 토크를 미리 더한다). 실물 Feetech 시리얼 백엔드는 `backend.hpp` 에 자리만 있는 `FeetechSerialBackend`(SO-101 실물 서보, 2주 계획 밖). JUnit 리포트는 CI 결과를 표 화면으로(ENVIRONMENT.md "필요하면 JUnit XML + 리포터 액션 30분"). 관절 한계 클램프(목표가 모델의 관절 범위를 넘지 않게 자르기)와 TLS 인증(브로커 접속 암호화·인증)은 저장소 문서에는 없고 장표에서 덧붙인 항목이다 — 5절 참고.

설명 상자 "전체 진행률(11/05) — 약 80%. 코드·측정·문서·CI 는 일관된 상태(main 2df4624 이후). 남은 큰 일은 영상과 분석 기간 — 둘 다 작성자의 손이 필요한 일": 80% 는 작업량 기준의 어림이다(5절). `2df4624` 는 11/05 "D7: 기록 파이프라인 첫 실행 반영" 커밋 — 그 뒤로 코드·측정 파일·문서·CI 가 서로 어긋나는 곳이 없다는 뜻. 남은 20% 는 AI 가 대신할 수 없는 일(사람이 치는 영상, 사람이 설명해 보는 분석)이라는 점이 이 상자의 요점이다.

## 3. 용어와 단위

- 분석 기간(5회차): 작성자가 교재(장표·설명 문서)로 저장소를 직접 설명해 보는 다섯 번의 세션. 공부 기간이지 개발 기간이 아니다.
- 원테이크(one take): 끊지 않고 한 번에 녹화. 실수하면 처음부터.
- TTS(Text-to-Speech): 글을 합성 음성으로 읽어 주는 기능. Clipchamp 는 Windows 의 영상 편집 앱.
- 수동 ACK / PUBACK: MQTT QoS 1 에서 "받았다"는 확인 패킷(PUBACK). 보통은 라이브러리가 받는 즉시 보내지만, 수동으로 바꾸면 DB 적재 뒤에 보낼 수 있다.
- 천둥 떼(thundering herd): 많은 클라이언트가 **동시에** 같은 일(재접속·재전송)을 해서 서버가 순간적으로 막히는 현상.
- 토크 피드포워드(torque feedforward): 측정값을 기다리지 않고 미리 아는 힘(팔 무게)을 명령에 더하는 제어 방식.
- 클램프(clamp): 값을 허용 범위 [최소, 최대] 안으로 자르는 것.
- JUnit 리포트: 테스트 결과를 적는 XML 형식. CI 화면에서 테스트별 통과/실패 표로 보여 줄 수 있다.
- 2 kHz: 1초에 2,000번. 지금 루프는 1 kHz(1 ms 주기), 2 kHz 는 0.5 ms 주기.

## 4. 쉬운 예시

- 비유: 시험 범위 공부(코드·측정·문서)는 끝났고, 남은 것은 **말로 설명해 보는 연습**(분석 기간)과 **시험장 가는 길 영상**(2분 영상), 그리고 원서의 빈칸(이력서 숫자 5개)이다. 공부가 80% 라고 해서 시험 준비가 80% 는 아니다 — 남은 20% 가 당락을 가른다.
- 숫자 예시: 11/05 에서 지원일 11/17 까지 12일. 분석 기간 5회차를 이틀에 한 번 하면 10일, 영상 하루, 이력서 하루 — 빠듯하지만 맞는다. 그래서 우선순위가 분석 기간 → 영상 → 이력서 순이다.
- "다음 단계" 예시(면접): "어깨가 1.1° 처진 것을 숫자로 봤으니, 다음은 그 관절에 토크 피드포워드를 넣어 처짐이 0.1° 아래로 가는지 같은 기록 파이프라인으로 재는 것입니다" — 숫자(1.1°)와 측정 방법(E20 요약)이 이미 있어 말이 된다.

## 6. 자주 하는 오해·함정

- "80% 면 거의 끝"이라는 오해: 남은 20% 는 전부 작성자 본인의 시간이 드는 일이고, AI 로 당길 수 없다. 영상은 원테이크라 연습이 필요하고 분석 기간은 다섯 번이다.
- 선택 과제를 "안 한 일"로 말하지 않는다 — "다음 단계로 **고른** 일"이다. 각 항목에 숫자 근거(1.1°, 80 us, 53 유실의 천둥 떼)가 붙어 있어야 다음 단계로 설득력이 있다.
- 분석 기간을 건너뛰고 영상을 먼저 찍지 않는다. 영상은 "설명할 수 있는 상태"에서 쳐야 한다 — LOG 11/05 "영상 녹화는 그 뒤".
- 이력서 숫자 5개는 이 저장소가 아니라 작성자의 **과거 경력** 숫자다. 저장소 숫자와 섞지 않는다.
- 방열판을 달고 재면 지금 표①의 Pi 줄과 조건이 달라진다 — 그 뒤 비교는 "방열판 있음" 줄끼리만.

## 7. 면접 한 문장

"코드·측정·문서·CI 는 서로 맞는 상태로 끝났고, 남은 것은 제가 직접 해야 하는 셋 — 장표로 설명해 보는 분석 기간 다섯 번, 직접 치는 2분 영상, 이력서 숫자 — 이고, 다음 단계로는 어깨 처짐 1.1° 를 없애는 중력 보상과 DB 적재 뒤 PUBACK 을 보내는 수동 ACK 를 같은 측정 방법으로 재 보고 싶습니다."
