# 장표 138 — 덧붙임 (11/10) — 장치의 설치: 내려받기 → sha256 → A/B 슬롯 → 자가 점검 → 원자적 전환 (ota_apply.install)
*위치: 7부 왜·사고·방식 · 덧붙임 릴리스 → 배포 2/3 코드 (11/10)*

## 1. 이 장표가 왜 있나
앞 장표(137)의 그림은 맨 끝에 "장치: 내려받기 → sha256 → 슬롯 → 자가 점검 → current 전환"이라는 상자 하나를 남겼다. 승인 모드든 자율 모드든, 가상 장치든 실물 Pi 든, 게시된 파일이 마지막에 지나가는 곳은 이 한 함수다. 그래서 질문은 이것이다 — "장치는 받은 파일을 어떻게 설치하나, 그리고 도중에 무엇이 잘못되든 **반쯤 깔린 상태**가 남지 않게 하려면?" 로봇의 소프트웨어를 덮어쓰다가 전원이 꺼지거나, 받은 파일이 깨져 있거나, 새 프로그램이 이 기계에서 켜지지 않으면, 로봇은 옛 버전도 새 버전도 아닌 상태가 된다. 이 장표는 그 답인 `fleet/agent/ota_apply.py` 의 `install` 함수 본체 서른 줄을 그대로 보인다. 장표의 코드는 빌드할 때 저장소 파일에서 읽은 것이다. 다음 장표(139)는 이 코드를 실제로 돌린 숫자다.

## 2. 장표를 하나씩 읽기
코드 상자 위에 `fleet/agent/ota_apply.py:205-234 (install 의 본체)`. 함수는 194줄에서 시작하고, 상자에 보이지 않는 앞부분(199~204줄)이 준비를 한다.
- 199줄 `r = Result()` — 설치 한 번의 결과를 담을 상자. 성공 여부(`ok`), 어디까지 갔나(`stage`), 오류 글(`error`), 단계별 걸린 시간(`took_s`), 받은 바이트 수(`bytes`).
- 201줄 `slot_root = os.path.abspath(slot_root)` — 설치 자리 폴더의 경로를 절대 경로로 굳힌다. 11/10 밤 CI 사고(상대 경로 슬롯, 장표 141)를 고친 줄이다.
- 203~204줄 — 내려받을 임시 파일의 자리(`<slot_root>/.download/<버전>.tar.gz`)와 풀 폴더의 자리(`<slot_root>/slots/<버전>`)를 정한다.

이제 상자 안. 한 줄이 한 단계다.
- 205줄 `try:` — 여기부터 어느 줄에서든 오류가 나면 223줄의 `except` 로 간다.
- 206줄 `r.bytes = _timed(r, "download", lambda: download(url, tar_path))` — **1단계 내려받기.** `download`(61~83줄)가 주소의 파일을 임시 자리로 받는다. 200 MB 를 넘으면 거부한다(잘못된 주소가 디스크를 채우지 않게). `_timed`(53~58줄)는 "이 일을 하고 걸린 시간을 `took_s` 에 이 이름으로 적어라"는 도우미다 — 그래서 설치가 끝나면 단계마다 몇 초 걸렸는지가 남는다.
- 207줄 `r.stage = "downloaded"` — 여기까지 왔다는 표시. `stage` 는 장치의 텔레메트리에 `ota_stage` 로 실려, 실패했을 때 서버가 "어디서 멈췄나"를 안다.
- 208~209줄 `if size is not None and int(size) != r.bytes: raise ValueError(…)` — 받은 크기가 매니페스트에 적힌 크기와 다르면 멈춘다. 도중에 끊긴 내려받기를 싸게 걸러 낸다.
- 210~211줄 `_timed(r, "verify", lambda: verify_sha256(tar_path, sha256))` / `r.stage = "verified"` — **2단계 검증.** 받은 파일의 지문(sha256)을 계산해 매니페스트의 값과 맞춘다(97~101줄). 다르면 `ValueError`.
- 212~213줄 `_timed(r, "extract", lambda: extract(tar_path, slot_dir))` / `r.stage = "extracted"` — **3단계 풀기.** 그 버전만의 폴더(`slots/<버전>/`)에 푼다(116~133줄). 지금 쓰고 있는 폴더는 건드리지 않는다.
- 214~215줄 `_timed(r, "selftest", lambda: selftest(slot_dir))` / `r.stage = "selftest_ok"` — **4단계 자가 점검.** 방금 푼 폴더 안의 `selftest.sh` 를 돌린다(136~149줄, 제한 60초). 0 이 아닌 종료 코드면 `ValueError` — 오류 글에 스크립트 출력의 마지막 세 줄이 담긴다.
- 216줄 `state = read_state(slot_root)` — 지금까지의 기록(`state.json`: 현재 버전과 이전 버전)을 읽어 둔다.
- 217줄 `_timed(r, "switch", lambda: switch_current(slot_root, version))` — **5단계 전환.** "지금 쓰는 것"을 가리키는 링크 `current` 를 새 폴더로 바꾼다(168~175줄). 이 한 줄 앞까지는 장치가 옛 버전을 쓰고 있고, 이 줄 뒤부터 새 버전이다.
- 218~219줄 `write_state(slot_root, {"current": version, "previous": state.get("current"), "switched_at": …, "sha256": sha256})` — **6단계 기록.** 새 현재 버전, 방금까지의 버전(이전 버전), 바꾼 시각, 설치한 파일의 지문을 `state.json` 에 적는다. 되돌릴 때 "어디로 돌아가나"의 기준이 이 파일이다.
- 220줄 `r.stage = "switched"`.
- 221줄 `_timed(r, "post_switch", lambda: post_switch(slot_dir))` — **7단계 훅.** 새 폴더에 `post_switch.sh` 가 있으면 돌린다(152~165줄). 실물에서 "새 실행 파일로 제어 노드를 다시 띄우기" 같은 일을 넣는 자리이고, 지금 패키지의 훅은 아무것도 하지 않는다(자리만).
- 222줄 `r.ok = True` — 일곱 단계가 다 지나가야 성공이다.
- 223~224줄 `except Exception as e:` / `r.error = f"{e.__class__.__name__}: {e}"` — 어느 단계에서든 오류가 나면 여기로 온다. 주석이 요점이다: "어느 단계에서 멈췄든 current 는 안 건드렸거나(1~4) 이미 바꿨다(5~7)". 오류의 종류와 글을 결과에 담는다(이것이 텔레메트리의 `ota_error` 가 된다).
- 225~226줄 `if os.path.isdir(slot_dir) and r.stage in ("extracted",): shutil.rmtree(slot_dir, …)` — `stage` 가 `extracted` 에서 멈췄다는 것은 풀기는 됐고 자가 점검에서 실패했다는 뜻이다. 그 폴더를 지운다 — 켜지지 않는 버전을 디스크에 남겨 두지 않는다.
- 227~230줄 `if r.stage == "switched": … if rollback(slot_root) is not None: r.stage = "post_switch_failed_rolled_back"` — `stage` 가 `switched` 에서 멈췄다는 것은 링크는 이미 새 폴더를 가리키는데 훅이 실패했다는 뜻이다. 이때는 서버의 판단을 기다리지 않고 **스스로** 링크를 이전 폴더로 되돌린다(`rollback`, 237~246줄).
- 231~233줄 `finally:` / `if not keep_download and os.path.isfile(tar_path): os.remove(tar_path)` — 성공이든 실패든 내려받은 임시 파일은 지운다.
- 234줄 `return r` — 결과를 돌려준다. 부른 쪽(`device_agent.apply_ota_artifact`, 장표 079 에서 언급)이 `r.ok` 를 보고 버전과 상태를 정한다 — 성공이면 `fw_version` 을 새 값으로 · `ok`, 실패면 `fault` 와 `ota_error`.

오른쪽 "읽는 포인트" 여섯 줄:
- "한 줄이 한 단계: 내려받기 → 크기·sha256 → 풀기 → 자가 점검 → 전환 → 훅. _timed 가 단계마다 걸린 시간을 took_s 에 적고, stage 는 '어디까지 갔나'(텔레메트리의 ota_stage)": 위 206~221줄. 코드가 위에서 아래로 곧게 읽히는 것이 설계의 일부다 — 설치 순서가 곧 줄 순서다.
- "검증이 풀기보다 먼저 — 해시가 다르면 풀지도 않는다. 풀 때는 경로 탈출(../)과 링크 멤버를 거부한다(extract, 116-133줄)": 순서의 이유. 지문이 맞지 않는 파일은 무엇이 들어 있는지 모르는 파일이므로 디스크에 풀지 않는다. 그리고 묶음 파일 안에는 `../../etc/…` 처럼 풀 폴더 **밖**을 가리키는 경로나, 다른 곳을 가리키는 링크가 들어 있을 수 있다 — 그대로 풀면 설치 자리 밖의 파일을 덮어쓴다. `extract` 는 풀기 전에 모든 항목의 실제 경로가 풀 폴더 안인지 확인하고(104~113줄 `_safe_members`), 링크가 하나라도 있으면 거부한다.
- "자가 점검(selftest.sh: jitter_bench 0.5초)이 0 을 돌려줄 때만 전환. 실패하면 그 슬롯을 지우고 current 는 그대로 — 깨진 빌드를 '켜 보기 전에' 거른다": 214줄과 225~226줄. 패키지의 자가 점검은 그 안의 실행 파일(`jitter_bench`, 1 kHz 루프)을 0.5초 돌려 본다 — 이 기계에서 실행되는가(아키텍처와 라이브러리가 맞는가), 주기가 100번 넘게 돌았는가, 드롭이 10 % 를 넘지 않는가. "켜지는가"를 묻는 검사이지 성능 측정이 아니다. 2부의 흉내 경로에서는 나쁜 펌웨어가 **켜진 뒤에** 고장을 내야 서버의 헬스 게이트가 잡았다. 여기서는 켜기 전에 장치가 거부한다.
- "전환은 switch_current(168-175줄): 임시 링크를 만들고 os.replace 로 바꿔치기 → 어느 순간 전원이 꺼져도 current 는 옛 슬롯 아니면 새 슬롯": 217줄의 속. 링크를 "지우고 새로 만들면" 그 사이에 전원이 꺼졌을 때 링크가 없는 순간이 생긴다. 그래서 다른 이름으로 새 링크를 먼저 만들어 놓고(`.current.tmp.<번호>`), 그것을 `current` 라는 이름으로 **바꿔치기**한다(`os.replace`). 이름 바꿔치기는 운영체제가 "되거나 안 되거나" 둘 중 하나로 처리한다(원자적) — 반쯤 된 상태가 없다.
- "훅(post_switch.sh)이 실패하면 서버를 기다리지 않고 스스로 이전 슬롯으로(rollback, 237-246줄)": 227~230줄. 2부의 결정 "롤백 판단은 서버가"(장표 126)의 경계다 — 함대 전체를 되돌릴지는 서버가 정하지만, "내 전환 직후의 뒷일이 실패했다"는 장치 한 대의 문제라 장치가 바로 되돌린다.
- "실측(Pi 4, 3회): 한 번에 0.98~1.62초 — 그중 자가 점검 0.67초, 검증 0.001초, 전환 0.001초 미만": `_timed` 가 남긴 `took_s` 를 실물 Pi 에서 읽은 값. 설치 한 번의 시간은 거의 전부 자가 점검(0.5초짜리 루프 + 프로세스 시작과 판정)이고, 지문 계산은 1 ms, 링크 바꿔치기는 잴 수 있는 해상도 아래다(다음 장표).

## 3. 용어와 단위
- 슬롯(slot) / A/B 슬롯: 버전 하나를 통째로 담는 폴더(`slots/0.9.0/`). 옛 버전과 새 버전이 각자 폴더에 온전히 있고, 링크 하나가 "지금 쓰는 쪽"을 가리킨다. 휴대전화나 자동차의 업데이트에서 쓰는 "A/B 파티션"과 같은 생각을 폴더로 한 것이다.
- 링크(symbolic link): 다른 폴더를 가리키는 이름표 파일. `current → slots/0.9.0`.
- 원자적(atomic): 중간 상태 없이 "전부 되거나 전혀 안 되거나". `os.replace`(이름 바꿔치기)가 그렇다.
- `state.json`: 슬롯 자리의 기록 파일. 예: `{"current": "1.2.0", "previous": "1.1.0", "switched_at": …, "sha256": …}`.
- sha256 / 무결성 / 진위: 지문 / 깨지지 않았나 / 누가 만들었나. 지문은 앞의 것만 보장한다.
- 자가 점검(selftest): 새 슬롯을 켜기 전에 돌려 보는 검사. 종료 코드 0 이 통과.
- 훅(hook): 정해진 순간에 불리도록 끼워 둔 스크립트. 여기서는 전환 직후의 `post_switch.sh`.
- 경로 탈출(path traversal): 묶음 파일 안의 경로가 `../` 로 풀 폴더 밖을 가리키는 것.
- `try / except / finally`: 파이썬의 오류 처리. try 안에서 오류가 나면 except 로, 어떻게 끝나든 finally 는 실행된다.
- `lambda: …`: 이름 없는 작은 함수. "이 일을 나중에 해 달라"고 `_timed` 에 넘기는 모양.
- `ValueError`: 값이 기대와 다를 때 내는 파이썬의 오류 종류. 여기서는 크기 · 지문 · 자가 점검 · 훅의 실패를 모두 이것으로 알린다.
- 단위: 초(s). 0.001초 = 1 ms. 21 KB = 약 21,000바이트.

## 4. 쉬운 예시
- 비유: 사무실 이사. 지금 쓰는 방(옛 슬롯)을 비우고 짐을 풀지 않는다. 옆 빈 방(새 슬롯)에 새 가구를 다 들이고, 배달 온 상자의 봉인 번호를 송장과 맞춰 보고(sha256), 전등과 콘센트가 켜지는지 눌러 본 뒤(자가 점검)에야 문패(`current`)를 그 방으로 옮긴다. 문패를 옮기는 것은 한 동작이라, 그 순간 정전이 돼도 문패는 옛 방 아니면 새 방에 붙어 있다. 새 방의 전등이 안 켜지면 그 방을 비우고 옛 방을 계속 쓴다. 문패를 옮긴 뒤 "전화선 연결"(훅)이 안 되면 스스로 문패를 옛 방으로 되돌린다.
- 숫자 예시(실물 Pi 4, 11/11, 세 번): 전체 1.620 / 1.009 / 0.983초. 그 안에서 내려받기 0.426 / 0.117 / 0.090초(21.7 KB, 첫 회가 느리다), 검증 0.001초, 풀기 0.029 / 0.026 / 0.027초, 자가 점검 0.678 / 0.674 / 0.674초, 전환 0.000초(소수 셋째 자리에서 0), 훅 0.009초. 나머지(0.477 / 0.182 / 0.182초)는 설치 앞에 매니페스트를 읽는 시간이다.
- 실패 예시: 릴리스 카나리의 깨진 패키지. 1~3단계(내려받기 · 검증 · 풀기)는 통과하고 4단계에서 `selftest.sh` 가 1 을 낸다 → `ValueError("selftest 실패 (exit 1): selftest: 고의로 깨진 빌드 (롤백 검증용)")` → 223줄로 → `stage` 가 `extracted` 이므로 폴더를 지운다 → `current` 는 그대로 → 장치는 `state=fault` 와 이 오류 글을 텔레메트리로 알린다 → 서버가 3대에서 보고 되돌린다.

## 6. 자주 하는 오해·함정
- "A/B 슬롯이면 디스크의 파티션이 둘이다"는 오해: 여기서는 파티션이 아니라 **폴더**와 링크다. 운영체제 전체를 바꾸는 것이 아니라 응용 프로그램 묶음을 바꾸는 크기에 맞춘 것이다.
- "sha256 을 맞추니 안전한 파일이다"는 과장: 깨지지 않았다는 것까지다. 서명이 없으므로 "누가 만들었나"는 확인하지 않는다 — 바닥 줄의 첫 한계.
- "자가 점검을 통과했으니 성능도 확인됐다"는 오해: 0.5초, 실시간 우선순위 없이(`--no-rt`), 드롭 10 % 까지 허용이다. 카나리에서는 가상 장치 25대가 러너 한 대에서 동시에 이 점검을 돌리므로 드롭 0 을 요구하면 멀쩡한 빌드가 떨어진다. 성능은 표①(장표 091~095)이 잰다.
- 실패한 설치 뒤의 "되돌리기"를 혼동하기 쉽다. 1~4단계에서 실패한 장치는 `current` 가 그대로라 되돌릴 것이 없다. 서버가 `ota_rollback` 을 보내면 상태만 정상으로 돌린다. 11/11 까지 이 구분의 순서가 틀려 있었다(장표 081, 141).
- 상대 경로 함정(11/10): 자가 점검과 훅은 슬롯 폴더 **안에서** 돌린다. 슬롯 경로가 상대 경로면 "안에 들어가서 다시 본 경로"가 되어 스크립트를 못 찾는다(종료 코드 127). 201줄이 그것을 막는다.
- `stage` 의 이름으로 원인을 읽는다. `downloaded` 에서 멈췄으면 크기나 지문, `verified` 에서 멈췄으면 풀기, `extracted` 에서 멈췄으면 자가 점검, `switched` 에서 멈췄으면 훅이다 — "멈춘 단계"는 "마지막으로 통과한 단계"다.

## 7. 면접 한 문장
"장치의 설치는 서른 줄입니다 — 받은 파일의 크기와 sha256 을 맞춘 뒤에만 풀고, 새 버전을 다른 폴더에 풀어 0.5초 켜 본 뒤에만 current 링크를 원자적으로 바꿉니다. 그래서 어느 순간 전원이 꺼져도 장치는 옛 버전 아니면 새 버전이고, 깨진 빌드는 켜 보기 전에 거부됩니다. sha256 은 무결성이지 서명이 아니라는 것과 훅 도중의 전원 차단은 복구하지 못한다는 것은 한계로 적어 두었습니다."
