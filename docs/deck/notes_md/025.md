# 장표 025 — 단계 4 — 루프 본체 (1/2) — 절대 시각에 깨서, 얼마나 늦게 깼는지 잰다
*위치: 1부 로봇을 움직이는 길 · 단계 4/10 RT 1 ms 루프 · ② 코드 — 루프 본체 1/2*

## 1. 이 장표가 왜 있나
- 앞 장표(024)에서 스레드를 실시간 스레드로 만드는 준비를 끝냈다. 이제 **루프 본체**다. `rt_loop.cpp` 머리말이 "이 파일의 핵심은 run() 의 for 문 20줄"이라고 한 그 for 문의 앞 절반(120~143줄)이다.
- 이 절반이 하는 일은 두 가지다. (a) 정해진 **절대 시각**까지 잔다. (b) 깨자마자 "얼마나 늦게 깼나(wake_lat)"와 "지난 주기와의 간격이 1 ms 에서 얼마나 벗어났나(period_err)"를 잰다. 3부 표①의 모든 숫자(p50·p99·max)가 (b)의 `wake_lat_ns` 에서 나온다.
- 뒷 절반(026)은 깬 뒤에 실제 일을 하고, 벨트에 올리고, 다음 목표 시각을 정하는 부분이다.

## 2. 장표를 하나씩 읽기
- `for (std::uint64_t i = 0; i < total_iters; ++i)` — `total_iters` 는 "몇 번 돌 것인가 = 시간 ÷ 주기". 60초 측정이면 60 × 1000 = 60,000번. 제어 노드처럼 `seconds` 가 0 이면 UINT64_MAX(사실상 무한)로 두고 stop 신호를 기다린다(run() 108~114줄).
- **(0)** `if (stop != nullptr && stop->load(std::memory_order_acquire)) break;` — ROS 2 노드가 Ctrl+C 를 받으면 소멸자에서 `stop_` 을 true 로 바꾸고, RT 스레드는 다음 주기에 여기서 빠져나온다. 측정기(jitter_bench)는 stop 을 안 넘기므로(nullptr) 이 검사는 건너뛴다. `acquire` 로 읽어 다른 스레드의 쓰기를 확실히 본다.
- **(a)** `timespec wake_ts = ns_to_timespec(next_wake_ns);` — 목표 시각(ns 정수)을 커널이 받는 `timespec`(초 + 나노초) 꼴로 바꾼다.
- `while (clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &wake_ts, nullptr) == EINTR) {}` — 핵심 한 줄. `CLOCK_MONOTONIC` 은 뒤로 가지 않는 시계, `TIMER_ABSTIME` 은 "**이 시각에** 깨워라"(절대 시각)는 뜻이다. "지금부터 1 ms 뒤"(상대 시각)로 자면 늦게 깬 만큼이 다음 주기로 밀려 쌓이는데(드리프트), 절대 시각이면 늦게 깨도 다음 목표 시각은 원래 격자 그대로다. `EINTR` 은 "신호 때문에 잠이 중간에 깨졌다"는 반환값이고, 그때는 같은 시각으로 다시 잔다 — while 로 감싼 이유다.
- `std::int64_t woke_ns = now_ns();` — 실제로 깬 시각.
- **(b)** `Sample s; s.iter = i;` — 이번 주기의 측정값 묶음. 벨트(타이밍 링)로 넘어가 통계가 된다.
- `s.wake_lat_ns = woke_ns - next_wake_ns;` — **깨어남 지연** = 실제 깬 시각 − 목표 시각. 표①의 주인공. 항상 0 이상이다(목표보다 일찍 깨워 주지는 않는다).
- `if (prev_wake_ns == 0) s.period_err_ns = 0; else s.period_err_ns = (woke_ns - prev_wake_ns) - cfg_.period_ns;` — **주기 오차** = (이번 깸 − 지난 깸) − 1 ms. 첫 주기는 "지난 깸"이 없어 0 으로 두고 통계에서 뺀다(주석에 적혀 있다). 음수도 가능하다: 지난번에 늦게 깨고 이번에 제때 깨면 간격이 1 ms 보다 짧다.
- `prev_wake_ns = woke_ns;` — 다음 주기의 비교 기준을 갱신한다.
- **오른쪽 요점**은 위 다섯 가지를 그대로 요약한다: 절대 시각(드리프트 0) · EINTR 처리 · wake_lat 의 정의 · period_err 의 정의와 첫 주기 예외 · stop 플래그.

## 3. 용어와 단위
- **절대 시각 타이머(TIMER_ABSTIME)**: "X 시각에 깨워라". 반대는 상대 시각 "지금부터 Δ 뒤에 깨워라". GLOSSARY "절대 시각 타이머" 항목.
- **드리프트(drift)**: 상대 시각으로 잘 때 늦게 깬 시간이 누적되어 주기가 점점 밀리는 현상. 1,000주기에 평균 50 us 씩 늦으면 1초에 50 ms 가 밀린다.
- **CLOCK_MONOTONIC**: 시스템이 켜진 뒤 흐른 시간. 벽시계 조정에 영향받지 않는다.
- **EINTR**: 시스템 호출이 신호(signal)에 의해 중단되었다는 오류 번호.
- **wake_lat(깨어남 지연)**: 목표 시각보다 늦게 깬 시간. 단위 ns 로 재고 표에는 us 로 적는다(÷1000).
- **period_err(주기 오차)**: 실제 깸 간격 − 목표 주기. 음수·양수 모두 가능.
- **p50 / p99 / max**: 값을 작은 것부터 늘어놓았을 때 50 %·99 % 지점의 값, 그리고 최댓값. 실시간에서는 max(꼬리)가 가장 중요하다.
- **UINT64_MAX**: 64비트 부호 없는 정수의 최댓값(약 1.8 × 10¹⁹). "사실상 무한" 으로 쓴다.

## 4. 쉬운 예시
- **알람 비유**: 매일 아침 7:00 에 일어나기로 했다. 상대 시각 방식은 "잠든 시각 + 8시간"이라서 어제 7:10 에 일어나 늦게 자면 오늘은 더 늦어진다(드리프트). 절대 시각 방식은 알람을 **7:00 에 고정**하는 것이라 어제 늦었어도 오늘 알람은 7:00 이다. 깨어남 지연은 알람이 울리고 실제로 눈을 뜬 시각의 차이(7:00 → 7:00:30 이면 30초), 주기 오차는 어제 눈 뜬 시각과 오늘 눈 뜬 시각의 간격이 24시간에서 벗어난 양이다.
- **숫자 예시**: 목표 10,000,000 ns 에 깨기로 했는데 10,000,037 ns 에 깼다 → wake_lat 37 us (WSL2 p50 이 이 수준). 지난번 깬 시각이 8,999,900 ns 였다면 간격은 1,000,137 ns → period_err +137 us. 다음 목표는 10,000,037 이 아니라 11,000,000 ns 다(절대 시각이니까).

## 6. 자주 하는 오해·함정
- "`sleep(1ms)` 나 `std::this_thread::sleep_for` 로도 1 kHz 가 된다" — 상대 시각이라 드리프트가 생기고, 늦게 깬 만큼 다음 주기가 밀린다. 1분이면 수 ms~수십 ms 가 쌓인다. 절대 시각 `clock_nanosleep(TIMER_ABSTIME)` 이 정답이다.
- "wake_lat 이 0 이 될 수 있다" — 이론상 0 이지만 실제로는 커널이 타이머 인터럽트를 처리하고 스레드를 올리는 데 수 us 는 걸린다. Pi 4 RT 커널 한가 p50 이 18.5 us 다(표①).
- "period_err 가 음수면 버그다" — 아니다. 지난 주기에 늦게 깼다가 이번에 제때 깨면 간격이 1 ms 보다 짧아 음수가 된다. 절대 시각이 드리프트를 되돌리고 있다는 증거다.
- "EINTR 처리는 없어도 된다" — 프로세스에 신호(예: SIGINT, 프로파일러)가 오면 잠이 깨진다. 처리하지 않으면 그 주기는 목표보다 일찍 깨서 일한다.

## 7. 면접 한 문장
"`clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME)` 로 '그 시각에' 깨고, 깬 즉시 목표 시각과의 차이를 wake_lat 으로, 지난 깸과의 간격에서 1 ms 를 뺀 것을 period_err 로 재서 벨트에 올립니다 — 표①의 p50·p99·max 는 전부 이 한 줄의 wake_lat 에서 나왔습니다."
