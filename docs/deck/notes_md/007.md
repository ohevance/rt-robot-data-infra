# 장표 007 — 한 장 그림 — 명령에서 움직임까지 10단계 (각 상자가 다음 장표들의 출발점)
*위치: 1부 로봇을 움직이는 길 · 한 장 그림 — 10단계*

## 1. 이 장표가 왜 있나
- 바로 앞 장표(006 바탕 지식)에서 관절 6개·rad·Hz·us·실시간이라는 여섯 가지 말을 익혔다. 그러면 자연스럽게 "그 말들이 실제로는 어떤 순서로 이어져서 로봇이 움직이나?"라는 질문이 생긴다.
- 이 장표는 그 질문에 **한 장**으로 답한다. 명령이 생기는 순간부터 로봇이 움직이고, 그 결과가 기록되고 관제 서버까지 올라가는 10단계를 번호 붙은 상자 10개로 그렸다.
- 1부의 나머지 장표는 전부 이 상자 하나하나를 확대한 것이다. 상자 안에 적힌 `파일:줄`이 그 단계의 핵심 소스 코드 위치이고, 뒤에 나오는 들머리·그림·코드 장표가 그 상자에서 출발한다. 그래서 제목이 "각 상자가 다음 장표들의 출발점"이다.
- 이 장표를 보고 나면 "지금 몇 번째 상자 이야기를 하고 있나"를 늘 알 수 있다. 장표 위 오른쪽의 알약(crumb)도 "단계 N/10"으로 같은 번호를 쓴다.

## 2. 장표를 하나씩 읽기
상자는 왼쪽 위에서 오른쪽으로 다섯 개, 그다음 줄은 오른쪽에서 왼쪽으로 다섯 개(뱀 모양)다. 번호 순서대로 따라간다.

- **1 명령이 생긴다** — "상위(계획기·조작기·시험용 ros2 topic pub)가 목표 관절 위치 6개를 50 Hz 로 낸다". 로봇을 움직이려면 누군가 "관절을 이 각도로"라고 말해야 한다. 실제 로봇이라면 경로를 계산하는 계획기나 사람이 쥔 조작기가 그 역할을 하고, 이 저장소에서는 시험용으로 명령줄 도구가 같은 값을 1초에 50번 낸다. 참조 `sensor_msgs/JointState → /joint_command`: 메시지 형식(ROS 2 표준)과 토픽 이름. 파란색(accent5)은 "로봇 밖/일반 스레드" 계열이다.
- **2 ROS 2 / DDS 전달** — "같은 PC 안 프로세스 간 통신. RMW(Fast DDS) 가 토픽을 실어 나른다. QoS 가 손실·지연을 정한다". 명령을 내는 프로그램과 받는 노드는 다른 프로세스라서 중간에 미들웨어가 필요하다. 참조 `표② dds_bench/rtt_bench.py`: 이 전달이 얼마나 믿을 만한지는 표②로 쟀고, 그 측정기가 이 파일이다. 측정 자체는 3부(검증)에서 본다.
- **3 노드가 우편함에** — "on_command: 길이 검사 → JointCommand → 락 없는 링(64칸)에 push. ROS 2 스레드는 여기까지". 받은 명령을 검사해서 '우편함'에 넣는 일까지만 일반 스레드가 한다. 참조 `rt_control/ros2_adapter/src/rt_control_node.cpp:184-201 · spsc_ring.hpp`. 여기부터 민트색(accent1) = 실시간 핵심 영역이다.
- **4 RT 스레드 1 ms** — "RtLoop::run: 준비 5단계 뒤 절대 시각에 깨서 step() 호출. 늦게 깬 만큼이 '깨어남 지연'". 1초에 1,000번, 정확한 시각에 깨는 스레드. 참조 `rt_control/rt_core/src/rt_loop.cpp:100-162 · 표①`. 표①(얼마나 정확히 깨나)이 이 상자에서 나온다.
- **5 제어 단계** — "최신 명령만 → 워치독(50 ms) + 상태 머신 → 변화량 제한(0.05 rad/주기) → 백엔드에 쓰기". 깨서 꺼낸 명령을 그대로 쓰지 않고 안전하게 다듬는 단계. 50 ms 는 "명령이 이만큼 안 오면 멈춘다"는 시간, 0.05 rad 는 "한 주기에 이 이상은 못 움직인다"는 변화량이다. 참조 `rt_control/rt_core/src/control_step.cpp:28-56`.
- **6 백엔드가 로봇에** — "Backend::write_command — SimLag(1차 지연) | MuJoCo(ctrl → mj_step) | 실물(서보 시리얼, 자리)". 로봇 쪽 인터페이스. 구현이 셋인데 지금 실제로 쓰는 것은 물리 시뮬레이터 MuJoCo 이고, 실물 서보용은 자리만 있다. 참조 `rt_control/rt_core/src/mujoco_backend.cpp:226-239`. 보라색(accent6)은 "로봇 쪽 구현"을 뜻한다.
- **7 로봇이 움직인다** — "물리가 목표를 따라간다. 어깨는 중력에 0.019 rad(1.1°) 처진다 — 데이터가 말해 준 사실". 이 장표의 목적지. 주황색(accent2)으로 강조했다. 0.019 rad 는 목표 −0.200 rad 에 대해 실제 −0.181 rad 가 읽힌 차이이고, 1 rad = 57.3° 이므로 약 1.1°다. 참조 `E15 · E16 · joint_states`.
- **8 상태를 읽어 올린다** — "read_state(qpos·qvel) → JointStateSample → 상태 벨트(2048) → publish_state 100 Hz, rt_status 1 Hz". 움직인 결과(위치 qpos·속도 qvel)를 읽어 바깥으로 내보내는 길. 1초에 100번 상태를, 1초에 1번 노드의 자기 보고(rt_status)를 낸다. 참조 `rt_control/ros2_adapter/src/rt_control_node.cpp:210-230`.
- **9 기록한다** — "rosbag2 MCAP 30초 → CSV 3개 → summary.md(실제 Hz·틈·추종 오차)". 로봇 안에 원본을 남기고 자동 요약을 만든다. 회색(accent3) = 다시 일반 스레드/도구 영역. 참조 `data_pipeline/record.sh · bag_to_csv.py · E20`.
- **10 관제로 올린다** — "ros_status_bridge 가 rt_status 를 51번째 장치로 MQTT 에 → 수집기 → DB → Grafana (2부)". 가상 장치 50대와 같은 길로 로봇의 요약 숫자가 서버 화면까지 간다. 여기서부터가 2부(데이터의 길)다. 참조 `fleet/agent/ros_status_bridge.py`.
- **아래 설명 상자** — "읽는 법: 왼쪽 위에서 시작해 뱀처럼 내려온다. ①~③ 은 ROS 2 스레드(일반 우선순위), ④~⑥·⑧ 앞부분은 RT 스레드(SCHED_FIFO 80, 1 kHz), ⑦ 은 물리, ⑨⑩ 은 다시 일반 스레드. 두 세계의 경계는 락 없는 링 버퍼뿐이다". 색이 말하는 것이 바로 이것이다. 일반 스레드와 실시간 스레드라는 두 세계가 있고, 둘이 만나는 자리는 '우편함'과 '벨트'라는 링 버퍼 둘뿐이다.

## 3. 용어와 단위
- **단계(상자)**: 데이터가 한 번 모양을 바꾸거나 다른 스레드/프로세스로 넘어가는 지점을 하나로 세었다. 10이라는 수에 특별한 의미는 없고, 설명하기 좋은 알갱이 크기다.
- **Hz(헤르츠)**: 1초에 몇 번. 50 Hz = 20 ms 마다 한 번, 1 kHz = 1 ms 마다 한 번, 100 Hz = 10 ms 마다 한 번.
- **rad(라디안)**: 각도 단위. 1 rad = 57.3°. 0.019 rad ≈ 1.1°, 0.05 rad ≈ 2.9°.
- **ms / us**: 1 ms(밀리초) = 1,000분의 1초, 1 us(마이크로초) = 100만분의 1초. 1 ms = 1,000 us.
- **RT 스레드**: 실시간(real-time) 우선순위로 도는 스레드. SCHED_FIFO 80 은 "우선순위 80, 더 급한 것이 없으면 CPU 를 안 내놓는 규칙"이다.
- **링 버퍼(ring buffer)**: 칸이 원처럼 이어진 고정 크기 저장소. 여기서는 명령 우편함 64칸, 상태 벨트 2048칸.
- **깨어남 지연(wake-up latency)**: "이 시각에 깨라"고 한 시각보다 실제로 늦게 깬 시간. 표①의 주인공.
- **워치독(watchdog)**: 일정 시간 소식이 없으면 안전한 행동(여기서는 멈춤)으로 가는 감시 장치.
- **백엔드(backend)**: 제어 코드가 "로봇"이라고 부르는 대상. 시뮬레이터일 수도, 실물 서보일 수도 있다.
- **qpos / qvel**: MuJoCo 가 쓰는 이름으로 관절 위치(position)와 속도(velocity).
- **rosbag2 / MCAP**: ROS 2 의 녹화 도구와 그 파일 형식.
- **MQTT / 브로커 / 수집기 / Grafana**: 2부에서 자세히. 장치 → 우체국(브로커) → 받아서 DB 에 적는 프로그램(수집기) → 화면(Grafana).

## 4. 쉬운 예시
- **식당 비유**: 손님이 주문(①)을 하면 점원이 주방에 전달(②)하고, 주방 입구의 주문표 꽂이(③ 우편함)에 꽂는다. 요리사는 1분마다 정확히 꽂이를 확인(④)하고, 이상한 주문(알레르기·과한 양)은 걸러서(⑤) 조리 도구(⑥ 백엔드)로 요리한다. 음식이 나오고(⑦), 홀에 "N번 나왔습니다" 알림(⑧)이 가고, 주문 기록이 장부에 남고(⑨), 본사 대시보드에 매출 요약이 올라간다(⑩). 점원과 요리사는 서로 말을 걸지 않고 꽂이로만 소통한다 — 그것이 "두 세계의 경계는 링 버퍼뿐"이다.
- **숫자 예시**: 명령이 50 Hz 면 20 ms 에 하나 온다. 제어 루프는 1 ms 마다 깨므로 명령 하나가 머무는 동안 20번 깬다. 그중 1번만 새 명령을 보고, 나머지 19번은 지난 목표를 그대로 쓴다(⑤의 "최신 명령만"). 목표가 갑자기 1 rad 뛰어도 한 주기에 0.05 rad 씩만 움직이니 20 주기(20 ms)에 걸쳐 따라간다.

## 5. 숫자의 출처와 다시 확인하는 법
- 확인: 50 Hz(명령)·1 kHz(루프)·100 Hz(상태)·1 Hz(rt_status) — `rt_control/ros2_adapter/src/rt_control_node.cpp` 의 파라미터 기본값과 `docs/experiments/E03.md` 조건 표. `ros2 topic hz /joint_states` 로 100.0 근처를 다시 볼 수 있다.
- 확인: 워치독 50 ms, 변화량 제한 0.05 rad — `rt_control/rt_core/include/rt_core/control_step.hpp:30-31`(기본값), `robots/so101.yaml`(`watchdog_ms: 50`, `max_step_rad: 0.05`).
- 확인: 링 칸 수 64·2048 — `rt_control/rt_core/include/rt_core/joint_types.hpp:40,43`(`kCommandRingSize = 64`, `kStateRingSize = 2048`).
- 확인: 어깨 처짐 0.019 rad(1.1°) — `docs/measurements/record_summary_wsl_20261105.md` 추종 오차 표(shoulder_lift 0.0191 rad), `docs/experiments/E16.md`. WSL2 에서 MuJoCo 백엔드로 잰 값이다(물리 결과라 커널과 무관).
- 확인: 줄 번호(184-201, 100-162, 28-56, 226-239, 210-230) — 각 파일을 `sed -n` 으로 열면 그 함수가 있다. `rt_loop.cpp:100-162` 는 `run()` 전체(준비 5단계 호출부터 for 문 끝까지)를 가리킨다.
- 확인: "51번째 장치" — 가상 장치가 50대(`virtual_fleet.py --count 50`)이고 RT 노드 다리가 하나 더 붙는다(`fleet/agent/ros_status_bridge.py`).

## 6. 자주 하는 오해·함정
- "10단계가 전부 실시간이다" — 아니다. 실시간은 ④~⑥과 ⑧의 앞부분(벨트에 올리기)뿐이다. 명령을 받는 것(③)도, 발행하는 것(⑧ 뒷부분)도 일반 스레드다. 색을 그렇게 칠한 이유.
- "1 kHz 로 명령을 보내야 1 kHz 제어다" — 아니다. 명령은 50 Hz 여도 루프는 1 kHz 로 돌며 최신 목표를 유지한다. 명령 주기와 제어 주기는 다른 것이다.
- "⑦ 이 시뮬레이션이니 숫자가 그냥 목표와 같다" — 아니다. 물리가 들어왔기 때문에 중력이 걸리는 어깨는 목표보다 1.1° 처진다. 그래서 상자에 "데이터가 말해 준 사실"이라고 썼다.
- 이 장표에는 시험·검증이 하나도 없다. 상자의 `표①`·`표②`·`E15·E16·E20` 은 "그 단계의 증거는 3부 검증에 있다"는 표시일 뿐이다.

## 7. 면접 한 문장
"명령 하나가 50 Hz 로 들어와서, 락 없는 우편함을 건너 1 kHz 실시간 스레드가 꺼내고, 워치독과 변화량 제한을 거쳐 백엔드에 쓰이면 로봇이 움직입니다 — 그 결과를 100 Hz 로 읽어 기록하고 1 Hz 요약을 관제로 올리는 10단계를 한 장으로 그렸고, 상자마다 코드 위치가 적혀 있습니다."
