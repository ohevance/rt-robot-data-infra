# 장표 028 — 단계 5 그림 — 제어 단계 한 주기(1 ms): 최신 명령 → 워치독 → 상태 머신 → 변화량 제한 → 로봇 쓰기/읽기 → 벨트
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ② 그림 — 한 주기의 다섯 가지*

## 1. 이 장표가 왜 있나
앞 장표(027, 단계 5 들머리)에서 "깨서 꺼낸 명령을 그대로 로봇에 쓰면 위험하다 — 명령이 끊기면 마지막 목표로 계속 가고, 값이 튀면 로봇을 치고, 상태 전이가 뒤엉킨다"는 문제와 "50 ms 끊기면 멈춤, 한 주기 변화량 ≤ 0.05 rad, 전이표 밖 전이 0, 함수 안 할당·락·파일 0"이라는 기준을 세웠다. 이 장표는 그 기준을 지키는 함수 `ControlStep::step()` 이 한 주기(1 ms) 안에 하는 다섯 가지를 순서도로 그린 것이다. 상자 하나가 코드의 함수 하나이고, 마름모 둘이 두 안전 검사(워치독, 변화량 제한)다. 이 그림을 머리에 넣고 다음 장표 029(step 본체 코드)부터 035(상태 머신 코드)까지를 읽으면 각 코드가 그림의 어느 상자인지 바로 연결된다.

## 2. 장표를 하나씩 읽기
흐름은 왼쪽 위 → 오른쪽 → 아래로 내려와 → 왼쪽(뱀 모양)이다.

- 회색 육각형 "우편함 (명령 링 64)": 단계 3 의 링 버퍼. 이 단계의 입력.
- 민트 상자 "① take_latest_command — 전부 비우고 마지막 것만 → desired_ (상위가 원하는 목표)": 우편함을 비우고 마지막 명령을 `desired_`(원하는 목표 위치 6개)에 넣는다. 밀렸다 풀린 옛 목표를 순서대로 따라갈 이유가 없다는 결정(D1). 코드 :61-79, 장표 030.
- 노란 마름모 "② 워치독 — 마지막 명령이 50 ms 보다 오래됐나?": 첫 번째 안전 검사. 마지막 명령 시각(`last_cmd_ns_`)과 지금의 차이가 `watchdog_ns`(50,000,000 ns = 50 ms)보다 크면 "끊겼다(stale)". 50 ms 는 50 Hz 명령 2.5개 분량 — 명령 하나가 늦는 정도는 봐주고, 셋이 연달아 안 오면 끊긴 것으로 본다. 코드 :83-100, 장표 031.
- 붉은 상자 "예(stale): desired_ = 현재 위치(멈춤) tripped=true, watchdog_trips++": 끊겼으면 목표를 지금 있는 자리로 바꿔 더 움직이지 않게 한다(급정지도, 원점 복귀도 아님 — 가장 안전한 기본값). 정상 → 멈춤으로 바뀌는 순간에만 `watchdog_trips` 를 1 센다.
- 민트 상자 "아니오: tripped=false": 명령이 제때 오고 있으면 멈춤 상태를 푼다.
- 보라 상자 "상태 머신 handle(사건) — COMMAND / WATCHDOG_TRIP / RECOVERED → RUNNING·FAULT·… (전이표, 표 밖은 illegal_events++)": 두 갈래 모두 상태 머신으로 간다. `update_state_machine()` 이 이번 주기의 사실(명령이 왔나, 끊겼나)을 사건으로 바꿔 전이표에 넣는다 — 끊김은 WATCHDOG_TRIP, 명령 도착은 COMMAND, 복구 중 정상 주기 100번이면 RECOVERED. 표에 없는 조합은 거부하고 `illegal_events` 를 센다(0 이어야 정상). 코드 :103-122 와 `robot_state_machine.cpp:15-46`, 장표 033~035.
- 노란 마름모 "③ 변화량 제한 — |desired − applied| > 0.05 rad?": 두 번째 안전 검사. 로봇에 실제로 보낼 값 `applied_` 가 한 주기에 0.05 rad(2.9°) 넘게 뛰지 못하게 한다. 관절마다 따로 검사한다. 코드 :126-142, 장표 032.
- 붉은 상자 "예: 이번 주기는 0.05 rad 만 이동 step_limited++": 목표가 멀면 이번 주기에는 0.05 rad 만 다가간다. 1 kHz 이므로 최대 50 rad/s — 실물에서는 로봇 프로필의 `safety.max_step_rad` 로 더 줄인다. 제한이 걸린 주기 수를 `step_limited` 로 센다(11/03 시험: 그리퍼 목표 0.5 rad 를 0.05 씩 10주기).
- 민트 상자 "아니오: applied_ = desired_": 차이가 작으면 목표를 그대로 쓴다.
- 파란 육면체 "④ 백엔드(로봇 쪽) write_command(applied_) read_state(position_, velocity_) SimLag | MuJoCo | 실물(자리)": 안전해진 목표를 로봇에 쓰고(`write_command`) 실제 위치·속도를 읽는다(`read_state`). 로봇이 무엇인지는 백엔드 구현이 정한다(단계 6).
- 회색 육각형 "⑤ 상태 벨트(링 2048)에 JointStateSample push — 꽉 차면 state_drops++ (기다리지 않음)": 읽은 위치·속도·목표·깨어남 지연·워치독 상태·로봇 상태를 한 묶음(`JointStateSample`)으로 벨트에 올린다. 발행 스레드가 100 Hz 로 비운다(단계 8). 꽉 차면 버리고 센다 — 단계 3 의 우편함과 같은 규칙.
- 화살표 글: 마름모에서 나가는 "예"/"아니오", 백엔드 → 벨트의 "읽은 위치·속도".
- 아래 글 두 줄: "한 주기(1 ms) 안에 이 다섯 가지 전부. 함수 안에 할당·락·파일·네트워크가 없다(RT 규칙). 로봇에 실제로 가는 값은 desired_ 가 아니라 applied_ 다" — 로봇은 상위의 희망(desired_)이 아니라 안전 검사를 통과한 값(applied_)만 받는다. "카운터(commands_applied · watchdog_trips · step_limited · state_drops · illegal_events)는 std::atomic — ROS 2 스레드가 1 Hz 로 읽어 rt_status 에 싣는다(단계 8)" — 이 그림의 상자들이 남기는 숫자가 어디로 가나.
- legend "소스 위치: …": 상자 ↔ 코드 줄. `control_step.cpp:28-56` step() 본체(다섯 가지를 차례로 부르는 함수), :61-79 ①, :83-100 ②, :103-122 상태 머신 갱신, :126-142 ③, `robot_state_machine.cpp:15-32` 전이표와 :34-46 handle. "안전 경로(명령이 끊기면 FAULT → RECOVERING → READY)는 1부 끝의 가로지르기 장표"(057) — 끊김 뒤 복구까지의 시간 순서는 거기서.

## 3. 용어와 단위
- desired_ / applied_ / position_: 상위가 원하는 목표 / 안전 검사를 거쳐 실제로 로봇에 보내는 값 / 로봇에서 읽은 실제 위치. 셋 다 관절 6개 배열, 단위 rad.
- rad: 각도의 SI 단위. 1 rad = 57.3°, 0.05 rad = 2.9°.
- 워치독(watchdog): "정해진 시간 안에 신호가 안 오면 안전 조치"를 하는 감시 장치. 여기서는 50 ms.
- stale: "오래됐다". 마지막 명령이 50 ms 보다 오래된 상태.
- 상태 머신 / 전이표: 로봇 상태 5개(INIT · READY · RUNNING · FAULT · RECOVERING)와 사건 5개(INIT_DONE · COMMAND · WATCHDOG_TRIP · RECOVERED · STOP)의 허용된 조합을 표 한 장으로 적은 것. 표 밖은 불법(illegal).
- 변화량 제한(step limit): 한 주기에 목표가 바뀔 수 있는 최대 폭. 0.05 rad/주기.
- 백엔드(Backend): 로봇 쪽 인터페이스 세 함수(init · write_command · read_state). SimLag(1차 지연 모델) · MuJoCo(물리) · 실물(자리).
- 벨트 / state_drops: 상태 샘플을 발행 스레드로 넘기는 링(2048칸)과, 꽉 차 버린 수.
- std::atomic 카운터: 두 스레드가 같이 봐도 안전한 정수. RT 가 쓰고 ROS 2 스레드가 1 Hz 로 읽는다.

## 4. 쉬운 예시
- 비유: 운전 중 내비게이션 안내(명령)를 그대로 핸들에 전달하지 않는 안전 운전자. ① 가장 최근 안내만 듣고, ② 안내가 50 ms 넘게 끊기면 그 자리에 정지하고(워치독), 상황판(상태 머신)에 "정지"를 표시하며, ③ "지금 당장 180° 돌아라"는 안내가 와도 한 번에 2.9° 씩만 돌리고(변화량 제한), ④ 바퀴에 쓰고 현재 위치를 읽어, ⑤ 블랙박스 벨트에 기록한다. 모두 1 ms 안에.
- 숫자 예시: 그리퍼 목표가 0 → 0.5 rad 로 뛰면 변화량 제한 때문에 0.05 rad 씩 10주기(10 ms)에 걸쳐 도달하고 step_limited 가 10 오른다(11/03 실측). 명령 발행을 끊으면 50 ms 뒤 watchdog_trips 1, 상태 RUNNING → FAULT; 다시 발행하면 RECOVERING 을 거쳐 100주기(100 ms) 연속 정상이면 READY.

## 6. 자주 하는 오해·함정
- "워치독이 걸리면 로봇이 급정지한다"가 아니다. 목표를 현재 위치로 바꿔 '더 가지 않게' 할 뿐이고, 변화량 제한도 그대로 적용된다. 실물에서는 토크 오프까지 가야 하며 그 자리(`Backend::safe_stop`)는 2주 범위 밖으로 비워 두었다.
- 변화량 제한은 "로봇의 속도 제한"이 아니라 "목표가 뛰는 것"을 막는 장치다. 1 kHz × 0.05 rad = 50 rad/s 까지 허용하므로 실물에서는 프로필 값으로 더 줄여야 한다.
- 상태 머신은 워치독의 결과를 받아 움직인다(그림에서 두 갈래가 모두 보라 상자로 간다). 워치독이 없으면 WATCHDOG_TRIP 사건도 없다.
- 이 다섯 가지 안에는 `new`, 락, 파일, 네트워크가 없다 — 하나라도 들어가면 단계 4 에서 잰 189 us 가 무의미해진다.

## 7. 면접 한 문장
"제어 한 주기는 다섯 가지뿐입니다 — 최신 명령만 취하고, 50 ms 끊기면 그 자리에 멈추며 상태 머신을 전이표로 갱신하고, 한 주기 0.05 rad 넘게 못 뛰게 한 뒤, 로봇에 쓰고 읽어 벨트에 올립니다. 로봇에 가는 값은 희망(desired)이 아니라 검사를 통과한 값(applied)입니다."
