# 장표 036 — 단계 5 — rt_status 에 올라가는 카운터 — 제어 단계가 스스로를 설명하는 숫자들
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ④ 판단 — rt_status 카운터*

## 1. 이 장표가 왜 있나
- 단계 5 의 앞 장표들(장표 029~035)에서 제어 단계가 한 주기에 하는 다섯 가지와 세 가지 안전장치(최신 명령만 · 워치독 · 변화량 제한)와 상태 머신 코드를 봤다. 그러면 자연스럽게 이런 질문이 생긴다. "그 안전장치가 실제로 동작했는지, 지금 로봇이 어떤 상태인지 밖에서는 어떻게 아나?"
- 이 장표가 그 답이다. 제어 단계는 자기가 한 일을 **카운터(숫자 세는 변수)** 로 남기고, 그 숫자들이 1초에 한 번 `rt_status` 라는 토픽(장표 050)으로 밖에 나간다. 즉 이 표는 "단계 5 의 판단 근거" 다 — 코드가 있다는 것만으로는 부족하고, 실제로 돌려서 숫자로 확인했다는 증거가 여기 있다.
- 순서도 논리로는 단계 5 의 마지막 걸음 "④ 판단" 에 해당한다. 이 표의 숫자가 정상값이면 단계 5 를 통과한 것이고, 그래서 다음 장표(단계 6 들머리)로 넘어간다.

## 2. 장표를 하나씩 읽기
표의 열(헤더)부터 읽는다.
- "카운터 (ControlCounters)": C++ 구조체 이름. `rt_control/rt_core/include/rt_core/control_step.hpp` 33~43줄에 정의돼 있다. 안에 있는 변수 하나하나가 표의 한 행이다.
- "뜻": 그 숫자가 무엇을 세는지.
- "정상값 · 실측": 정상이라면 어떤 값이어야 하는지, 그리고 실제로 돌렸을 때 나온 값(날짜 표시).

행 하나하나:
- `commands_applied` — RT 스레드가 우편함에서 꺼내 **실제로 적용한 명령 수**. 장표 030 의 `take_latest_command` 끝에서 1 씩 늘어난다. 명령을 50 Hz(1초에 50번)로 주면 1초마다 50 씩 늘어나야 정상이다. 이 숫자가 멈춰 있으면 명령이 안 들어오고 있다는 뜻이다.
- `state_drops` — 상태 벨트(RT 스레드가 매 주기 상태를 올려 두는 2,037칸짜리 링 버퍼)가 꽉 차서 **버린 샘플 수**. 발행 스레드가 100 Hz 로 벨트를 비우기 때문에(장표 049) 벨트에는 많아야 10개 정도만 쌓인다. 그래서 정상값은 0 이다. 0 이 아니면 발행 쪽이 멈췄거나 느려진 것이다.
- `watchdog_trips` — "정상 → 멈춤" 으로 넘어간 **횟수**. 장표 031 의 `check_watchdog` 에서 stale(명령이 50 ms 넘게 없음)로 처음 바뀌는 순간에만 1 씩 센다. 11/03 노드 시험에서 명령 발행을 일부러 끊었더니 정확히 1 이 됐다 — 워치독이 실제로 작동했다는 증거.
- `step_limited` — 변화량 제한(장표 032)이 **실제로 걸린 주기 수**. 목표가 한 주기 0.05 rad 보다 크게 뛸 때만 센다. 11/03 시험에서 그리퍼에 0.5 rad 를 한 번에 주자 0.05 씩 10주기에 나눠 가면서 10 이 됐다. 정상 운전(목표가 부드럽게 변할 때)에서는 0 에 가깝다.
- `watchdog_tripped` — 횟수가 아니라 **지금 멈춤 상태인가**(참/거짓). 시작할 때는 true 다. 이유: 노드가 뜨자마자 명령이 오기 전까지는 "명령이 없는 상태" 이므로 멈춰 있는 것이 안전하다. 첫 명령이 오면 false 가 된다.
- `robot_state` / `state_transitions` — 지금 상태(INIT·READY·RUNNING·FAULT·RECOVERING 중 하나, 장표 033)와 상태가 바뀐 횟수. 정상 운전 중이면 RUNNING. 명령이 끊겼다가 돌아오면 RUNNING → FAULT → RECOVERING → READY → RUNNING 으로 네 번 바뀌므로 횟수가 4 늘어난다.
- `illegal_events` — 전이표(장표 034)에 **없는 조합**의 사건이 들어온 횟수. 예를 들어 FAULT 상태에서 RECOVERED 사건이 오는 일은 설계상 없어야 한다. 그래서 0 이어야 정상이고, 0 이 아니면 코드 어딘가의 논리 버그다.

표 아래 주석:
- "전부 std::atomic — 락 없이 RT 스레드가 쓰고 ROS 2 스레드가 1 Hz 로 읽는다": 이 변수들은 두 스레드가 동시에 만진다(RT 스레드가 쓰고, 발행 스레드가 읽는다). 보통은 락(mutex)으로 보호하지만, RT 스레드가 락을 기다리면 지연의 꼬리가 생긴다(장표 021). 그래서 **원자 변수(atomic)** 를 쓴다 — 읽고 쓰는 동작 자체가 쪼개지지 않아 락 없이도 값이 깨지지 않는다.
- 출처: `control_step.hpp:33-43` 과 `rt_control_node.cpp` 의 `publish_status`(실제로 JSON 으로 찍는 곳, 장표 050).

아래 "다음 ▶": 안전해진 목표(`applied_`)가 생겼으니, 이제 그것을 로봇에 쓰는 단계 6 으로 간다. 로봇이 셋(SimLag·MuJoCo·실물)인데 제어 코드는 어떻게 그대로 두나 — 가 다음 질문이다.

## 3. 용어와 단위
- **카운터(counter)**: 어떤 일이 몇 번 일어났는지 세는 변수. 값이 "늘어나는 속도" 가 중요할 때가 많다(초당 50).
- **std::atomic(원자 변수)**: C++ 에서 "쪼개지지 않는" 읽기·쓰기를 보장하는 변수. 한 스레드가 쓰는 도중에 다른 스레드가 반쯤 쓰인 값을 읽는 일이 없다. 락과 달리 기다리지 않는다.
- **RT 스레드 / ROS 2 스레드**: RT 스레드는 1 ms 마다 깨서 제어를 하는 스레드(높은 우선순위). ROS 2 스레드는 토픽 발행·구독을 처리하는 일반 스레드. 이 표의 숫자는 RT 스레드가 쓰고 ROS 2 스레드가 읽는다.
- **상태 벨트**: 상태 샘플을 RT 스레드에서 밖으로 내보내는 링 버퍼(2,037칸). 컨베이어 벨트처럼 RT 가 올려 두면 발행 스레드가 걷어 간다.
- **Hz(헤르츠)**: 1초에 몇 번. 50 Hz = 20 ms 에 한 번, 100 Hz = 10 ms 에 한 번, 1 Hz = 1초에 한 번.
- **rad(라디안)**: 각도 단위. 1 rad ≈ 57.3°. 0.05 rad ≈ 2.9°, 0.5 rad ≈ 28.6°.
- **ms(밀리초)**: 1/1,000 초. 워치독 50 ms = 0.05 초.

## 4. 쉬운 예시
- 비유: 공장 기계에 붙은 **계기판**. "오늘 처리한 개수(commands_applied)", "비상정지 누른 횟수(watchdog_trips)", "속도 제한에 걸린 횟수(step_limited)", "지금 비상정지 상태인가(watchdog_tripped)", "현재 모드(robot_state)" 가 한 화면에 있다. 기계를 열어 보지 않아도 계기판만 보면 "정상인가, 무슨 일이 있었나" 를 안다.
- 숫자 예시: 노드를 띄우고 50 Hz 명령을 10초 동안 보낸 뒤 끊고, 5초 뒤 다시 보냈다고 하자. 기대값은 — `commands_applied` 약 500 + 그 뒤 재개분, `watchdog_trips` 1(끊긴 순간 한 번), `watchdog_tripped` 재개 뒤 false, `state_transitions` 끊김·복구로 4 증가(RUNNING→FAULT→RECOVERING→READY→RUNNING), `illegal_events` 0, `state_drops` 0. 하나라도 다르면 어디가 이상한지 바로 짚을 수 있다.

## 6. 자주 하는 오해·함정
- "`watchdog_tripped` 가 true 면 고장 아닌가?" — 시작 직후에는 **정상**이다. 명령이 한 번도 안 왔으니 멈춰 있는 것이 맞다. 첫 명령이 오면 false 로 바뀐다. 고장 신호는 "명령을 계속 보내는데도 true" 인 경우다.
- "`step_limited` 가 0 이 아니면 문제?" — 아니다. 목표가 크게 뛰는 순간(예: 그리퍼를 한 번에 0.5 rad 열기)에는 걸리는 것이 **설계대로** 다. 문제는 부드러운 명령인데도 계속 늘어나는 경우(상위가 잡음 섞인 목표를 보내는 중).
- 횟수(`watchdog_trips`)와 상태(`watchdog_tripped`)를 헷갈리기 쉽다. 하나는 "몇 번", 하나는 "지금".
- `state_drops` 와 `timing_drops` 는 다르다. 전자는 상태 벨트(2,037칸), 후자는 측정용 타이밍 링(65,536칸, 장표 026)이 꽉 찬 경우다. 둘 다 0 이어야 한다.

## 7. 면접 한 문장
- "제어 단계는 안전장치마다 카운터를 남깁니다 — 명령을 끊자 watchdog_trips 가 정확히 1, 목표를 0.5 rad 뛰게 하자 step_limited 가 10, 불법 전이는 0. 코드가 있다는 말이 아니라 숫자로 보여 드릴 수 있습니다."
