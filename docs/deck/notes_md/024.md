# 장표 024 — 단계 4 — RT 스레드가 1 ms 마다 깬다 — 준비 5단계 (run() 이 처음에 부른다)
*위치: 1부 로봇을 움직이는 길 · 단계 4/10 RT 1 ms 루프 · ② 코드 — 준비 5단계*

## 1. 이 장표가 왜 있나
- 단계 4 들머리(022)와 시간축 그림(023)에서 "RT 스레드는 1 ms 마다 절대 시각에 깬다"고 했다. 그런데 보통 스레드를 그냥 1 ms 마다 재우고 깨우면 수백 us 씩 늦게 깬다. **스레드를 '실시간 스레드'로 만드는 준비**가 먼저 필요하다.
- 이 장표는 `RtLoop::run()` 이 루프에 들어가기 전에 부르는 준비 함수 다섯 개 중 세 개의 코드를 보인다(lock_memory, set_realtime_priority, prefault_stack). 나머지 둘(record_kernel_info, pin_cpu)은 오른쪽 요점에 글로 적었다.
- 위치는 `rt_control/rt_core/src/rt_loop.cpp:29-97` 이고 "(요약 발췌)"라고 적은 이유는 다섯 함수 중 셋만 골라 실었기 때문이다. 이 다섯이 바로 공고의 "PREEMPT_RT · SCHED_FIFO · mlockall" 키워드가 코드로 나타나는 자리다.

## 2. 장표를 하나씩 읽기
**lock_memory() (파일 44~50줄)**
- `mlockall(MCL_CURRENT | MCL_FUTURE)` — 지금 쓰는 메모리 페이지(CURRENT)와 앞으로 할당될 페이지(FUTURE)를 전부 RAM 에 고정한다. 고정하지 않으면 운영체제가 안 쓰는 페이지를 디스크(스왑)로 내보낼 수 있고, 루프 중에 그 페이지를 다시 읽어 오느라 수 ms 가 걸릴 수 있다.
- 성공하면 `status_.mlock_ok = true`, 실패하면 `errno`(실패 이유 번호)를 남긴다. **실패해도 멈추지 않는다.** 권한(ulimit -l)이 모자라면 실패하는데, 그 사실을 숫자 옆에 적어 두려는 것이다.

**set_realtime_priority() (70~84줄)**
- `if (cfg_.prio <= 0) return;` — 설정이 0 이면 일반 스케줄링으로 돈다(`--no-rt` 옵션). 비교 실험(일반 vs RT)이 가능한 이유.
- `pthread_setschedparam(pthread_self(), SCHED_FIFO, &sp)` — 지금 스레드를 SCHED_FIFO 정책, 우선순위 `cfg_.prio`(기본 80)로 바꾼다. SCHED_FIFO 는 "더 급한(우선순위 높은) 스레드가 없으면 CPU 를 내놓지 않는다"는 규칙이다. 일반 스레드처럼 시간을 나눠 쓰지 않는다.
- 성공 `rt_sched_ok = true`, 실패 `rt_errno = rc`. root 가 아니거나 RLIMIT_RTPRIO 한도가 0 이면 EPERM 으로 실패한다.

**prefault_stack() (86~97줄)**
- `volatile unsigned char pad[256 * 1024];` — 스택에 256 KB 배열을 잡고 4096 바이트(페이지 하나)마다 한 번씩 0 을 쓴다. 리눅스는 메모리를 "처음 건드릴 때" 실제로 할당한다(페이지 폴트). 그 첫 폴트를 루프 밖에서 미리 일으켜 두면 루프 안에서는 생기지 않는다.
- `volatile` 은 "안 쓰는 배열이니 지우자"는 컴파일러 최적화를 막는다. 마지막 두 줄(`last`, `(void)last`)은 "쓰기만 하고 안 읽은 변수" 경고를 막기 위한 것이다.
- mlockall(MCL_FUTURE) 뒤에 하므로 이 페이지들도 RAM 에 고정된다.

**오른쪽 요점**
- 0) `record_kernel_info`: `uname -r` 와 `/sys/kernel/realtime`(1 이면 PREEMPT_RT) 을 기록 — 모든 측정 표의 "커널" 열이 여기서 나온다.
- 1) mlockall, 2) `pin_cpu`(`--cpu N` 이면 그 CPU 에만 붙인다 — Pi 실험 E19-b 가 `--cpu 3`), 3) SCHED_FIFO 80, 4) 스택 256 KB 미리 밟기.
- 실패해도 멈추지 않고 `RtStatus` 에 남긴다 → 표의 비고에 `SCHED_FIFO=ok mlockall=ok` 로 보인다.

## 3. 용어와 단위
- **PREEMPT_RT**: 리눅스를 실시간용으로 고친 커널 패치. 커널 안에서도 급한 스레드가 끼어들 수 있게 한다. `/sys/kernel/realtime` 파일이 1 이면 켜진 커널.
- **SCHED_FIFO**: 실시간 스케줄링 정책. 우선순위 1~99, 같은 우선순위끼리는 먼저 온 순서. 여기서는 80.
- **mlockall**: 프로세스의 메모리를 전부 RAM 에 고정하는 시스템 호출. MCL_CURRENT(지금 것), MCL_FUTURE(앞으로 것).
- **페이지 폴트(page fault)**: 처음 건드리는 메모리 페이지를 운영체제가 실제로 붙여 주는 사건. 수 us ~ 수십 us 걸린다. 1 페이지 = 4096 바이트(4 KB).
- **CPU 고정(affinity, pin)**: 스레드를 특정 CPU 에서만 돌게 하는 것. 옮겨 다니면 캐시가 식는다.
- **errno / rc**: 시스템 호출 실패 이유를 담는 정수. EPERM(권한 없음)이 흔하다.
- **RLIMIT_RTPRIO**: 일반 사용자가 쓸 수 있는 최대 실시간 우선순위 한도. 0 이면 못 쓴다. `sudo prlimit --pid $$ --rtprio=99 --memlock=unlimited` 로 터미널에 열어 준다(ros2_adapter/README.md).
- **KB**: 킬로바이트. 256 KB = 262,144 바이트 = 64 페이지.

## 4. 쉬운 예시
- **수술실 준비 비유**: 수술(1 ms 루프) 전에 (0) 어느 병원·어느 수술실인지 기록하고(record_kernel_info) (1) 필요한 도구를 전부 수술실 안에 들여놓고 창고에 두지 않는다(mlockall) (2) 의사를 한 수술실에만 배정한다(pin_cpu) (3) 의사에게 "호출이 오면 다른 일보다 먼저"라는 권한을 준다(SCHED_FIFO) (4) 수술 중 처음 쓰는 서랍이 없도록 서랍을 전부 한 번씩 열어 둔다(prefault_stack). 어느 하나가 안 되어도 수술은 하되, 차트에 "도구 일부 창고" 라고 적는다.
- **숫자 예시**: WSL2 에서 `prlimit` 를 안 건 터미널로 노드를 띄우면 `rt.sched_fifo=false` 로 뜨고(LOG 11/04), 그 상태의 wake max 는 수백 us 다. 같은 Pi 4 에서 일반 커널은 부하 max 781 us, RT 커널 + CPU 3 고정 + 격리는 189 us(표①).

## 6. 자주 하는 오해·함정
- "SCHED_FIFO 80 이면 무조건 1 ms 를 지킨다" — 아니다. 커널 자체가 끼어들기를 막는 구간(일반 커널)이 있어 RT 커널이 필요하고, 다른 CPU 로 옮겨 다니는 비용과 같은 CPU 의 다른 일도 꼬리를 만든다. 그래서 3부 표①이 일반 → RT → 고정 → 격리 순서로 하나씩 바꿔 가며 잰 것이다.
- "mlockall 이 실패하면 프로그램이 죽어야 한다" — 이 저장소는 죽이지 않고 기록한다. 측정값 옆에 "mlockall=fail" 이 붙으면 그 숫자를 그렇게 읽으라는 뜻이다. 숨기는 것보다 적는 것이 낫다는 원칙.
- "prefault_stack 은 쓸모없는 코드 아닌가" — 컴파일러가 보기에는 결과를 안 쓰는 배열이라 지우려 든다. `volatile` 과 마지막 읽기가 그것을 막는다. 지워지면 첫 페이지 폴트가 루프 안에서 생긴다.
- 우선순위 99 가 아니라 80 인 이유: 커널의 일부 실시간 스레드(IRQ 스레드 등)보다 높게 두면 시스템이 굳을 수 있다. 80 은 그 아래의 관례적인 값이다(추정: 저장소에 이유가 따로 적혀 있지는 않다).

## 7. 면접 한 문장
"루프에 들어가기 전에 커널 종류를 기록하고, 메모리를 RAM 에 고정하고, CPU 를 붙이고, SCHED_FIFO 80 을 걸고, 스택 256 KB 를 미리 밟습니다 — 하나가 실패해도 죽이지 않고 RtStatus 에 남겨, 모든 측정 표의 비고에 `SCHED_FIFO=ok mlockall=ok` 가 함께 찍히게 했습니다."
