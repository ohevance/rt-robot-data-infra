# 장표 029 — 단계 5 — 제어 단계 — 한 주기에 하는 다섯 가지 (ControlStep::step)
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ② 코드 — step() 다섯 가지*

## 1. 이 장표가 왜 있나
- 앞 장표(028)에서 제어 단계 한 주기를 그림(파이프라인)으로 봤다. 이 장표는 그 그림이 코드로는 **함수 하나**라는 것을 보인다. `ControlStep::step()` 29줄이 1 ms 마다 RT 스레드에서 불리고, 다섯 가지 일을 순서대로 한다.
- 단계 4의 루프 본체(026)에서 `step.step(i, s.wake_lat_ns)` 라고 불렀던 그 `step` 이 이 함수다. 측정기에서는 같은 자리에 "바쁘게 돌기"(BusyWorkStep)가 들어가고, 제어 노드에서는 이 ControlStep 이 들어간다.
- 위치 `rt_control/rt_core/src/control_step.cpp:28-56`. 뒤따르는 세 장표(030·031·032)는 여기서 부르는 함수 셋을 하나씩 펼친 것이다.

## 2. 장표를 하나씩 읽기
- `void ControlStep::step(std::uint64_t iter, std::int64_t wake_lat_ns)` — 인자는 주기 번호와 이번 주기의 깨어남 지연. 둘은 계산에 쓰지 않고 상태 샘플에 그대로 실어 보낸다(나중에 "어느 주기, 얼마나 늦게 깼을 때의 값인가"를 맞춰 볼 수 있게).
- `std::int64_t now = now_ns();` — 단조 시계로 지금 시각. 워치독의 "얼마나 오래 명령이 없었나" 계산에 쓴다.
- `got_command_this_cycle_ = false;` — 이번 주기에 새 명령이 왔는지 표시. 상태 머신에 COMMAND 사건을 넣을지 정한다.
- **1) `take_latest_command(now);`** — 우편함을 전부 비우고 마지막 명령만 `desired_` 에 넣는다(030).
- **2) `check_watchdog(now);`** — 마지막 명령으로부터 50 ms 가 지났으면 `desired_ = 현재 위치`(멈춤), 그리고 상태 머신을 갱신한다(031).
- **3) `limit_step();`** — `applied_` 가 `desired_` 를 향해 한 주기에 `max_step_rad`(0.05) 이상 뛰지 않게 한다(032).
- **4) `backend_.write_command(applied_, cfg_.dof); backend_.read_state(position_, velocity_, cfg_.dof);`** — 로봇(백엔드)에 목표를 쓰고, 현재 위치·속도를 읽는다. 백엔드가 SimLag 든 MuJoCo 든 실물이든 이 두 줄은 같다(단계 6).
- **5) 벨트에 올리기** — `JointStateSample s;` 에 주기 번호·시각·깨어남 지연·관절 수·워치독 상태·로봇 상태(`sm_.state()` 를 정수로)·관절별 위치·속도·적용 목표를 채우고 `state_ring_.push(s)`. 꽉 차면 `counters_.state_drops` 를 1 올린다. **기다리지 않는다.**
- **오른쪽 요점**: ①~⑤ 요약과 마지막 줄 "이 함수 안에 할당·락·파일이 없다 — RT 규칙". 실제로 이 함수가 부르는 모든 코드는 고정 배열 복사, 정수 비교, 원자 변수 증가뿐이다.
- 참고: 상태 벨트 쪽에서는 RT 스레드가 **생산자**다. 우편함에서는 소비자였다. 같은 SpscRing 클래스를 반대 방향으로 쓴다.

## 3. 용어와 단위
- **ControlStep**: "제어 한 주기"를 담당하는 클래스. `RtStep` 인터페이스를 구현해 RtLoop 가 매 주기 부른다.
- **desired_ / applied_ / position_ / velocity_**: 원하는 목표 / 실제 보내는 목표 / 읽은 위치 / 읽은 속도. 전부 `double[kMaxJoints]`(64칸 고정 배열), 단위 rad, rad/s.
- **cfg_.dof**: 관절 수(6). 배열은 64칸이지만 앞 6칸만 쓴다.
- **JointStateSample**: 벨트 한 칸에 들어가는 고정 크기 구조체. 발행 스레드가 100 Hz 로 꺼내 `/joint_states` 로 낸다(단계 8).
- **state_drops**: 상태 벨트가 꽉 차서 버린 수. 2048칸을 1 kHz 로 채우고 100 Hz 로 비우므로 정상이면 0.
- **fetch_add(1, relaxed)**: 원자 변수를 1 올리는 연산. 다른 스레드(발행 스레드)가 읽어도 값이 깨지지 않는다.
- **static_cast<std::uint8_t>**: 열거형(RobotState)을 1바이트 정수로 바꾸는 것. 벨트에는 정수로 싣고, 발행할 때 이름으로 바꾼다.
- **할당·락·파일**: `new`/`malloc`, mutex, open/write 같은 "얼마나 걸릴지 모르는" 동작. RT 함수에서 금지.

## 4. 쉬운 예시
- **공장 라인 검사원 비유**: 1 ms 마다 벨이 울리면 검사원(step)이 (1) 지시서 함에서 가장 최근 지시서만 집는다 (2) 지시서가 50 ms 넘게 안 왔으면 "현재 자세 유지" 지시서를 스스로 쓴다 (3) 지시가 지금 자세와 너무 다르면 한 번에 0.05 rad 만큼만 옮긴다 (4) 기계에 지시를 넣고 기계의 현재 자세를 읽는다 (5) 결과를 보고 벨트에 올린다 — 벨트가 꽉 차면 보고서를 버리고 "버림 1" 을 표시한다. 검사원은 전화도 받지 않고(락 없음) 서류를 새로 만들지도 않고(할당 없음) 장부에 직접 쓰지도 않는다(파일 없음).
- **숫자 예시**: 50 Hz 명령이면 20주기 중 1번만 1)에서 새 지시서가 나오고 19번은 지난 `desired_` 그대로다. 그래도 3)~5)는 매 주기 돈다. 그래서 `/joint_states` 는 명령이 없어도 100 Hz 로 나온다.

## 6. 자주 하는 오해·함정
- "step() 안에서 ROS 2 메시지를 만들어 발행하면 간단하지 않나" — 메시지 생성은 메모리 할당이고 발행은 미들웨어 호출이다. 둘 다 얼마나 걸릴지 모른다. 그래서 고정 크기 샘플을 벨트에 올리기만 하고, 발행은 일반 스레드가 한다(단계 8).
- "워치독 검사가 명령 읽기보다 먼저 와야 하지 않나" — 순서가 중요하다. 먼저 명령을 읽어 `last_cmd_ns_` 를 갱신한 뒤 워치독이 그 값을 보아야 "지금 막 온 명령"을 끊김으로 오판하지 않는다.
- "read_state 는 write 전에 해야 한다" — 어느 쪽이든 한 주기 안이면 된다. 여기서는 쓰고 바로 읽어 "이 목표를 준 직후의 상태"를 같은 샘플에 싣는다.
- `wake_lat_ns` 를 샘플에 싣는 이유: 나중에 "추종 오차가 큰 순간이 늦게 깬 순간과 겹치나"를 CSV 로 볼 수 있게 하기 위해서다.

## 7. 면접 한 문장
"제어 한 주기는 함수 하나입니다 — 최신 명령 하나만 집고, 50 ms 끊김이면 현재 위치로, 한 주기 0.05 rad 까지만, 백엔드에 쓰고 읽고, 고정 크기 샘플을 벨트에 올립니다 — 그 안에 할당·락·파일이 없어서 RT 스레드에서 매 ms 돌아도 꼬리가 생기지 않습니다."
