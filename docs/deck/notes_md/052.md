## 2. 장표를 하나씩 읽기
그림(`img/record_flow_td.png`, 원본 `build/diagrams/record_flow_td.mmd`)은 위에서 아래로 여덟 상자다.

- 맨 위 "rt_control_node — /joint_states 100 Hz · /joint_command 50 Hz · /rt_status 1 Hz": 단계 8 까지 만든 노드가 내는(그리고 받는) 세 토픽. 기록의 입력.
- "record.sh 30 — timeout --foreground 30 ros2 bag record -s mcap --disable-keyboard-controls --topics …": `data_pipeline/record.sh` 22~23줄의 실제 명령. `timeout … 30` 이 30초 뒤 SIGINT 를 보내 녹화기를 곱게 끝내고, `-s mcap` 이 저장 형식, `--disable-keyboard-controls` 가 터미널을 읽지 않게, `--topics` 가 받을 토픽 세 개(위치 인자는 Jazzy 에서 폐기 예고)를 정한다. `--foreground` 가 첫 실패의 교훈이다(아래 다섯째 줄).
- "build/bags/run_<시각>/ — *.mcap 1.07 MB + metadata.yaml": 녹화 결과 폴더. MCAP 파일 하나와 메타데이터. 11/05 실제 폴더는 `run_20261105_124003`, 1.07 MB. 저장소에는 넣지 않는다(`build/` 는 git 제외).
- "bag_to_csv.py — open_bag → read_messages": `data_pipeline/bag_to_csv.py` 가 폴더를 열어(`open_bag`, 31줄, rosbag2_py 리더) 메시지를 토픽별로 역직렬화해 읽는다(`read_messages`, 43줄).
- 세 갈래 "joint_states.csv 2,964행 / joint_command.csv 1,482행 / rt_status.csv 29행": `write_joint_csv`(57줄)가 상태·명령을, `write_status_csv`(82줄)가 rt_status JSON 의 숫자 열만 뽑아 CSV 로 쓴다. 행 수가 곧 메시지 수. 29.6초 동안 100 Hz → 2,964, 50 Hz → 1,482, 1 Hz → 29(28초 구간).
- 맨 아래 "summary.md — rate_and_gaps: 실제 Hz · 틈 / tracking_error: |목표 − 위치| 관절별": 세 CSV 가 합쳐지는 곳. `rate_and_gaps`(110줄)가 토픽마다 기간·실제 Hz·틈 목록을, `tracking_error`(127줄)가 상태 시각마다 가장 최근 목표를 짝지어 관절별 |목표 − 위치| 의 평균·최대를, `write_summary`(157줄)가 그 둘을 표로 쓴다. 이 파일이 저장소의 `docs/measurements/record_summary_wsl_20261105.md` 로 복사돼 있다.

오른쪽 다섯 줄은 결과다.
- "record.sh 30: 토픽 3개를 30초 MCAP 으로 (1.07 MB)": 위 두 번째·세 번째 상자의 실제 값.
- "bag_to_csv.py: open_bag → read_messages → write_*_csv → rate_and_gaps → tracking_error → write_summary": 함수 여섯 개의 순서 = 파일 머리 "읽는 순서".
- "결과: 100.0 / 50.0 / 1.0 Hz, 틈(>3주기) 0, 드롭 0": 들머리의 기준 세 개를 넘었다. 실제 Hz 는 (메시지 수 − 1) ÷ 기간. 틈은 설계 주기의 3배(`GAP_FACTOR = 3.0`)보다 벌어진 곳.
- "추종 오차: shoulder_lift 0.0191, elbow_flex 0.0094, wrist_flex 0.0025 rad — 단계 7 의 처짐이 자동으로": 단계 7(045)에서 `ros2 topic echo` 로 눈으로 읽은 어깨 처짐(−0.181 vs −0.200 = 0.019)이 요약 표에 그대로 나왔고, 팔꿈치 0.0094(≈0.5°)·손목 0.0025(≈0.14°)는 눈으로는 지나친 것. 중력이 걸리는 관절(어깨·팔꿈치·손목 피치) 순서로 크다. shoulder_pan·wrist_roll 은 0.0000 — 회전축이 중력과 나란해 처질 것이 없다.
- "1차 실패: timeout 과 터미널(SIGTTIN) → --foreground + --disable-keyboard-controls": 첫 시도(12:34)는 `--foreground` 가 없어 녹화기가 뒤 프로세스 그룹에 놓였고, 키보드 제어(SPACE 일시정지)가 터미널을 읽다 SIGTTIN 으로 정지됐다. 정지된 프로세스는 30초 뒤 SIGINT 도 못 받아 스크립트가 영원히 기다렸다. 두 번째 시도(12:40)는 바로 통과.

## 3. 용어와 단위
- MCAP: rosbag2 의 저장 형식(Jazzy 기본). 여러 토픽을 시간순으로 한 파일에. `metadata.yaml` 은 토픽 목록·메시지 수·기간 같은 색인.
- 역직렬화(deserialize): 네트워크로 오간 바이트열을 다시 메시지 객체(JointState 등)로 되돌리는 것. `rclpy.serialization.deserialize_message`.
- CSV: 쉼표로 나눈 표 파일. 엑셀·pandas 로 바로 열린다.
- 실제 Hz: (메시지 수 − 1) ÷ (마지막 시각 − 첫 시각). 틈(gap): 연속 메시지 간격이 설계 주기 × 3 보다 클 때. 드롭: rt_status 의 timing_drops + state_drops.
- 추종 오차: |목표 − 위치|, rad. 1 rad = 57.3°. 0.0191 rad ≈ 1.1°, 0.0094 rad ≈ 0.5°, 0.0025 rad ≈ 0.14°.
- SIGINT / SIGTTIN / SIGCONT: 각각 '끝내라(Ctrl+C)' / '뒤에서 터미널을 읽으려 해서 정지' / '다시 돌아라' 신호. rosbag2 는 SIGINT 를 받아야 파일을 곱게 닫는다.
- 프로세스 그룹: 터미널이 키보드를 넘겨 주는 단위. 앞(foreground) 그룹 하나만 키보드를 받는다.

## 4. 쉬운 예시
비유 — 공장 CCTV 와 일일 점검표: CCTV(ros2 bag record)가 세 카메라(토픽) 영상을 하나의 녹화 파일(MCAP)에 담는다. 퇴근 전 점검 프로그램(bag_to_csv)이 파일을 열어 카메라별 프레임을 표로 뽑고(CSV), "카메라 1 은 30 fps 로 2,964프레임, 끊긴 구간 0" 과 "로봇 팔이 지시 위치에서 평균 1.1° 벗어남"을 한 장(summary.md)에 적는다. 첫날은 녹화기가 '일시정지 키를 누르셨나요?' 하고 키보드를 기다리다 멈춰 버린 것이 실패였다.

숫자 예시 — 틈의 기준: 100 Hz 는 10 ms 간격이 정상이므로 틈 기준은 30 ms. 29.6초에 2,964행이면 간격 평균 10.0 ms. 만약 어디서 녹화가 0.1초 멈췄다면 100 ms 간격이 하나 생겨 "틈 1 (시작 12.3초, 길이 0.100초)" 로 요약에 찍힌다. 추종 오차: 목표 −0.200 rad, 실제 −0.181 rad → 0.019 rad. 이 값이 2,964행 전부에서 같아 평균 = 최대 = 0.0191.

## 6. 자주 하는 오해·함정
- "bag_to_csv.py 가 ROS 2 없이 돌아가나?" — 아니다. `rosbag2_py`, `rclpy`, `sensor_msgs` 가 보이는 터미널(WSL 의 ROS 2 Jazzy)이 전제다. 샌드박스 검증은 가짜 모듈로 논리만 봤다.
- "MCAP 을 git 에 넣으면 안 되나?" — 1.07 MB 가 30초다. 하루면 수 GB 라 저장소에 넣지 않고 요약(summary.md)과 rt_status CSV 만 `docs/measurements/` 에 둔다.
- "rt_status.csv 가 29행이면 1초가 빠진 것 아닌가?" — 28초 구간에 29줄, 1.0 Hz. 1 Hz 는 첫 메시지가 녹화 시작 뒤 최대 1초 지나 오므로 30초 녹화에 29줄은 정상이다. 틈 기준(3초)도 넘지 않았다.
- "`--max-bag-duration` 으로 30초를 정하면 되지 않나?" — 그 옵션은 파일을 쪼개는 옵션이라 시간 제한 용도로는 `timeout` 을 쓴다(record.sh 18줄 주석).
- 함정: "조용히 안 끝남"은 죽은 게 아니라 정지된 것일 수 있다. `pkill -CONT` 로 깨운 뒤 `-INT` 로 끝낸다.

## 7. 면접 한 문장
"기록은 셸 한 줄(timeout --foreground 로 감싼 ros2 bag record, MCAP)과 파이썬 하나(open_bag → read_messages → CSV → rate_and_gaps → tracking_error → summary)로 끝나고, 30초 기록에서 100.0 Hz·틈 0·드롭 0 과 중력 처짐 1.1° 가 사람 손 없이 요약으로 나왔습니다 — 첫 시도가 SIGTTIN 으로 멈춘 것도 원인까지 스크립트 주석과 실험 문서에 남겼습니다."
