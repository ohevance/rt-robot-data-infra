# 장표 137 — 결국 로봇은 이렇게 움직인다
*위치: 끝*

## 1. 이 장표가 왜 있나
장표 003 의 목차는 "'로봇을 움직이고 싶다'에서 출발해 '결국 로봇은 이렇게 움직인다'로 끝난다"고 약속했다. 이 장표는 그 약속의 끝, 마지막 섹션(끝)의 표지다. 1~7부를 다 지나온 뒤 처음의 질문 — 그래서 로봇은 어떻게 움직이나 — 에 **한 문장**으로 답하고, 다음 장표(137)의 한 장 요약(10 상자)으로 넘긴다. 부제의 요구가 이 발표 전체의 기준이다: 어느 상자에서든 멈춰 "이 숫자는 어디서 왔고, 코드는 어디에 있고, 왜 그렇게 했나"를 말할 수 있어야 한다 — 숫자는 3·4·5부, 코드는 1·2부의 파일 위치, 왜는 7부의 결정 기록이 답한다. 발표에서는 처음 1부 장표 007(10단계 그림)을 떠올리게 하고 같은 길을 이번엔 숫자와 함께 다시 걷는다.

## 2. 장표를 하나씩 읽기
- 왼쪽 위 표지 번호 "끝" 과 제목 "결국 로봇은 이렇게 움직인다": 숫자 번호가 아니라 '끝'이다. 1부 표지(005) 제목 "로봇을 움직이는 길 — 명령에서 움직임까지"와 짝을 이룬다.
- 부제 "출발(공고)에서 여기까지 온 길을 한 장으로 접는다 — 어느 상자에서든 멈춰 '이 숫자는 어디서 왔고, 코드는 어디에 있고, 왜 그렇게 했나'를 말할 수 있어야 한다": '접는다'는 긴 길을 한 장으로 요약한다는 뜻. 세 질문(어디서 왔나·코드는 어디·왜)이 면접 준비의 체크리스트다.
- 흐름 상자 "들어온 것": "1~7부 — 로봇을 움직이는 10단계 · 데이터의 길 8단계 · 검증 · 공고와 숫자 · 어디서 · 어떻게 믿나 · 왜 이렇게". 일곱 부의 제목을 한 줄에 다 적었다.
- 흐름 상자 "질문": "그래서 로봇은 어떻게 움직이나?" 발표의 첫 질문이자 마지막 질문.
- 흐름 상자 "답": "명령 50 Hz → DDS → 우편함 → 1 ms 루프(max 189 us) → 안전 검사 → MuJoCo → 관절이 움직인다(어깨 1.1° 처짐) → 상태 100 Hz → 기록(틈 0) → 관제(유실 0). 한 장표에 숫자와 파일 이름을 같이". 1부의 10단계를 화살표 열 개로 압축하고, 괄호마다 그 단계의 대표 숫자를 붙였다. 하나씩: 명령은 `/joint_command` 로 50 Hz(1부 단계 1) → DDS 가 전달(단계 2, 표②: 작은 메시지 손실 0) → 우편함 = 락 없는 SPSC 링(단계 3) → RT 스레드가 1 ms 마다 깬다(단계 4, 표①: Pi 4 RT + 격리 max 189 us) → 제어 단계의 안전 검사: 최신 명령·워치독·변화량 제한·상태 머신(단계 5) → MuJoCo 백엔드(단계 6, 한 주기 p99 8.5 us) → 관절이 움직이고 어깨는 중력으로 1.1° 처진다(단계 7, E16) → 상태를 100 Hz 로 발행(단계 8) → rosbag2 기록 → CSV → 요약, 틈 0(단계 9, 11/05) → 관제로 올라가 51번째 장치가 되고 브로커 10초 중단에도 유실 0 / 1400(단계 10 + 2부). 마지막 문장 "한 장표에 숫자와 파일 이름을 같이"는 다음 장표 137 의 형식이다 — 상자마다 숫자(text)와 파일(ref).
- 차례 "한 장 요약(10 상자, 숫자 + 파일) · 닫는 장": 138(path 형식 10 상자) 과 139(닫는 장 — "코드와 숫자는 저장소에 있습니다").

## 3. 용어와 단위
- Hz(헤르츠): 1초에 몇 번. 명령 50 Hz = 20 ms 마다, 상태 100 Hz = 10 ms 마다, 루프 1 kHz = 1 ms 마다.
- DDS: ROS 2 밑의 통신 미들웨어. 표②는 DDS 구현체·QoS·크기별 왕복 지연과 손실.
- 우편함(SPSC 링 버퍼): 일반 스레드가 넣고 RT 스레드가 꺼내는 락 없는 원형 큐. 1부 단계 3.
- max 189 us: Pi 4 RT 커널 + CPU 3 격리, 부하 중 60초 동안 가장 늦게 깬 한 번. 1 ms 의 19%.
- 안전 검사: 제어 단계가 매 주기 하는 것 — 가장 최신 명령만 쓰기, 워치독(명령이 끊기면 멈춤), 변화량 제한(한 주기 0.05 rad 까지), 상태 머신(RUNNING 에서만 움직임).
- 어깨 1.1° 처짐: 목표 −0.200 rad 에 −0.180 rad 까지만 가는 중력에 의한 정상 상태 오차(0.02 rad ≈ 1.1°).
- 틈(gap): 기록된 메시지 간격이 설계 주기의 3배를 넘은 횟수. 0 이면 끊김 없이 기록됐다.
- 유실 0 / 1400: 브로커 10초 중단 창에서 50대가 만든 1,400개 중 DB 에 없는 것 0.

## 4. 쉬운 예시
여행 비유: 긴 여행의 마지막 날 밤, 지도를 펴고 출발지에서 도착지까지 손가락으로 한 번에 그어 본다. 가는 길에 들렀던 도시(단계)마다 사진 한 장(숫자)과 주소(파일)가 붙어 있다. 누가 "그 사진은 어디서 찍었고 왜 그 길로 갔나"를 물으면 그 자리에서 답할 수 있어야 한다는 것이 이 장표의 요구다.

숫자 예시: 명령 20 ms 간격(50 Hz) 사이에 1 ms 루프는 20번 깨고, 그중 19번은 빈 우편함을 보고 가장 최신 명령을 유지한다. 그 20번 중 가장 늦게 깬 한 번이 189 us 를 넘지 않았고(Pi 4, 60초 = 6만 번 중 최악), 물리 계산은 그 1 ms 중 8.5 us 를 썼다.

## 6. 자주 하는 오해·함정
- 이 장표의 한 문장은 **요약**이라 조건이 빠져 있다. "max 189 us" 는 Pi 4 RT + 격리·부하 중·60초 값이고 WSL 은 참고값, "유실 0" 은 틀린 0 → 53 → 고친 0 의 이력이 있는 0, "0.9%" 는 CI 러너 CPU 값이다. 물으면 조건을 붙여 답해야 한다.
- 열 개 화살표 중 "안전 검사"와 "MuJoCo" 는 같은 1 ms 주기 안에서 일어난다(단계 5·6) — 시간이 따로 걸리는 별 단계가 아니다.
- "어깨 1.1° 처짐"을 버그로 말하면 안 된다. 물리가 맞게 보여 준 중력이고, 실물에서도 같은 자리에 나며, 중력 보상은 지원 후 보류 항목이다.
- "기록(틈 0)" 과 "관제(유실 0)" 은 다른 길이다 — 기록은 로봇 안(rosbag2 → CSV), 관제는 로봇 밖(MQTT → DB). 둘 다 0 이지만 세는 방법이 다르다(틈 = 간격 > 3주기, 유실 = seq 빠짐).
- 마지막 장표라고 숫자 없이 감상으로 끝내지 않는다 — 138 은 상자마다 숫자와 파일이 붙은 요약이고, 139 는 "코드와 숫자는 저장소에 있습니다"로 닫는다.

## 7. 면접 한 문장
"결국 로봇은 이렇게 움직입니다 — 50 Hz 명령이 DDS 와 락 없는 우편함을 지나 1 ms 마다 깨는 RT 스레드(Pi 4 에서 최악 189 us)에서 안전 검사를 거쳐 물리로 들어가고, 어깨가 중력으로 1.1° 처진 상태가 100 Hz 로 올라와 틈 없이 기록되고 유실 없이 관제까지 갑니다 — 그리고 각 숫자의 출처와 코드 위치를 상자마다 적어 두었습니다."
