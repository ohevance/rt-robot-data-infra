# 장표 019 — 단계 3 — 노드가 받아 우편함에 넣는다 — on_command()
*위치: 1부 로봇을 움직이는 길 · 단계 3/10 우편함 · ② 코드 — on_command()*

## 1. 이 장표가 왜 있나
- 앞 장표(018)에서 우편함(SPSC 링)이 어떤 모양인지 그림으로 봤다. 이 장표는 **집배원 쪽 코드**, 즉 ROS 2 가 명령 메시지를 받았을 때 불리는 함수 `on_command()` 를 저장소 파일 그대로 보인다.
- 장표 상단의 `rt_control/ros2_adapter/src/rt_control_node.cpp:184-201` 이 이 코드의 정확한 위치다. 장표의 코드는 빌드 시점에 그 파일에서 자동으로 가져온 것이라 손으로 베낀 오타가 없다.
- 이 함수는 단계 3의 "확인 방법" 중 첫 번째였다: 길이 검사 → 고정 크기 구조체로 복사 → 링에 push. 그 세 동작이 18줄 안에 다 있다.

## 2. 장표를 하나씩 읽기
코드를 위에서 아래로 읽는다. 줄 번호는 파일 기준(184부터)이다.

- `void on_command(const sensor_msgs::msg::JointState::SharedPtr msg)` — ROS 2 가 `/joint_command` 토픽에서 `JointState` 메시지를 받을 때마다 이 함수를 부른다. `SharedPtr` 는 메시지를 가리키는 공유 포인터(자동으로 수명 관리되는 주소)다.
- `if (msg->position.size() != dof_)` — 메시지에 담긴 위치 값 개수가 노드가 아는 관절 수(`dof_`, SO-101 은 6)와 다르면 이 명령은 못 쓴다. `dof` 는 degrees of freedom(자유도) = 관절 수.
- `bad_commands_ = bad_commands_ + 1;` — 버린 명령 수를 센다. `++` 대신 `+ 1` 로 쓴 것은 이 저장소의 "읽기 쉬운 코드" 규칙이다.
- `if (bad_commands_ % 100 == 1)` … `RCLCPP_WARN(...)` — 1번째, 101번째, 201번째에만 경고를 찍는다. 잘못된 명령이 50 Hz 로 계속 오면 초당 50줄의 로그가 쏟아져 디스크와 화면을 메우기 때문이다. `%zu` 는 size_t, `%u` 는 unsigned 를 찍는 서식이다.
- `return;` — 잘못된 명령은 여기서 끝. 우편함에 넣지 않는다.
- `JointCommand cmd;` — 고정 크기 구조체. `position[kMaxJoints]` 배열(64칸)과 `dof`, `stamp_ns` 가 들어 있다. 크기가 고정이라 링 버퍼의 한 칸에 그대로 복사된다(동적 할당 없음).
- `cmd.stamp_ns = rt_core::now_ns();` — 받은 시각을 **단조 시계**(CLOCK_MONOTONIC)로 적는다. 벽시계(날짜·시각)는 NTP 동기화 등으로 뒤로 갈 수 있지만 단조 시계는 늘 앞으로만 간다. 워치독이 "얼마나 오래 명령이 없었나"를 셀 때 뒤로 가는 시계는 치명적이다.
- `cmd.dof = dof_;` 와 `for (...) cmd.position[j] = msg->position[j];` — 관절 수와 위치 6개를 복사한다. 메시지의 `position` 은 가변 길이 벡터이므로 고정 배열로 옮겨 담는다.
- `if (!g_cmd_ring.push(cmd))` — 우편함에 넣는다. `g_cmd_ring` 은 전역(파일 범위) SPSC 링 64칸이다. 전역에 둔 이유는 크기가 커서 스택에 두기 적당하지 않고, 노드와 RT 스레드 둘이 같은 것을 봐야 하기 때문이다.
- `cmd_ring_full_ = cmd_ring_full_ + 1;` — push 가 false 면 꽉 찬 것. 주석대로 "RT 스레드가 비우지 못하고 있다는 뜻 (정상이면 0)". 기다리지 않고 센다.
- `commands_received_ = commands_received_ + 1;` — 길이 검사를 통과한 명령 수. 꽉 차서 버렸어도 "받았다"로 세므로, `commands_received − commands_applied` 로 잃은 수를 가늠할 수 있다.
- **오른쪽 요점 다섯 줄**: 콜백 스레드에서 돈다(제어는 안 한다) · 길이 검사와 100번에 한 번 경고 · 고정 크기 복사와 push · 단조 시계 · 다음은 RT 스레드가 비운다(단계 5의 take_latest_command).

## 3. 용어와 단위
- **sensor_msgs/JointState**: ROS 2 표준 메시지. `name[]`, `position[]`(rad), `velocity[]`(rad/s), `effort[]` 필드가 있다. 여기서는 position 만 쓴다.
- **dof(자유도)**: 독립적으로 움직이는 관절 수. SO-101 은 6.
- **단조 시계(monotonic clock)**: 시스템이 켜진 뒤 흐른 시간. 뒤로 가지 않는다. `now_ns()` 는 이를 ns 단위 정수로 돌려준다.
- **ns**: 나노초, 10억분의 1초. `stamp_ns` 의 단위.
- **전역 변수 `g_`**: 이 저장소에서 전역 변수 이름에 붙이는 접두사.
- **RCLCPP_WARN**: ROS 2 C++ 로그 매크로(경고 수준).
- **rt_status**: 노드가 1 Hz 로 내는 자기 보고 JSON. `bad_commands`, `cmd_ring_full`, `commands_received` 가 여기 실린다.

## 4. 쉬운 예시
- **접수 창구 비유**: 창구 직원(on_command)은 신청서(메시지)를 받으면 (1) 칸이 6개 맞는지 본다 — 아니면 반려하고 "반려 1건" 표시, 100건마다 한 번만 상사에게 보고 (2) 규격 봉투(JointCommand)에 옮겨 적고 접수 시각 도장(stamp_ns)을 찍는다 (3) 뒤쪽 서류함(링)에 넣는다 — 꽉 차 있으면 "서류함 포화 1건"을 적고 신청서는 버린다. 직원은 서류를 처리하지 않는다. 처리는 뒷방(RT 스레드)의 일이다.
- **숫자 예시**: 시험용으로 `ros2 topic pub -r 50 /joint_command ...` 를 쓰면 1초에 50번 이 함수가 불린다. 10초면 `commands_received` 500 근처. 그중 길이가 5개인 메시지를 섞으면 `bad_commands` 가 올라가고 경고는 1, 101, 201 … 번째에만 찍힌다.

## 6. 자주 하는 오해·함정
- "콜백에서 바로 로봇에 쓰면 되지 않나" — 콜백 스레드는 일반 우선순위다. 다른 프로그램이 CPU 를 쓰면 밀린다. 그래서 이 함수는 넣기만 하고 끝낸다.
- "꽉 차면 기다렸다 넣으면 되지" — 기다리면 콜백 스레드가 멈추고, ROS 2 의 다른 콜백(rt_status 발행 등)도 같은 실행기에서 밀린다. 버리고 세는 쪽이 낫다. 어차피 평상시 우편함에는 1개밖에 없다(50 Hz 명령, 1 kHz 비우기).
- "stamp_ns 에 메시지 헤더의 시각을 쓰면 더 정확하지 않나" — 보내는 쪽 시계와 받는 쪽 시계가 다를 수 있다. 워치독은 "내가 마지막으로 받은 시각"만 필요하므로 받는 쪽 단조 시계가 맞다. 실제로 워치독은 이 값 대신 RT 스레드가 꺼낸 시각(`last_cmd_ns_`)을 쓴다(장표 030).
- `bad_commands_ % 100 == 1` 은 "100번에 한 번"이지 "100번째마다"가 아니다. 첫 번째 잘못된 명령에서 바로 경고가 나오게 하려고 `== 1` 로 두었다.

## 7. 면접 한 문장
"콜백은 길이 검사 → 고정 크기 복사 → 링 push 세 가지만 하고 끝납니다 — 제어는 한 줄도 없고, 버린 것은 bad_commands·cmd_ring_full 로 세어 rt_status 에 실으며, 시각은 뒤로 가지 않는 단조 시계로 찍습니다."
