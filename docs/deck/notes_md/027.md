# 장표 027 — 단계 5 들머리 — 제어 단계가 안전하게 만든다: 끊김·튐·불법 상태 전이를 막는다
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ① 들머리*

## 1. 이 장표가 왜 있나
- 단계 3·4를 거쳐 "1 ms 마다 정확히 깨는 RT 스레드"와 "우편함 속 최신 명령"이 준비됐다. 다음 질문은 "그 명령을 그대로 로봇에 쓰면 되나?"이고, 답은 **아니오**다. 이 장표는 그 이유(세 가지 위험)와 막는 방법(다섯 가지 일), 그리고 통과 기준을 한 장에 담은 단계 5의 들머리다.
- 세 위험은 **끊김**(명령이 안 오는데 마지막 목표로 계속 간다), **튐**(값이 갑자기 크게 바뀌어 로봇이 자기 몸이나 물건을 친다), **불법 상태 전이**(복구·정지의 순서가 뒤엉킨다)다. 각각에 대해 코드·카운터·테스트가 하나씩 있어야 통과다.
- 공고의 "안전 로직·상태 머신·워치독" 요구가 코드로 나타나는 자리가 이 단계다.

## 2. 장표를 하나씩 읽기
- **들어온 것(회색)** — "1 ms 마다 정확히 깨는 RT 스레드 + 우편함의 최신 명령 (단계 3·4)".
- **문제** — "명령을 그대로 로봇에 쓰면 위험하다: 명령이 끊기면 마지막 목표로 계속 가고, 값이 튀면 로봇을 치고, 상태 전이가 뒤엉킨다". 세 위험을 한 문장에 나열했다. 순서대로 워치독·변화량 제한·상태 머신이 대응한다.
- **◇ 기준(마름모)** — "50 ms 끊기면 멈춤(현재 위치 유지), 한 주기 변화량 ≤ 0.05 rad, 전이표 밖 전이 0, 함수 안 할당·락·파일 0인가?". 네 조건이다. 앞의 셋이 세 위험에 대한 것, 마지막 하나는 "이 모든 것이 RT 스레드 안에서 돌아도 되는 코드인가"(메모리 할당·락·파일 입출력은 기다림을 만들므로 금지)다.
- **확인 방법(파란색)** — "ControlStep::step 다섯 가지(최신 명령 · 워치독 · 변화량 제한 · 백엔드 쓰기/읽기 · 벨트) · test_control_step.cpp · test_state_machine.cpp · 11/03 노드에서 명령 끊기". 코드는 step() 한 함수가 다섯 단계를 순서대로 부른다(029). 테스트 둘은 ROS 2 없이 step() 과 상태 머신을 직접 부른다. 11/03 에는 실제 노드를 띄워 명령 발행을 끊어 보았다.
- **결과(흰색)** — "명령을 끊자 watchdog_trips 1, RUNNING → FAULT → (재개) RECOVERING → READY. 목표가 튈 때 step_limited 10. illegal_events 0". 세 위험이 각각 숫자로 보인다: 끊김 → trips 1 과 상태 전이, 튐 → step_limited 10, 불법 전이 → illegal_events 0.
- **판단 → 다음** — "통과 → 단계 6: 안전해진 목표(applied_)를 로봇에 쓴다 — 로봇이 셋인데 제어 코드는 그대로 둘 수 있나?". `applied_` 는 변화량 제한을 거친 "실제로 로봇에 보내는 값"이다. 로봇이 셋(SimLag·MuJoCo·실물)이라는 것이 단계 6의 질문이다.
- **아래 줄** — 이 단계의 장표: 코드 4장(step 029, 최신 명령 030, 워치독 031, 변화량 제한 032) + 상태 머신 그림(033) + 상태 머신 코드 2장(034·035) + rt_status 카운터(036). 넘어가는 조건: "세 가지 위험(끊김·튐·불법 전이)마다 코드와 카운터와 테스트가 있다".

## 3. 용어와 단위
- **워치독(watchdog)**: "일정 시간 안에 신호가 안 오면 안전한 행동"을 하는 감시 장치. 여기서는 50 ms 동안 명령이 없으면 목표를 현재 위치로 바꿔 멈춘다.
- **변화량 제한(step limit)**: 한 주기(1 ms)에 목표가 바뀔 수 있는 최대량. 0.05 rad ≈ 2.9°. 1초면 최대 50 rad/s 가 되므로 실물에서는 더 줄인다.
- **상태 머신(state machine)**: 로봇이 지금 어떤 상태(INIT/READY/RUNNING/FAULT/RECOVERING)인지와, 어떤 사건이 오면 어디로 가는지를 표로 정한 것.
- **불법 전이(illegal event)**: 전이표에 없는 (상태, 사건) 조합. 상태를 바꾸지 않고 `illegal_events` 를 센다. 0 이어야 정상.
- **ms / rad**: 1 ms = 1,000분의 1초. 1 rad = 57.3°.
- **desired_ / applied_ / position_**: 상위가 원하는 목표 / 변화량 제한을 거쳐 실제로 보내는 목표 / 로봇에서 읽은 현재 위치.
- **카운터**: `watchdog_trips`(정상→멈춤 전환 횟수), `step_limited`(제한이 걸린 주기 수), `illegal_events`. 전부 rt_status 에 실린다.
- **할당·락·파일 0**: RT 함수 안에서 `new`/`malloc`, mutex, 파일 입출력을 쓰지 않는다는 규칙. 셋 다 얼마나 걸릴지 모르는(기다릴 수 있는) 동작이다.

## 4. 쉬운 예시
- **자동차 크루즈 컨트롤 비유**: 운전자가 "시속 80" 을 누른다(명령). (끊김) 운전자가 손을 떼고 아무 신호가 없으면 차는 마지막 설정으로 계속 달리면 위험하므로, 일정 시간 신호가 없으면 현재 속도 유지 또는 감속으로 바꾼다(워치독). (튐) 운전자가 실수로 "시속 800" 을 입력해도 차는 1초에 몇 km 씩만 올린다(변화량 제한). (불법 전이) 고장 상태에서 바로 "정상 주행"으로 돌아가지 못하고, 점검 상태를 거쳐야 한다(상태 머신의 FAULT → RECOVERING → READY).
- **숫자 예시**: 11/03 시험에서 그리퍼 목표를 0 에서 0.5 rad 로 한 번에 바꿨다. 한 주기에 0.05 rad 씩이므로 10주기(10 ms) 동안 제한이 걸렸고 `step_limited` 가 10 이 되었다. 명령 발행을 멈추자 `watchdog_trips` 가 1 올라갔다(노드 시험). 상태가 RUNNING → FAULT 로 가고, 다시 명령이 오면 RECOVERING 을 거쳐 100 주기(100 ms) 뒤 READY 로 돌아오는 것은 단위 테스트가 같은 코드로 확인한다.

## 5. 숫자의 출처와 다시 확인하는 법
- 확인: 50 ms, 0.05 rad, 복구 100주기 — `rt_control/rt_core/include/rt_core/control_step.hpp:30-32` (`watchdog_ns = 50000000`, `max_step_rad = 0.05`, `recover_cycles = 100`); `robots/so101.yaml` safety 절(`watchdog_ms: 50`, `max_step_rad: 0.05`).
- 확인: step() 다섯 가지 — `rt_control/rt_core/src/control_step.cpp:28-56` (장표 029).
- 확인: 테스트 — `rt_control/rt_core/test/test_control_step.cpp` 머리말 "1) 명령을 주면 움직인다 2) 변화량 제한 3) 워치독 4) 벨트"; `test_state_machine.cpp` 에 INIT→READY→RUNNING→FAULT→RECOVERING→READY 순서와 불법 사건 2개 검사.
- 확인: 11/03 노드 시험 결과 — `docs/LOG.md` 2026-11-03 "워치독 tripped → ok → tripped, trips 1, step_limited 10(0.5 rad 를 0.05 씩 10주기)"; `docs/experiments/E03.md`.
- 추정: 결과 상자의 "RUNNING → FAULT → (재개) RECOVERING → READY" 경로는 노드 로그에는 상태 이름이 남아 있지 않고, 단위 테스트 `test_control_step.cpp:90-113` (FAULT → RECOVERING → 100주기 뒤 READY → RUNNING, illegal 0)과 `test_state_machine.cpp` 로 확인된 것이다. 노드에서 직접 보려면 명령 발행을 끊고 켠 뒤 `/rt_status` 의 `state` 를 1초 간격으로 본다.
- 확인: 카운터가 rt_status 에 실린다 — `rt_control_node.cpp` publish_status(233-291) 의 `watchdog_trips`, `step_limited`, `illegal_events`.
- 확인: 결정 기록 — `docs/DECISIONS.md` 2026-11-03 (D1) "워치독은 멈춤 = 현재 위치 유지", (D3) "상태 머신은 전이 표 하나로".

## 6. 자주 하는 오해·함정
- "워치독이 걸리면 로봇이 0 위치로 돌아간다 / 급정지한다" — 둘 다 아니다. **지금 있는 자리에 머문다**(목표 = 현재 위치). 급정지는 관성으로 물건을 떨어뜨릴 수 있고, 0 위치 복귀는 움직임 자체가 위험하다(DECISIONS D1).
- "변화량 제한이 있으니 워치독은 필요 없다" — 다른 위험이다. 변화량 제한은 "얼마나 빨리"를, 워치독은 "명령이 살아 있나"를 본다.
- "상태 머신은 보여 주기용이다" — FAULT 에서 바로 RUNNING 으로 못 가게 막는 것은 실제 안전 동작이다. 명령이 잠깐 돌아왔다 다시 끊기는 것을 100주기 동안 확인하는 것이 RECOVERING 이다.
- 이 들머리의 숫자(trips 1, step_limited 10)는 WSL2 에서 11/03 에 한 번 본 값이다. 재현하려면 노드를 띄우고 `ros2 topic pub` 을 켜고 끄며 `/rt_status` 를 본다.

## 7. 면접 한 문장
"명령을 그대로 쓰지 않고 세 위험마다 장치를 하나씩 두었습니다 — 50 ms 끊기면 현재 위치에 멈추는 워치독, 한 주기 0.05 rad 변화량 제한, 전이표 밖 전이를 세는 상태 머신 — 그리고 각각 카운터와 단위 테스트가 있고, 11/03 노드 시험에서 trips 1 · step_limited 10 · illegal 0 으로 확인했습니다."
