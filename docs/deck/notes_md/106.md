# 장표 106 — 환경 지도 — 네 곳과 그 사이의 길
*위치: 5부 어디서 · 한 장 그림*

## 1. 이 장표가 왜 있나
앞 장표(105)는 5부의 문을 여는 장 구분 장표였다. 4부까지 "공고가 요구한 것을 다 덮었나"에 숫자로 답했으니, 다음 질문은 "그 숫자는 어디서, 어떤 조건에서 나왔나"다. 같은 코드라도 WSL2 에서 돌린 값과 Raspberry Pi 4 의 실시간 커널에서 돌린 값은 뜻이 다르고, GitHub 러너에서 돈 것은 "돌아간다"의 증거일 뿐 지연 수치의 증거가 아니다.

이 장표는 그 답의 지도다. 컴퓨터 네 곳(① 개발 PC, ② Raspberry Pi 4, ③ GitHub, ④ 작성 보조 작업본)에 무엇이 있고, 코드와 숫자가 어느 길로 오가는지를 한 장 그림으로 보여 준다. 뒤에 오는 장표 107~110 은 이 그림의 각 부분을 표로 자세히 푼다. 발표에서는 "이 저장소의 숫자를 말할 때는 항상 이 네 곳 중 어디서 잰 값인지 같이 말한다"는 규칙을 이 그림으로 설명한다.

## 2. 장표를 하나씩 읽기
그림은 Mermaid 로 그린 `diagrams/env_map.mmd` 를 PNG 로 만든 것이다. 큰 상자 네 개가 네 곳이고, 그 안의 작은 상자가 거기서 도는 것, 상자 사이 화살표가 코드와 숫자의 길이다. 왼쪽 위 ① 부터 읽는다.

- 큰 상자 ① "개발 PC — Windows 11 + WSL2 Ubuntu 24.04 (코드를 실제로 돌리는 곳)": 작성자의 노트북. 안에 작은 상자 다섯 개가 있다.
  - "WSL 터미널 — .bashrc 가 venv·ROS 2·RT_REPO_ROOT 자동 설정": 모든 명령을 치는 자리. 터미널을 새로 열면 `.bashrc` 가 파이썬 가상 환경(venv), ROS 2 환경, 저장소 경로 변수 `RT_REPO_ROOT` 를 자동으로 잡는다.
  - "ROS 2 Jazzy 노드 rt_control_node — 1 kHz RT 루프 + MuJoCo 백엔드": 1부에서 본 로봇 제어 노드. 1 ms 루프와 물리 엔진이 여기서 돈다.
  - "Docker 컨테이너 3개 — fleet_mqtt :1883 · fleet_db(TimescaleDB) :5432 · fleet_grafana :3000": 2부의 관제 쪽. MQTT 브로커, 시계열 DB, 대시보드가 각각 컨테이너 하나씩이고 숫자는 포트 번호다.
  - "파이썬 프로세스 — 수집기 · 가상 장치 50대 · 장애 주입 · OTA 배포기 · 진단": 2부의 나머지. 전부 파이썬 스크립트로 WSL 안에서 돈다.
  - "기록 파이프라인 — rosbag2 MCAP → CSV → summary.md": 1부 단계 9. ROS 2 토픽을 MCAP 파일로 녹음하고 CSV 와 요약 문서로 바꾼다.
  - ① 안의 화살표: WSL → ROS 노드, WSL → 파이썬 → Docker(파이썬 프로세스가 컨테이너의 브로커·DB 에 붙는다), ROS 노드 → 기록 파이프라인, 그리고 ROS 노드에서 Docker 로 가는 점선 "텔레메트리 1 Hz (ros_bridge)" — 로봇 노드의 상태가 1초에 한 번 관제 브로커로 올라가는 다리다.
- 큰 상자 ② "Raspberry Pi 4B 4 GB — Ubuntu 24.04 + PREEMPT_RT (표①의 진짜 숫자만 재는 곳)": 작은 상자 둘. "커널 6.8.0-2054-raspi-realtime — /sys/kernel/realtime = 1, isolcpus=3" 은 실시간 커널이 켜져 있고 CPU 3 이 격리된 상태라는 뜻이고, "같은 저장소 clone → rt_core 빌드 — jitter_run.sh · cyclictest_run.sh" 는 Pi 가 GitHub 에서 같은 코드를 받아 측정기만 빌드해 돌린다는 뜻이다. ROS 2·Docker·MuJoCo 는 깔지 않는다.
- 큰 상자 ③ "GitHub — ohevance/rt-robot-data-infra (진실의 원천 + 자동 검사원)": "저장소 main — 코드 · 문서 · docs/measurements 원본" → "Actions 러너 ubuntu-24.04 (GitHub 의 VM) — 잡 3개: rt_core → fleet_integration · mujoco" → "README 배지 ✓/✗ — 아티팩트(jitter-ci · fleet-integration · mujoco-ci)". 화살표 글 "push 마다"가 핵심이다. push 할 때마다 GitHub 가 새 가상 머신을 켜서 잡 3개를 돌리고 결과를 배지 색과 아티팩트(결과 파일)로 남긴다.
- 큰 상자 ④ "작성 보조 작업본 — Claude 의 리눅스 샌드박스 (코드·문서 초안을 쓰는 곳)": "gcc · cmake · python 만 있음 — ROS 2·Docker·MuJoCo 없음 → 가짜 브로커·DB·스텁으로 논리만 검증" → "git bundle (patch-NN.bundle)". AI 가 코드와 문서 초안을 쓰고 컴파일·단위 테스트까지 해 본 뒤 패치 묶음 파일로 넘기는 곳이다. 진짜 ROS 2 나 Docker 가 없으므로 여기서 통과한 것은 "논리가 맞다"까지다.
- 네 곳 사이의 화살표(실선 = 코드와 숫자가 실제로 흐르는 길):
  - ④ bundle → ① WSL "Downloads 폴더로 전달": 패치 파일이 작성자의 Downloads 폴더에 놓이고, WSL 에서 `git pull` 로 받는다.
  - ① WSL → ③ 저장소 "git pull --no-rebase (bundle) → git push": 받은 패치를 사람이 확인하고 push 한다. push 는 항상 사람이 한다.
  - ③ 저장소 → ④ 샌드박스 "git fetch (읽기 전용)": 작업본은 패치를 만들기 전에 GitHub 의 main 을 읽기 전용으로 받아 기준을 맞춘다. 쓰기 권한은 없다.
  - ③ 저장소 → ② Pi "git clone / pull (HTTPS, 로그인 없음)": Pi 도 GitHub 에서 코드를 받는다. 공개 저장소라 로그인이 없고, 그래서 Pi 에는 자격 증명이 없다.
  - ② Pi → ① WSL "scp *pi4* → docs/measurements → commit·push": Pi 에서 잰 결과 파일을 scp 로 WSL 에 복사하고, 커밋과 push 는 WSL 에서 한다.
  - 점선 ROS → 기록 "WSL 수치는 참고값 (가상 커널)": WSL 에서 나온 지연 숫자는 가상 커널 위의 값이라 참고값으로만 쓴다는 주의 표시다.
- 아래 설명 글 "실선 = 코드와 숫자가 실제로 흐르는 길, 점선 = 참고 관계. GitHub 가 가운데: 네 곳 모두 main 을 기준으로 맞춘다. 11/05 의 그림 — 11/10 에 더한 다섯째 곳(클라우드 서버)은 다음 장표의 비고와 장표 140. 출처: docs/ENVIRONMENT.md §0": 그림 읽는 법이다. GitHub 를 가운데 둔 이유는 Pi 도, 작업본도, PC 도 전부 GitHub 의 `main` 에서 코드를 받기 때문이다. 둘째 문장은 이 그림의 날짜다 — 11/10 에 운영 층을 클라우드 서버(AWS, 시드니)에 올려 곳이 다섯이 됐고, Pi 는 그날부터 에이전트 서비스로 그 서버에 보고한다. 그림을 그대로 둔 이유는 표①②③ 의 숫자가 전부 그 전에, 이 네 곳에서 잰 값이기 때문이다. 다섯째 곳은 장표 107 의 비고와 덧붙임 장표 140 이 다룬다.

## 3. 용어와 단위
- WSL2(Windows Subsystem for Linux 2): 윈도우 안에서 리눅스를 가상 머신으로 돌리는 기능. 리눅스 커널이 가상이라 실시간 지연 수치는 믿을 수 없다.
- venv: 파이썬 가상 환경. 프로젝트 전용 패키지 묶음.
- ROS 2 Jazzy: 로봇 소프트웨어 프레임워크 ROS 2 의 2024년 배포판 이름.
- Docker 컨테이너: 프로그램과 그 의존성을 하나로 묶어 격리해 돌리는 단위. `:1883` 같은 숫자는 포트(프로그램이 네트워크에서 듣는 문 번호)다.
- MQTT 브로커 / TimescaleDB / Grafana: 장치 메시지를 중계하는 서버 / 시계열 데이터용 PostgreSQL 확장 DB / 대시보드 화면.
- rosbag2 MCAP: ROS 2 의 녹음 도구와 그 파일 형식.
- PREEMPT_RT: 리눅스 커널을 실시간용으로 바꾸는 패치. `/sys/kernel/realtime` 이 1 이면 켜진 것.
- isolcpus=3: CPU 3 을 일반 작업에서 떼어 두는 커널 부팅 인자.
- GitHub Actions 러너: push 마다 GitHub 가 새로 켜서 CI 를 돌리는 리눅스 가상 머신(ubuntu-24.04).
- 아티팩트(artifact): CI 잡이 끝나며 남기는 결과 파일(표·JSON). Actions 화면에서 내려받을 수 있다.
- git bundle: 커밋 묶음을 파일 하나로 만든 것. 네트워크 없이 USB 나 다운로드 폴더로 옮겨 `git pull` 할 수 있다.
- scp: SSH 위에서 파일을 복사하는 명령.
- Hz: 1초에 몇 번. 1 Hz = 1초에 한 번, 1 kHz = 1초에 1,000번.

## 4. 쉬운 예시
- 비유: ① 은 작업장(조립과 시운전을 하는 곳), ② 는 계측실(진동 없는 방에서 한 가지만 정밀하게 재는 곳), ③ 은 도면 보관소 겸 검사원(원본을 보관하고 들어오는 도면마다 다시 조립해 보는 곳), ④ 는 설계 사무실(도면 초안을 그리는 곳)이다. 설계 사무실의 도면(bundle)은 작업장에서 먼저 조립해 보고(WSL 실행), 보관소에 올리면 검사원이 매번 다시 조립해 본다(CI). 계측실은 지연 한 가지만 재서 결과지를 작업장으로 보낸다(scp).
- 숫자 예시: 같은 `jitter_bench` 를 세 곳에서 돌리면 WSL2 는 max 약 900~2,000 us(참고값), GitHub 러너는 "2초 동안 드롭 0"(돌아간다의 증거), Pi 4 실시간 커널 + 격리는 max 189 us(진짜 값)다. 세 숫자를 섞어 비교하면 안 되는 이유가 이 그림이다.

## 5. 숫자의 출처와 다시 확인하는 법
- 확인: 그림의 글자 전부 — 장표의 PNG 원본인 `docs/deck/build/diagrams/env_map.mmd`(11/05 의 그림). `docs/ENVIRONMENT.md` §0 의 Mermaid 블록은 11/11 에 다섯 곳으로 늘었다 — ①·④ 상자와 그 사이 길 다섯은 그대로이고, ② 에 서비스 상자(`rt-pi-agent`), ③ 에 `release.yml` 상자, 그리고 ⑤ 클라우드 서버와 길 넷이 더해졌다.
- 확인: 포트 1883 / 5432 / 3000 — `fleet/docker-compose.yml`.
- 확인: 커널 이름 6.8.0-2054-raspi-realtime, `/sys/kernel/realtime` = 1 — `docs/LOG.md` 11/04, `docs/SETUP_RT_MEASURE.md`.
- 확인: 잡 3개 이름과 아티팩트 이름 — `.github/workflows/ci.yml`.
- 확인: 가상 장치 50대, 텔레메트리 1 Hz — `fleet/agent/virtual_fleet.py` 기본 사용법(`--count 50 --rate 1`), `docs/ENVIRONMENT.md` §3.
- 다시 확인하는 법: WSL 창에서 `docker ps` 로 컨테이너 3개, `echo $RT_REPO_ROOT` 로 저장소 경로를 본다. Pi 창에서 `uname -r; cat /sys/kernel/realtime; cat /sys/devices/system/cpu/isolated`. GitHub 는 `gh run list -L 3`.

## 6. 자주 하는 오해·함정
- "한 대로 다 하면 되지 않나": WSL 은 실시간 수치를 못 재고, Pi 는 ROS 2·Docker 를 돌리기엔 작고, 러너는 실시간 커널이 없다. 각 곳이 "못 하는 것"이 다음 곳을 만들었다(장표 107).
- "GitHub 에 올라간 숫자는 GitHub 가 잰 것": 아니다. `docs/measurements/*pi4*` 는 Pi 에서 재서 WSL 을 거쳐 커밋한 파일이다. 러너가 직접 재는 것은 `table1_ci.md` 같은 `*_ci` 파일뿐이다.
- "Pi 도 push 한다": Pi 에는 GitHub 로그인이 없다. 측정만 하고 결과는 scp 로 WSL 에 보낸다. 커밋 주체는 ① 하나다(이력이 한 줄로 남고 자격 증명이 한 곳에만 있다).
- 함정(실제로 겪은 것): 11/04 에 WSL 용 명령을 Pi 창에 쳐서 복사·커밋이 실패했다. 그래서 이 저장소의 모든 안내는 명령 앞에 [Pi 창] / [WSL 창] 을 붙인다(11/10 부터는 [EC2 안] 도).
- "지금도 네 곳이다": 11/10 부터 다섯 곳이다. 이 그림은 11/05 의 것이고 본편의 숫자(표①②③)를 잰 환경을 보여 준다. 서버 왕복이 들어간 숫자(왕복 290 ms, 연속 보고 유실 0)는 다섯째 곳에서 나온 것이라 "서버: 시드니"를 붙여 따로 말한다(장표 140·142).

## 7. 면접 한 문장
"컴퓨터 네 곳을 역할로 나눴다 — 코드를 실제로 돌리는 WSL, 실시간 지연만 재는 Pi 4, 원본을 보관하고 push 마다 다시 검사하는 GitHub, 초안을 쓰는 작업본 — 그래서 숫자를 말할 때는 항상 어디서 잰 값인지를 같이 말한다."
