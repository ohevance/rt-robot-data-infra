# 장표 030 — 단계 5 — ① 최신 명령만 — 우편함을 전부 비우고 마지막 것만 쓴다 (take_latest_command)
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ② 코드 — 최신 명령만*

## 1. 이 장표가 왜 있나
- step()(029)의 다섯 가지 중 **첫 번째**다. 단계 3에서 콜백이 우편함(SPSC 링 64칸)에 넣어 둔 명령을 RT 스레드가 꺼내는 쪽이 이 함수다. 장표 020의 `pop()` 을 실제로 부르는 유일한 자리다.
- 핵심 설계가 하나 있다: 우편함에 명령이 여러 개 쌓여 있으면 **순서대로 하나씩 처리하지 않고 전부 비운 뒤 마지막 것만 쓴다**. 이것이 왜 맞는지(목표 위치 명령은 궤적이 아니다)가 이 장표의 요점이다. DECISIONS 에 "버린 대안: 큐를 FIFO 로 하나씩 소비" 로 기록된 결정이다.
- 위치 `rt_control/rt_core/src/control_step.cpp:61-79`.

## 2. 장표를 하나씩 읽기
- `void ControlStep::take_latest_command(std::int64_t now_ns)` — 인자는 step() 이 잰 "지금 시각". 명령을 받은 시각으로 기록한다.
- `JointCommand cmd; bool got_any = false;` — 꺼낸 명령을 담을 자리와 "하나라도 꺼냈나" 표시.
- `while (cmd_ring_.pop(cmd)) { got_any = true; }` — 핵심. `pop` 이 true 를 돌려주는 동안(= 링에 명령이 남아 있는 동안) 계속 꺼낸다. 매번 같은 `cmd` 에 덮어쓰므로 루프가 끝나면 **마지막에 꺼낸 것**만 남는다. 앞의 것들은 그냥 버려진다.
- `if (!got_any) return;` — 이번 주기에 새 명령이 없으면 아무것도 바꾸지 않고 돌아간다. `desired_` 는 지난 주기 값 그대로다. 50 Hz 명령이면 20주기 중 19주기가 이 경우다.
- `if (cmd.dof != cfg_.dof) return;` — 관절 수가 다르면 무시. 콜백(019)에서 이미 걸렀지만 "RT 쪽은 바깥을 믿지 않는다"는 태도로 한 번 더 본다. 주석: "상위에서 걸러지지만 한 번 더".
- `for (...) desired_[j] = cmd.position[j];` — 관절 6개의 목표를 `desired_` 에 복사. 이것이 "상위가 원하는 목표"다. 아직 로봇에 보내는 값은 아니다(변화량 제한 전).
- `last_cmd_ns_ = now_ns;  last_cmd_seq_ = cmd.seq;` — **마지막으로 명령을 받은 시각**과 그 명령의 번호. 번호(11/11 에 더함)는 상태 샘플에 `cmd_seq` 로 실려 나가 ZeroMQ 클라이언트가 "내 명령이 RT 루프에 반영됐다"를 확인하는 데 쓴다(장표 143) — 줄 번호가 흔들리지 않게 같은 줄에 넣었다. 바로 다음에 불리는 워치독(031)이 이 값과 지금 시각의 차이로 끊김을 판정한다.
- `got_command_this_cycle_ = true;` — 상태 머신에 COMMAND 사건을 넣으라는 표시(워치독 함수 끝의 `update_state_machine` 이 본다).
- `counters_.commands_applied.fetch_add(1, relaxed);` — 실제로 적용한 명령 수. 50 Hz 로 보내면 rt_status 에서 초당 50 씩 늘어난다. 콜백의 `commands_received` 와 비교하면 "받았지만 적용 못 한 수"(꽉 차서 버린 수와 같아야 한다)를 알 수 있다.
- **오른쪽 요점**: while 로 전부 비우고 마지막만 · got_any false 면 유지 · dof 재검사 · last_cmd_ns_ 는 워치독용 · commands_applied 카운터.

## 3. 용어와 단위
- **목표 위치 명령(position setpoint)**: "관절을 이 각도로". 지금 어디로 가야 하는지만 말한다. 지난 명령이 뭐였는지는 의미가 없다.
- **궤적(trajectory) 명령**: "0 ms 에 0.1, 20 ms 에 0.2, 40 ms 에 0.3 …" 처럼 시간순 점 목록. 이것은 순서대로 모두 따라가야 하므로 FIFO 가 맞다. 이 저장소의 명령은 궤적이 아니다.
- **FIFO**: First In First Out, 먼저 들어온 것을 먼저 처리. 여기서는 버린 대안.
- **pop**: 링에서 하나 꺼내기. 비어 있으면 false (장표 020).
- **desired_**: 원하는 목표(rad). **applied_**(실제 보내는 값)와 다르다.
- **last_cmd_ns_**: 마지막 명령 시각, 단조 시계 ns. 0 이면 "아직 한 번도 못 받음".
- **commands_applied**: RT 가 적용한 명령 수. `commands_received`(콜백이 받은 수)와 짝.

## 4. 쉬운 예시
- **내비게이션 비유**: 운전 중 동승자가 "다음에 좌회전", 잠시 뒤 "아니 직진", 또 "우회전" 이라고 연달아 말했다면, 운전자는 마지막 "우회전"만 들으면 된다. 앞의 두 말을 순서대로 실행하면(좌회전 → 직진 → 우회전) 오히려 틀린 길로 간다. 목표 위치 명령은 이런 "지금 어디로" 식의 말이라 최신 것만 맞다.
- **반례(궤적)**: 반면 "100 m 직진, 그다음 좌회전, 그다음 200 m" 같은 경로 안내는 순서대로 다 따라야 한다. 이런 명령 형식을 쓰게 되면 이 함수는 바뀌어야 한다 — 그래서 DECISIONS 에 "궤적 명령이라면 FIFO 가 맞다"고 조건을 적어 두었다.
- **숫자 예시**: RT 스레드가 어떤 이유로 100 ms 멈췄다가 깼다면 우편함에 50 Hz × 0.1 s = 5개가 쌓여 있다. 이 함수는 5개를 한 주기에 전부 꺼내 마지막 것만 쓴다. FIFO 였다면 5주기(5 ms)에 걸쳐 이미 지난 목표를 차례로 따라갔을 것이다.

## 6. 자주 하는 오해·함정
- "명령을 버리면 데이터 손실 아닌가" — 목표 위치 명령에서 옛 목표는 이미 의미가 없다. 버리는 것이 맞고, 버린 수는 `commands_received − commands_applied` 로 알 수 있다.
- "while 로 다 비우면 RT 시간이 길어지지 않나" — 한 번 pop 은 원자 변수 둘 읽기와 구조체 복사(수백 바이트)뿐이다. 링은 최대 63개이므로 최악의 경우에도 상한이 있다(bounded). 평상시에는 0~1회다.
- "콜백에서 dof 를 걸렀으니 여기 검사는 낭비다" — RT 쪽은 바깥을 믿지 않는 것이 원칙이다. 잘못된 길이의 배열을 복사하면 배열 경계를 넘을 수 있다. 정수 비교 하나의 비용으로 그 위험을 막는다.
- `last_cmd_ns_` 에 콜백이 찍은 `cmd.stamp_ns` 를 쓰지 않고 RT 스레드의 `now_ns` 를 쓰는 이유: 워치독 판정은 "RT 스레드가 명령을 손에 넣은 시각" 기준이 일관되기 때문이다(우편함에 머문 시간은 최대 1 ms 라 차이가 거의 없다).

## 7. 면접 한 문장
"목표 위치 명령은 궤적이 아니라 '지금 어디로'이므로 우편함을 while 로 전부 비우고 마지막 것만 적용합니다 — 밀렸다 풀린 옛 목표를 순서대로 따라갈 이유가 없고, 적용한 수는 commands_applied 로 세어 받은 수와 맞춰 봅니다."
