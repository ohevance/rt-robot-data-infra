# 장표 129 — 사고와 해결 (2/2)
*위치: 7부 왜·사고·방식 · 사고 2/2*

## 1. 이 장표가 왜 있나

앞 장표(128)의 6건에 이어 나머지 5건이다. 앞 장이 관제·CI 1차·ROS 2 쪽이었다면 이 장은 노드 시작, Pi 작업, 실시간 커널 토큰, CI 2차, 기록 파이프라인 — 즉 **11/03 노드 작업부터 11/05 마지막 실행까지** 시간 순으로 더 넓게 퍼진 사고들이다. 아래 비고의 "배운 규칙 둘"은 11건 전체에서 가장 비싼 교훈이고, 6부 CI 장표(119~122)와 7부 작성 방식(131)에서 이미 몇 번 나온 문장이 여기서 출처를 얻는다. 다음 장표(130)는 이 결정과 사고들이 2주 중 언제 일어났는지를 한 줄로 늘어놓는다.

## 2. 장표를 하나씩 읽기

네 칸: 무엇 / 원인 / 해결 / 기록(LOG 날짜).

- 1행 "노드가 파라미터 파일로 시작 안 됨 / 빈 배열 mujoco_joints: [] 의 타입 미정 / 빈 배열이면 키를 뺀다(profile_to_params) / 11/03": ROS 2 노드는 YAML 파라미터 파일로 설정을 받는다. 로봇 프로필(`robots/*.yaml`)에서 파라미터 파일을 만드는 `scripts/profile_to_params.py` 가 MuJoCo 관절 이름 목록이 비어 있을 때 `mujoco_joints: []` 를 그대로 썼는데, ROS 2 파라미터 파서는 **빈 배열의 원소 타입을 정할 수 없어**(문자열 배열인지 정수 배열인지) 노드 시작을 거부한다. 해결: 목록이 비면 키 자체를 쓰지 않는다(`profile_to_params.py` 41~44행, 주석에 이유가 적혀 있다). 노드 쪽은 키가 없으면 "모델 순서로 연결"이라는 기본 동작을 쓴다.
- 2행 "Pi 결과 파일 복사·커밋 실패 / WSL 명령을 Pi 창에 침, sudo 가 만든 root 소유 파일 / 안내에 [Pi 창]/[WSL 창] 표시, chown -R / 11/04": 11/04 밤 Pi 에서 측정한 결과를 WSL 로 옮겨 커밋하려는데, WSL 에서 칠 `scp`·`git` 명령을 **Pi 창**에 쳤다. Pi 가 자기 자신에게 복사하려다 root 소유 파일(측정을 `sudo` 로 돌려 결과가 root 소유)에 "Permission denied", git 은 "Author identity unknown". 해결은 둘 — 작업 안내문의 모든 명령 앞에 **[Pi 창] / [WSL 창]** 을 붙이는 규칙, 그리고 Pi 에서 `git reset` + `chown -R <사용자>` 로 소유를 돌린 뒤 WSL 창에서 다시. 이 사고가 "Pi 는 측정만, 커밋은 WSL 에서"라는 결정(장표 127 5행)의 배경이다.
- 3행 "Ubuntu One 가입 실패(실시간 커널 토큰) / Launchpad 사용자명 검사 time out(Canonical 쪽) / 기다렸다 재시도(다음 날 아침 성공) / 11/04": Pi 의 PREEMPT_RT 커널은 Ubuntu Pro 의 무료 개인 토큰이 필요하고, 그러려면 Ubuntu One 계정이 필요한데 가입이 두 번 실패했다. 오류문은 "Dry run of setting username(...) in Launchpad failed with (The read operation timed out)" — 가입 때 Launchpad 에 사용자명을 검사하는 호출이 시간 초과, 즉 Canonical 서버 쪽 문제이고 입력값(한글 이름 등)과 무관했다. 플랜 B(WSL 에서 Pi 커널을 PREEMPT_RT 로 크로스 컴파일, 2~3시간)를 준비했지만 다음 날 아침 재시도에 바로 가입되어 토큰을 받았다. 교훈: 오류문을 끝까지 읽으면 "내 탓인지 저쪽 탓인지"가 적혀 있다. 토큰 값 자체는 어디에도 적지 않는다.
- 4행 "CI fleet_integration 빨강(2차, NameError: request_stop) / 잠금 공용화 패치에서 시그널 핸들러 함수가 통째로 삭제. 단위 테스트가 main() 을 안 탐 / 함수 복원 + main() 한 바퀴 스모크 테스트 / 11/05": 11/04 의 패치(단일 인스턴스 잠금을 `fleet/common/single_instance.py` 로 옮긴 patch-08, 커밋 861e628)가 수집기의 종료 신호 처리 함수 `request_stop` 을 통째로 지웠다. 수집기 `main()` 이 시작 직후 `NameError` 로 죽어 장치 0대, 유실 집계 불가. 단위 테스트는 Collector 클래스만 쓰고 `main()` 을 안 타서 초록이었고, WSL 에서도 그 뒤 수집기를 다시 띄운 적이 없어 통합 테스트(CI)만 빨갰다. 그 사이 push 가 측정 파일·문서 위주라 CI 를 안 봤다. 해결: 함수 복원 + `test_collector_resilience.py` 에 `test_main_entry_smoke` — STOP 플래그를 미리 세워 루프를 0바퀴 돌고 shutdown 까지 가며, 시그널 핸들러를 직접 호출한다.
- 5행 "record.sh 가 조용히 안 끝남 / timeout 이 recorder 를 뒤 프로세스 그룹에 둠 → 키보드 읽기에서 SIGTTIN 정지 / timeout --foreground + --disable-keyboard-controls / 11/05": 기록 파이프라인 첫 실행(E20)에서 `record.sh 30` 이 경고 한 줄 뒤 아무것도 안 찍고 30초가 지나도 끝나지 않았다. `timeout` 명령은 기본 동작으로 자식(recorder)을 **별도 프로세스 그룹**에 두고, `ros2 bag record` 는 키보드 제어(SPACE 일시정지) 때문에 터미널을 읽으려다 **SIGTTIN 신호로 정지**됐다 — 죽은 것이 아니라 멈춘 것이라 로그도 없고 30초 뒤 SIGINT 도 못 받았다. 해결: `timeout --foreground`(같은 프로세스 그룹에 둔다) + `--disable-keyboard-controls`(터미널을 아예 안 읽는다) + `--topics`(위치 인자는 Jazzy 에서 폐기 예고). `data_pipeline/record.sh` 18~23행 주석에 이 사고가 그대로 적혀 있다.
- 아래 비고 "배운 규칙 둘: 진입점(main)은 단위 테스트가 한 번은 타야 한다 · 문서 커밋이라도 push 뒤 CI 를 본다(빨간 배지는 포트폴리오 첫 화면)": 둘 다 4행에서 나왔다. 첫째는 테스트의 **범위** 규칙(클래스만이 아니라 진입점까지), 둘째는 **습관** 규칙(`gh run list -L 1`, 1초).
- `다음 ▶` 다리 "2주 일정 — 이 결정과 사고가 언제 일어났나? D0~D7 을 한 줄로": 결정(125~127)과 사고(128~129)를 시간 축에 올리면 장표 130 이다.

## 3. 용어와 단위

- 파라미터 파일(ROS 2): 노드가 시작할 때 읽는 YAML 설정. 값마다 타입(정수, 문자열, 배열…)이 정해져야 한다.
- 프로세스 그룹과 전경(foreground)/배경(background): 터미널은 한 번에 한 그룹만 "전경"으로 둔다. 배경 그룹의 프로세스가 터미널을 **읽으려** 하면 커널이 SIGTTIN 을 보내 정지시킨다(멈춤, 죽음 아님). `pkill -CONT` 로 다시 깨울 수 있다.
- SIGINT·SIGTERM·SIGTTIN: 프로세스에 보내는 신호. INT = Ctrl-C(rosbag2 는 이걸 받아야 파일을 곱게 닫는다), TERM = 종료 요청, TTIN = 배경에서 터미널 읽기 시도.
- 시그널 핸들러(`request_stop`): 신호가 오면 실행되는 함수. 여기서는 "STOP 플래그를 세워 루프를 멈추라"는 역할.
- NameError: 파이썬에서 정의되지 않은 이름을 쓸 때 나는 오류.
- 스모크 테스트(smoke test): 깊이 검사하지 않고 "켜지고 꺼지나"만 보는 테스트. 진입점 한 바퀴.
- Ubuntu Pro 토큰: Canonical 이 개인에게 무료로 주는 구독 키. 실시간 커널 패키지를 받는 데 필요. 비밀값이라 문서·영상·저장소에 쓰지 않는다.
- `chown -R`: 파일 소유자를 바꾸는 명령. `-R` = 폴더 아래 전부.

## 4. 쉬운 예시

- 1행 비유: 서류 양식에 "가족 이름(여러 명)" 칸이 비어 있을 때 빈 칸을 내면 "이게 이름인지 번호인지 모르겠다"고 접수가 거부된다. 칸을 아예 지우고 내면 "없음"으로 처리된다.
- 2행 비유: 창 둘을 띄워 놓고 집(WSL)에서 칠 명령을 사무실(Pi) 창에 치면, 사무실이 자기 자신에게 택배를 보내려다 실패한다. 모든 지시문 앞에 "집에서 / 사무실에서" 를 붙이기로 했다.
- 4행 숫자: 단위 테스트 15건이 초록이었는데 통합 테스트 1건만 빨강 — 15 대 1 이지만 그 1 이 "프로그램이 켜지지도 않는다"였다. 스모크 1개가 그 구멍을 영구히 막았다.
- 5행 비유: 녹음기(recorder)에게 "30초 뒤 멈춰"라고 타이머(timeout)를 걸었는데, 타이머가 녹음기를 다른 방에 두어 녹음기가 리모컨 입력을 기다리다 얼어 버렸다. 같은 방에 두고(`--foreground`) 리모컨을 떼어 내면(`--disable-keyboard-controls`) 된다.

## 6. 자주 하는 오해·함정

- "조용히 안 끝난다 = 죽었다(hang)"는 오해: 5행은 **정지(stopped)** 였다. `ps -o stat` 의 `T` 가 그 표시고, `pkill -CONT` 로 깨운 뒤 `-INT` 를 보내면 파일을 곱게 닫는다. 스크립트 안에서 터미널을 읽는 프로그램을 `timeout` 으로 감쌀 때는 `--foreground` 가 필수다.
- "단위 테스트가 다 초록이면 프로그램이 켜진다"는 믿음: 클래스 단위 테스트는 진입점을 안 탄다. 규칙 1 이 생긴 이유.
- "CI 는 코드 바꿀 때만 본다": 11/05 문서 위주 push 사이에 빨간 배지가 한동안 보였다. 규칙 2.
- 가입 실패를 입력값 탓으로 돌려 이름·이메일을 바꿔 가며 반복하는 것: 오류문에 "Launchpad … timed out" 이 적혀 있었다. 저쪽 문제면 기다리는 것이 답이다.
- 측정을 `sudo` 로 돌리면 결과 파일이 root 소유가 된다. 커밋 전에 `chown` — 또는 처음부터 Pi 에서는 커밋하지 않는다.
