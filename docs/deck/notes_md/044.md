# 장표 044 — 단계 7 들머리 — 로봇이 움직인다: 물리는 목표를 따라갔나, 어디까지?
*위치: 1부 로봇을 움직이는 길 · 단계 7/10 로봇이 움직인다 · ① 들머리*

## 1. 이 장표가 왜 있나
단계 1~6 으로 명령이 1 ms 마다 안전 검사를 거쳐 백엔드(MuJoCo)의 액추에이터까지 들어갔다. 이 장표는 1부의 제목 "로봇을 움직이는 길"이 실제로 끝에 닿았는지를 묻는 들머리다 — "목표를 넣었으니 움직였겠지"가 아니라 **관절이 어디까지 갔는지 숫자로** 확인하고, 목표와 다르면 그 차이가 설명되는지를 본다. 들머리 장표의 공통 꼴(들어온 것 → 문제 → ◇기준 → 확인 방법 → 결과 → 판단 → 다음)을 그대로 따르고, 실험 자체(E15 → E16 사슬)는 3부 장표 096 으로 미룬다. 다음 장표 045(큰 숫자 넷)와 046(관절별 막대 그래프)이 이 들머리의 '결과' 상자를 펼친 것이다.

## 2. 장표를 하나씩 읽기
상자 여섯 개가 두 줄(한 줄에 셋)로 이어진다.

- 회색 "들어온 것 — MuJoCo 액추에이터(position)에 들어간 목표 6개 (단계 6)": 단계 6 의 `write_command` 가 `ctrl[액추에이터]` 에 넣은 값. position 타입 액추에이터는 "이 각도로 가라"를 받아 내부 PD 제어로 토크를 낸다.
- "문제 — 시뮬레이션이라도 물리(중력·유한한 모터 강성)가 있다. 목표를 줬다고 그 자리에 가는 게 아니다": SimLag(수식)였다면 목표에 정확히 수렴하지만 MuJoCo 는 중력과 모터 강성(kp 가 유한)을 계산한다. 그래서 "어디까지 가나, 차이가 있으면 설명되나"가 질문이 된다.
- 노란 마름모 "기준 — 정상 상태에서 실제 위치 ≈ 목표인가? 차이가 있으면 물리로 설명되고, 숫자로 재현되나?": 합격선이 "오차 0"이 아니라는 점이 중요하다. 차이가 나도 ① 물리로 설명되고 ② 다른 측정에서 같은 숫자가 나오면 통과.
- 파란 "확인 방법 — E16: 목표 [0.3, −0.2, 0.1, 0, 0, 0.5] 를 50 Hz 로 주고 ros2 topic echo /joint_states, 기록 요약(E20)의 추종 오차 표와 대조 → 사슬은 3부 장표 96": 두 가지 측정. 하나는 11/04 터미널에서 `/joint_states` 를 눈으로 읽은 것(E16), 하나는 11/05 30초 기록을 `bag_to_csv.py` 가 자동으로 요약한 추종 오차 표(E20). 둘이 맞아야 "재현"이다. 관절 순서는 shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper(모델 이름 Rotation, Pitch, Elbow, Wrist_Pitch, Wrist_Roll, Jaw).
- "결과 — 어깨(Pitch) −0.181(목표 −0.200, 0.019 rad = 1.1° 처짐), 팔꿈치 0.109(0.5°), 중력이 안 걸리는 축은 목표 그대로. 요약 표도 0.0191": 어깨 관절만 목표에 0.019 rad 못 미치고, 팔꿈치가 0.009 rad, 나머지(수평 회전 shoulder_pan, wrist_roll, 그리퍼)는 목표 그대로. 자동 요약의 추종 오차 표가 shoulder_lift 0.0191 로 같은 값을 냈다. 1.1° 는 0.019 × 57.3.
- 진한 "판단 → 다음 — 움직인다 ✓. 처짐 = 중력 → 중력 보상이 다음 할 일(2주 밖, 보류). → 단계 8: 이 사실을 누가 아나?": 통과. 차이는 팔 무게가 걸리는 관절에서만, 중력 방향으로 났으니 물리로 설명된다. 고치는 방법(중력 보상 = 토크 피드포워드)은 2주 계획 밖 보류 항목. 다음 질문은 "로봇이 움직였다는 사실을 RT 스레드 밖(사람·기록·관제)이 어떻게 아나" — 단계 8.
- 아래 글 "이 단계의 장표: ③ 실측 숫자 KPI(1장). 물리 실험 사슬 E15 → E16 은 3부 검증. 넘어가는 조건: …": 이 단계에는 코드 장표가 없다(코드는 단계 6 에서 끝났고, 여기서는 결과를 본다). 실제로는 KPI 1장(045)에 막대 그래프 1장(046)이 더 붙어 있다.

## 3. 용어와 단위
- 정상 상태(steady state): 움직임이 멈춘 뒤의 상태. 그때 남는 "목표 − 실제"가 정상 상태 오차.
- position 액추에이터 / kp: "각도를 주면 토크 = kp × (목표 − 현재)" 로 끌어당기는 모터 모델 / 그 스프링의 세기. 유한하므로 무게가 걸리면 오차가 0 이 될 수 없다(오차 = 중력 토크 ÷ kp).
- 중력 처짐: 팔 무게가 만드는 토크 때문에 관절이 목표보다 중력 방향으로 조금 내려가 멈추는 현상.
- 중력 보상(토크 피드포워드): 자세에서 중력 토크를 계산해 그만큼 미리 더해 주는 것. 넣으면 처짐이 사라진다.
- rad ↔ °: 1 rad = 57.3°. 0.019 rad = 1.1°, 0.009 rad = 0.5°.
- 추종 오차(tracking error): 같은 시각의 |목표 − 실제 위치|. 자동 요약은 30초 평균과 최대를 낸다.
- 50 Hz: 1초에 50번 명령 발행(20 ms 마다). 노드의 루프 1 kHz, 상태 발행 100 Hz 와 구분.
- E15 / E16 / E20: 실험 번호. 물리 한 주기 비용 / 중력 처짐 첫 관찰 / 기록 파이프라인 첫 실행. 한 장씩 `docs/experiments/`.

## 4. 쉬운 예시
- 비유: 용수철 저울에 짐을 올리면 눈금이 0 이 아닌 자리에서 멈춘다. 용수철(kp)이 셀수록 덜 내려가지만 0 은 아니다. 수평으로 미는 힘에는 짐 무게가 안 걸리니 그 방향 눈금은 정확하다 — shoulder_pan 과 wrist_roll 이 0 인 이유.
- 숫자 예시: 어깨 처짐 0.019 rad 는 팔 길이 30 cm 끝에서 호 길이 0.30 × 0.019 = 0.0057 m ≈ 6 mm. 작은 물건을 집는 작업이면 성공과 실패를 가르는 크기다. 그래서 "중력 보상이 왜 필요한가"의 근거 숫자가 된다.

## 5. 숫자의 출처와 다시 확인하는 법
- 확인: 자동 요약의 추종 오차 shoulder_lift 0.0191 · elbow_flex 0.0094 · wrist_flex 0.0025 · 나머지 0.0000~0.0001 은 `docs/measurements/record_summary_wsl_20261105.md` "추종 오차" 표. 목표 −0.200 + 0.0191 = −0.1809 ≈ −0.181, 0.100 + 0.0094 ≈ 0.109 가 장표의 실제 위치. 상세는 `docs/experiments/E20.md` §3·§4-2.
- 확인: 11/04 의 눈 측정은 `docs/LOG.md` 2026-11-04 (D5 MuJoCo) "물리가 보여 준 것": 위치 [0.299, −0.180, 0.109, 0.002, 0.000, 0.499] — 어깨 0.020 rad(약 1.1°). `docs/experiments/E16.md` §3 표. 11/04 값(−0.180)과 11/05 값(−0.181)은 0.001 rad 차이로 같은 급이며, 장표는 11/05 기록값을 적었다.
- 확인: 명령 50 Hz 와 목표 여섯 값은 `docs/experiments/E20.md` §2 (`ros2 topic pub -r 50 /joint_command …`), 환경은 WSL2 + ROS 2 Jazzy + `so101_mujoco.params.yaml`, 일반 스케줄링(RT 아님).
- 확인: "중력 보상은 2주 밖 보류"는 `docs/experiments/E16.md` §4-3, `docs/HANDOVER.md` 보류 목록, `docs/DECISIONS.md` 2026-11-03 "6주 계획을 2주로".
- 확인: 1.1° = 0.019 × 57.3 = 1.09°; 0.5° = 0.0094 × 57.3 = 0.54°.
- 추정: 팔꿈치 0.009 rad 도 같은 원인(손목·그리퍼 무게)의 작은 버전이라는 설명은 E16·E20 의 추정이다. kp 값과 링크 질량으로 계산해 맞춰 보지는 않았다.

## 6. 자주 하는 오해·함정
- "오차가 있으니 제어가 틀렸다"가 아니다. position 제어의 정상 상태 오차는 물리가 있으면 반드시 생기며, 그것이 보이는 것 자체가 "물리가 들어왔다"는 증거다. SimLag 에서는 전부 0 이었을 것.
- 이 숫자는 WSL2 시뮬레이션 값이다. 실물 SO-101 도 같은 자리(어깨)에서 같은 방향으로 처지겠지만 크기는 실물 모터의 kp·마찰·백래시에 달려 있어 실측 전에는 숫자를 옮기지 않는다(E16 의 추정).
- "요약 표도 0.0191"에서 평균 = 최대인 이유는 목표가 고정값이고 기록 시작 전에 이미 정상 상태였기 때문. 목표가 뛰는 구간을 기록하면 최대가 커진다(변화량 제한 0.05 rad/주기로 따라가는 동안).
- 들머리의 '확인 방법'은 실험을 가리키기만 한다. 사슬(E15 물리 비용 0.9% → E16 처짐)과 합격선은 3부 장표 096 에 있다.

## 7. 면접 한 문장
"목표 여섯 개를 넣자 로봇이 움직였고, 어깨 관절만 1.1° 처진 채 멈췄습니다 — 팔 무게가 걸린 관절에서 position 제어의 정상 상태 오차가 난 것이고, 눈으로 읽은 값과 자동 요약 표가 같은 숫자를 내서 재현도 확인됐습니다. 중력 보상이 다음 할 일이라는 근거 숫자입니다."
