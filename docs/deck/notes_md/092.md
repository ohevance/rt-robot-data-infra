# 장표 092 — 단계 4 검증 — 표① 실험 사슬 (2/3) — E18 → E19-a/b/c: 커널 → 고정 → 격리
*위치: 3부 검증 · 단계 4 RT 1 ms 루프 · 실험 사슬 2/3 (Pi 4)*

## 1. 이 장표가 왜 있나
앞 장표(091)의 결론은 "우선순위로는 꼬리를 못 자른다 → 커널(PREEMPT_RT)과 실물 보드가 필요하다"였다. 이 장표는 그 처방을 **실물 Raspberry Pi 4 에서 변수 하나씩 바꿔 가며** 확인한 네 실험(E18, E19-a, E19-b, E19-c)이다. 질문은 단계 4 들머리의 기준 그대로 — "부하 중 깨어남 지연 max 가 200 us 아래로 들어오나?". 일반 커널(781 us)에서 출발해 커널을 바꾸고(301), CPU 에 고정하고(311), CPU 를 격리하니(189) 비로소 기준을 넘었다. 중간에 기준을 못 넘을 때마다 "왜 못 넘었나"가 다음 실험을 낳는 모양이 순서도에 그대로 보인다.

## 2. 장표를 하나씩 읽기
- **상자 "E18 Pi 4 일반 커널 기준값 — 한가 300 s · 부하 120 s"**: RT 커널을 켜기 전에 **같은 보드·같은 측정기·같은 부하**로 "전" 값을 남긴다. 그래야 "커널을 바꿨더니 얼마가 됐다"를 말할 수 있다. 보드는 Pi 4B 4 GB, Ubuntu 24.04, 커널 `6.8.0-1064-raspi`, 방열판 없음, 클럭은 performance 로 고정. 한가 상태 300초(cyclictest), 부하 120초(cyclictest; jitter_bench 는 60초). 부하는 `stress-ng --cpu 4 --io 2 --vm 1`.
- **마름모 "일반 커널로 충분한가? 부하 max < 200, 한가도 안정?"**: 만약 일반 커널이 이미 합격이면 RT 커널은 필요 없다. 그 가능성부터 지운다. 기준 200 us 의 근거: 1 ms 예산에서 제어+물리가 p99 약 145 us(E15)를 쓰므로 지연에 줄 수 있는 몫이 200 us 쯤이고, Pi 4 + PREEMPT_RT 의 알려진 수준(100~200 us)과도 맞춘 값이다.
  - **답 "아니오: 부하 781(jitter)·695(cyclictest), 한가도 5분에 376"**: 부하 중 max 781.2 us(jitter_bench 60 s), 695 us(cyclictest 120 s, 4 CPU 중 최악). 한가해도 5분 동안 한 번 376 us. 기준의 3.9배. 불합격 — 그러나 이제 가상 머신이 없으니 범인은 커널로 좁혀진다.
- **상자 "E19-a PREEMPT_RT — 6.8.0-2054-raspi-realtime"**: 변수 하나만 바꾼다 — 커널. Ubuntu Pro 의 `realtime-kernel --variant=raspi` 로 설치한 PREEMPT_RT 커널. `/sys/kernel/realtime` 이 1 이면 켜진 것.
- **마름모 "부하 max < 200?"**:
  - **답 "아니오: 301 (781 의 1/2.6, p99 는 146→185 비용)"**: max 는 300.6 us 로 2.6배 줄었다. 그러나 아직 200 을 넘는다. 그리고 정직하게 적어야 할 비용 — p99 는 145.7 → 185.2 us 로 오히려 조금 나빠졌다. RT 커널은 "최악의 상한"을 사는 대신 "보통 때"를 조금 내준다(인터럽트가 스레드가 되어 평소 비용이 는다).
- **상자 "E19-b + CPU 3 고정 — 옮겨 다님이 원인?"**: 남은 300 의 범인 후보 1 — 리눅스가 스레드를 빈 CPU 로 옮기며(마이그레이션) 캐시가 식고 스케줄러 비용이 드는 것. 흔한 처방 "RT 스레드를 CPU 하나에 고정"을 시험한다(`--cpu 3`).
- **마름모 "고정으로 줄었나?"**:
  - **답 "아니오: 311"**: 311.5 us. 변화 없음(잡음 범위). 옮겨 다님은 범인이 아니다.
- **상자 "E19-c + isolcpus=3 — 그 CPU 의 다른 일 때문?"**: 범인 후보 2 — CPU 3 위에 올라오는 다른 일(stress-ng 작업자, IRQ 스레드, 커널 스레드). 부팅 인자 `isolcpus=3 nohz_full=3 rcu_nocbs=3` 으로 CPU 3 을 일반 스케줄링에서 떼어 내고 RT 스레드만 올린다.
- **끝 상자 "예: max 189, work max 135→53 — 표① 통과 — 1 ms 의 19%"**: max 189.3 us 로 기준 통과. 결정적 증거는 `work time` max — 매 주기 50 us 일하는 데 실제 걸린 최악 시간이 일반 커널 134.9 → RT 97.7 → 고정 86.1 → **격리 53.1 us**. 50 us 일하는 동안 3 us 밖에 안 밀렸다 = 그 CPU 에 경쟁자가 사라졌다는 직접 증거. 189 us 는 1 ms 예산의 19%.
- **아래 설명 "cyclictest 도 같은 방향: 한가 376→37(10배), 부하 695→132(5배). 전부 스로틀 0"**: 표준 도구로도 같은 방향이 확인된다(일반 → RT). 모든 측정에서 온도 스로틀 플래그가 0 이었으므로 클럭 저하가 섞이지 않았다.

## 3. 용어와 단위
- **PREEMPT_RT**: 커널이 하던 일을 급한 스레드가 중단시킬 수 있게 만든 리눅스 패치. 인터럽트 핸들러가 스레드가 되고 스핀락이 잠들 수 있는 락이 된다. `/sys/kernel/realtime = 1`.
- **마이그레이션 / CPU 고정(pin, affinity)**: 스레드가 CPU 사이를 옮겨 다니는 것 / 한 CPU 에 못 박는 것.
- **isolcpus / nohz_full / rcu_nocbs**: 부팅 인자. 그 CPU 를 일반 스케줄링에서 제외 / 그 CPU 의 주기적 틱 인터럽트를 줄임 / RCU 뒷정리를 다른 CPU 로 보냄. 셋이 묶여 "격리".
- **work time**: 매 주기 50 us 일하는 데 실제 걸린 시간. 50 보다 크면 일하는 도중에 밀린 것.
- **cyclictest**: 리눅스 실시간 커뮤니티의 표준 지연 측정 도구. `-S` 는 CPU 마다 스레드 하나씩.
- **stress-ng**: 부하 생성 도구. `--cpu 4 --io 2 --vm 1` = CPU 작업자 4 + 디스크 I/O 2 + 메모리 1.
- **스로틀(throttle)**: Pi 4 가 80 °C 근처에서 클럭을 내리는 것. 지연 측정을 오염시키므로 매 측정 뒤 플래그 0 을 확인한다.
- **us**: 마이크로초. 189 us = 0.189 ms = 1 ms 의 18.9%.

## 4. 쉬운 예시
- 비유: 한 명의 요리사(RT 스레드)가 1분마다 한 접시를 내야 한다. (1) 일반 커널 = 주방장이 가끔 요리사를 불러 세워 재고 정리를 시킨다(최악 781). (2) RT 커널 = 재고 정리는 언제든 중단 가능해진다(301). (3) 고정 = 요리사를 한 화구 앞에 세운다 — 하지만 그 화구 앞에 다른 사람들도 드나들어 별 차이 없다(311). (4) 격리 = 그 화구 구역에 요리사 외엔 출입 금지(189, 그리고 요리하는 중간에 거의 안 밀림).
- 숫자 예시: 1 ms 주기에서 제어+물리에 p99 145 us 를 쓴다면, 깨어남 지연이 189 us 일 때 합계 334 us — 예산의 1/3. 일반 커널의 781 us 였다면 합계 926 us 로 거의 꽉 찬다.

## 5. 숫자의 출처와 다시 확인하는 법
- 확인: 781.2 / 300.6 / 311.5 / 189.3 us 와 work max 134.9 / 97.7 / 86.1 / 53.1 = `docs/measurements/jitter_pi4_generic_stress.json`, `jitter_pi4_rt_stress.json`, `jitter_pi4_rt_stress_pin.json`, `jitter_pi4_rt_stress_isol.json` 의 `wake_us.max`, `work_us_stats.max`; 표로는 `docs/measurements/table1_pi4.md`.
- 확인: cyclictest 376(한가 300 s) → 37, 695(부하 120 s) → 132 = `cyclictest_pi4_generic_idle.txt`, `cyclictest_pi4_generic_stress.txt`, `cyclictest_pi4_rt_idle.txt`, `cyclictest_pi4_rt_stress.txt` (가장 나쁜 CPU 값), `table1_pi4.md`.
- 확인: p99 145.7 → 185.2 = 같은 JSON 들의 `wake_us.p99`.
- 확인: 측정 시간(300/120/60 s)·온도·스로틀 0 = 각 파일의 `.meta` (`duration_s`, `temp_before_mC`, `temp_after_mC`, `throttled_after`).
- 확인: 기준 200 us 의 근거와 각 실험의 질문·판단 = `docs/experiments/E18.md`, `E19a.md`, `E19b.md`, `E19c.md` 의 1절·5절.
- 다시 돌려 보기(Pi, RT 커널): `sudo scripts/jitter_run.sh pi4_rt_stress_isol 60 stress 3` → `python3 scripts/make_table1.py`.

## 6. 자주 하는 오해·함정
- "RT 커널만 켜면 끝" — 커널만 바꿔서는 301 로 기준을 못 넘었다. 격리까지 해야 189 였다. 반대로 격리만 하고 일반 커널이면? 이 사슬에서는 재지 않았다(변수 하나씩의 순서상 RT 다음에 격리).
- "CPU 고정이 RT 의 기본 처방" — 여기서는 효과가 없었다(311). 고정은 옮겨 다님만 막고, 그 CPU 의 다른 일은 못 막는다. 격리가 그 일을 치운다.
- RT 커널의 비용을 숨기지 말 것: p99 146 → 185 로 나빠진 줄을 표에 그대로 둔 이유. "상한을 사고 평균을 조금 내준다"가 정확한 표현.
- 열: 부하 75초에 45 → 75 °C 까지 올랐다(방열판 없음). 그래서 부하 측정은 120초(cyclictest)·60초(jitter_bench) 상한이고, 플래그가 0 이 아닌 측정은 버린다.
- max 끼리 비교할 때 측정 시간을 맞춰야 한다. 한가 376(300 s, cyclictest) 와 24.9(60 s, jitter_bench) 는 도구도 시간도 다르다.

## 7. 면접 한 문장
"일반 커널 781 → RT 커널 301 → CPU 고정 311 → CPU 격리 189 us — 커널이 최악을 자르고 격리가 나머지를 눌렀으며, 50 us 일하는 동안의 밀림이 135 에서 53 us 로 내려온 것이 '그 CPU 에 경쟁자가 없다'는 직접 증거입니다. 1 ms 예산의 19% 입니다."
