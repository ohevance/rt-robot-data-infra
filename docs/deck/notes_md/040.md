# 장표 040 — 단계 6 — 백엔드 A — SimLag: 로봇 없이 노드 전체를 돌리는 1차 지연 모델
*위치: 1부 로봇을 움직이는 길 · 단계 6/10 백엔드 · ② 코드 — 백엔드 A SimLag*

## 1. 이 장표가 왜 있나
- 장표 039 에서 로봇 쪽의 "모양" 세 함수를 봤다. 이제 그 모양을 채운 **첫 번째 구현**이다. SimLag 는 이 저장소에서 처음 만들어진 로봇(D1~D4)이고, MuJoCo 가 들어오기 전까지 ROS 2 노드 전체(명령 → 1 ms 루프 → 상태 발행 → 워치독)를 검증한 도구다.
- 왜 굳이 가짜 로봇이 필요한가: 실물도 시뮬레이터도 없는 상태에서 "제어 루프가 명령을 받아 상태를 내는 전체 흐름" 을 돌려 봐야 했기 때문이다. 수식 한 줄이면 충분하고, 외부 라이브러리가 없어 어디서든(CI 러너·Pi 포함) 빌드된다.
- 동시에 이 장표는 다음 장표(MuJoCo)와의 **대비**를 위해 있다. SimLag 에는 물리가 없다 — 그래서 단계 7 에서 보는 "중력 처짐" 을 SimLag 로는 절대 볼 수 없다. 그 차이가 "왜 물리 엔진을 들였나" 의 답이 된다.

## 2. 장표를 하나씩 읽기
코드는 `sim_lag_backend.cpp` 21~38줄. 첫 줄의 `}` 는 바로 앞 `init()` 함수의 닫는 괄호다(장표에는 안 보이지만 `init` 은 5~20줄에 있다: dof 와 주기를 받아 `dt_s_ = 주기(초)`, `alpha_ = dt_s_ / 시정수` 를 계산하고 배열을 0 으로 채운다. 시정수가 주기보다 짧으면 alpha 를 1.0 으로 잘라 "즉시 도달" 로 취급한다).

- 23~27줄 `write_command`: 목표 배열을 `target_[j]` 에 **복사만** 한다. 움직이지 않는다. 조건 `j < dof && j < dof_` 는 "넘어온 길이와 내 길이 중 작은 쪽까지만" — 범위 밖 접근을 막는 안전장치.
- 29줄 주석 "읽을 때 한 주기만큼 시간을 진행시킨다 (명령 쓰기 → 한 주기 뒤의 상태 읽기)": 이 구현의 핵심 설계. 물리를 진행시키는 시점을 `read_state` 로 두어, 제어 단계가 "쓰고 → 읽는" 순서(장표 029 의 ④)와 맞춘다.
- 30~38줄 `read_state`: 관절마다 네 줄.
  - 32줄 `before = position_[j]`: 지난 주기의 위치를 기억해 둔다.
  - 33줄 `position_[j] = before + (target_[j] - before) * alpha_`: **1차 지연 식**. 목표와 현재의 차이 중 alpha 비율만큼만 다가간다. alpha = 0.02 면 매 주기 남은 거리의 2% 씩.
  - 34줄 `velocity_[j] = (position_[j] - before) / dt_s_`: 속도 = 이번 주기에 움직인 거리 ÷ 주기. 단위 rad/s.
  - 35~36줄: 계산한 위치·속도를 호출자(제어 단계)의 배열에 써 준다.
- 상태 변수는 전부 고정 크기 배열(`kMaxJoints` = 64칸)이라 루프 안에서 할당이 없다 — RT 규칙(장표 039).

읽는 포인트:
- "position += (target − position) × alpha, alpha = 주기/시정수 = 1 ms / 50 ms = 0.02": 시정수(time constant) 50 ms 는 `robots/so101.yaml` 의 `sim_lag.time_constant_s: 0.05` 에서 온다(노드 파라미터 `sim_time_constant_s`).
- "목표의 63% 에 도달하는 데 약 50 ms": 1차 지연의 성질. 시정수만큼 시간이 지나면 남은 거리가 e 분의 1(약 37%)로 줄어, 즉 63% 를 간다. 95% 까지는 시정수의 3배(150 ms).
- "물리 없음: 관절 한계·충돌·중력 없음 → 중력 처짐은 여기서는 절대 안 보인다(E16 과 대비)": 식에 질량도 힘도 없으니 어떤 관절이든 목표에 정확히 수렴한다. 그래서 어깨가 1.1° 처지는 현상(장표 045)은 SimLag 에서는 원리적으로 나올 수 없다.
- "용도: ROS 2 노드 전체(명령 → 루프 → 발행 → 워치독)를 로봇·시뮬레이터 없이 시험. CI 러너에서도 돈다": 외부 의존성이 0 이라 GitHub 러너의 1단계 잡(rt_core)에서도 노드 논리를 검증할 수 있다.

## 3. 용어와 단위
- **1차 지연(first-order lag)**: 입력이 바뀌면 출력이 지수 곡선으로 서서히 따라가는 가장 단순한 동적 모델. 뜨거운 커피가 식는 모양, 서보가 목표각으로 가는 모양이 대략 이렇다.
- **시정수(time constant, τ)**: 1차 지연에서 63% 에 도달하는 시간. 여기서는 0.05 s = 50 ms.
- **alpha(α)**: 한 주기에 남은 거리의 몇 할을 가나. 주기 ÷ 시정수 = 0.001 / 0.05 = 0.02 (2%).
- **dt_s_**: 주기를 초 단위로 둔 변수. 1 ms = 0.001 s. 속도 계산에 쓴다.
- **rad, rad/s**: 각도(라디안)와 각속도. 1 rad ≈ 57.3°.
- **고정 크기 배열(kMaxJoints = 64)**: 최대 관절 수를 컴파일 때 정해 두고 실제 관절 수(dof)만 쓴다. 실행 중 메모리 할당을 피하기 위해서.

## 4. 쉬운 예시
- 비유: **온도 조절기 없이 식는 커피**. 90 °C 커피를 20 °C 방에 두면 차이(70 °C)의 일정 비율씩 식어 처음엔 빨리, 나중엔 천천히 20 °C 에 다가간다. SimLag 의 관절도 목표와의 차이의 2% 씩 매 1 ms 다가간다. 중력이라는 "바람" 은 이 모델에 없다.
- 숫자 예시: 관절이 0 rad 에 있고 목표가 0.3 rad 일 때. 1주기 뒤 0.3 × 0.02 = 0.006 rad. 50주기(50 ms) 뒤 약 0.3 × 0.63 = 0.19 rad. 150주기(150 ms) 뒤 약 0.285 rad(95%). 첫 주기의 속도는 0.006 rad ÷ 0.001 s = 6 rad/s 로 계산된다. 단, 단계 5 의 변화량 제한(0.05 rad/주기)은 **목표** 쪽에 걸리는 것이라 이 모델의 응답 속도와는 별개다.

- 확인: 시정수 50 ms — `robots/so101.yaml` `sim_lag.time_constant_s: 0.05`, 노드 파라미터 기본값 `sim_time_constant_s` 0.05 (`rt_control_node.cpp` 파라미터 선언부).
- 확인: SimLag 위에서 노드 전체를 검증한 기록 — `docs/experiments/E03.md`(노드 안 RT 루프, WSL), `docs/LOG.md` 2026-11-03 "결과(노드)".
- 다시 보는 법: `scripts/profile_to_params.py --backend sim_lag` 로 파라미터 파일을 만들고 노드를 띄우면 MuJoCo 없이 돈다. 같은 명령을 주고 `/joint_states` 를 보면 모든 관절이 목표에 정확히 수렴한다(E16 의 비교 대상).

## 6. 자주 하는 오해·함정
- "SimLag 는 시뮬레이션이다" — 아니다. 질량·힘·충돌이 없는 **수식 한 줄**이다. "시뮬레이션·CI" 라는 공고 항목에 답하려면 물리 엔진(다음 장표)이 필요했다(E15 1절).
- "왜 write_command 에서 바로 움직이지 않나?" — 제어 단계는 "쓰고 → 읽는" 순서로 부른다. 쓰는 순간 움직이면 같은 주기 안에 두 번 진행되는 꼴이 된다. 한 번만 진행시키려고 읽을 때로 몰았다.
- "alpha 가 1 보다 크면?" — `init` 에서 1.0 으로 자른다. 시정수가 주기보다 짧다는 뜻이니 "한 주기에 바로 도달" 로 취급한다.
- SimLag 결과(모든 관절 목표 수렴)를 보고 "제어가 완벽하다" 고 결론 내리면 안 된다. 물리를 넣자 어깨가 1.1° 처졌다(장표 045) — 가짜 로봇이 숨기는 것이 있다.

## 7. 면접 한 문장
- "처음 로봇은 '위치 += (목표 − 위치) × 0.02' 한 줄짜리 1차 지연 모델이었습니다 — 노드 전체 흐름을 로봇 없이 검증하기엔 충분했고, 물리를 넣자마자 그 한 줄로는 절대 못 보는 중력 처짐이 보였다는 점이 이 모델의 한계를 숫자로 말해 줍니다."
