# 장표 115 — 테스트 목록 — '테스트 케이스 등록'은 따로 없다, 전부 저장소의 코드이고 CI 가 push 마다 돌린다
*위치: 6부 믿을 수 있나 · 테스트 목록 20건*

## 1. 이 장표가 왜 있나
6부 표지(111)의 답 상자에 "테스트 20건(C++ 5 · Python 15)과 통합 스크립트"라고 적었다. 그 20건이 **무엇**인지, 어느 파일에 있고, 각각 무엇을 확인하고, CI 의 어느 잡에서 도는지를 한 표로 보여 주는 장표다. 제목의 "'테스트 케이스 등록'은 따로 없다"는 회사의 테스트 관리 도구(케이스를 등록하고 결과를 표로 보는 시스템)에 익숙한 사람을 위한 말이다 — 이 저장소에서는 테스트가 전부 **코드 파일**이고, 등록은 `add_test`(C++)와 `def test_`(Python)이며, 실행은 push 때마다 CI 가 한다. 앞 장표(112~114)가 '측정' 묶음이었고 이 장표부터 '테스트' 묶음(115~118)이 시작된다.

## 2. 장표를 하나씩 읽기
표는 머리말 한 줄 + 다섯 행, 열은 넷(묶음 · 파일 · 케이스 · CI 잡). 위에서 아래로 "빠르고 가짜인 것 → 느리고 진짜인 것" 순이다.

- 행 1 "C++ 단위 (ctest)" — 파일 `rt_control/rt_core/test/test_spsc_ring.cpp · test_control_step.cpp · test_state_machine.cpp · jitter_smoke` — 케이스 "4 — 링 버퍼(두 스레드, 역전 없음·드롭 허용) · 제어 단계(최신 명령·워치독·변화량 제한) · 상태 머신(전이·불법 거부) · 1 kHz 2초 드롭 0" — 잡 rt_core. 네 개가 `CMakeLists.txt` 의 add_test 로 등록되어 `ctest` 한 번에 돈다. 링 버퍼 테스트는 용량 경계(N−1 개까지), 순서 보존, 두 스레드 동시 실행에서 역순·중복 없음(드롭은 허용)을 본다. 제어 단계 테스트는 목표를 향해 움직이는가, 변화량 제한(목표가 1.0 rad 로 뛰어도 첫 주기는 max_step_rad 이하), 워치독(명령이 끊기면 멈춤, 다시 오면 풀림), 상태 벨트에 매 주기 샘플. 상태 머신은 전이표대로 가고 표에 없는 전이는 막히는가. jitter_smoke 는 측정기를 `--no-rt` 로 2초 돌려 드롭 0 이어야 통과 — RT 권한이 없는 러너에서도 돈다.
- 행 2 "C++ MuJoCo" — `test_mujoco_backend.cpp` — "1 — SO-ARM100 2,000주기 움직임 + 비용 p99 < 900 us → mujoco_backend_ci.json" — 잡 mujoco. 관절 0 에 +0.3 rad 목표를 주고 1 kHz 로 2,000주기(2초) 돌려 위치가 목표 쪽으로 가는지, 한 주기 비용(mj_step + 상태 읽기) p99 가 1 ms 의 90% 아래인지 본다. 결과 JSON 이 4부 KPI "0.9%"의 원본이다. 빌드 옵션(RT_CORE_WITH_MUJOCO)이 켜진 mujoco 잡에서만 등록된다.
- 행 3 "Python 단위 (가짜 브로커·DB)" — `fleet/tests/test_fleet_logic.py · test_ota_rollout.py · test_collector_resilience.py` — "6 + 3 + 6 = 15 — 에이전트 버퍼·재전송·유언·OTA, 배포 good/bad/timeout, 수집기 DB 중단·복귀 / backlog 상한 / 지속 세션 옵션 / 종료 flush / 옛 스키마 감지 / main() 스모크" — 잡 rt_core. 컨테이너 없이 `fake_mqtt.py`·`fake_psycopg.py` 를 끼워 넣어(다음 장표 116) 1초 안에 끝난다. 첫 파일 6건: 파싱, store-and-forward, 명령·OTA, 수집기 dry-run, 유언이 수집기에 닿는가, retained 상태·잠금. 둘째 3건: 정상 펌웨어·나쁜 펌웨어(롤백)·적용 시간 초과. 셋째 6건: DB 중단·복귀, backlog 상한, 지속 세션 옵션, 종료 시 pending flush, 옛 스키마 감지, main() 한 바퀴 스모크(11/05 사고 뒤 추가).
- 행 4 "통합 (진짜 컨테이너)" — `fleet/tests/integration.sh + fleet/chaos/assert_results.py` — "장애 3종 + 나쁜 펌웨어 롤백 + 정상 OTA 의 판정 규칙" — 잡 fleet_integration. 브로커·DB 컨테이너를 실제로 띄우고 수집기(지속 세션) + 가상 장치 10대 2 Hz 를 올린 뒤 장애 3종 → 정상 OTA → 판정(5단계). 결과가 `table3_ci.md`.
- 행 5 "연기(CI 단계, ctest 밖)" — `jitter_bench --no-rt 2초 → JSON → make_table1.py · 대시보드 JSON 생성 → 파싱` — "2 — '돌아간다'의 증거(지연 수치 아님)" — 잡 rt_core. ci.yml 의 두 단계: 측정기를 JSON 으로 돌려 표 생성기까지 통과하는가, 대시보드 생성기가 만든 JSON 이 파싱되는가. 수치는 참고도 아니고 '돈다'만.
- 아래 주석 "결과는 Actions 잡 로그의 'OK: …' / '100% tests passed'. 케이스별 표(JUnit 리포트)는 없다 — ctest·파이썬이 XML 을 내게 하고 리포터 액션을 붙이면 30분(우선순위 낮음). 출처: docs/ENVIRONMENT.md §5-7": 결과를 보는 곳과, 회사식 "케이스별 결과표"가 없다는 것을 숨기지 않고 그 비용(30분)까지 적었다.

## 3. 용어와 단위
- 단위 테스트: 함수·클래스 하나를 떼어 가짜 환경에서 확인. 통합 테스트: 진짜 부품(컨테이너)을 다 띄워 끝까지. 연기(smoke) 테스트: 켜지고 도는지만.
- ctest / add_test: CMake 의 테스트 실행기와 등록 명령. `ctest --output-on-failure` 로 돌리면 "100% tests passed".
- `def test_…`: 파이썬 테스트 함수. 이 저장소는 외부 프레임워크 없이 파일을 직접 실행한다(`python3 fleet/tests/test_fleet_logic.py`).
- 가짜(fake) 브로커·DB: paho-mqtt 와 psycopg 를 흉내 내는 작은 파이썬 모듈. 네트워크·컨테이너 없이 논리를 확인한다.
- SPSC 링 버퍼: 한쪽만 넣고 한쪽만 꺼내는 락 없는 원형 큐(1부 단계 3 의 우편함).
- 워치독: 명령이 일정 시간 안 오면 멈추게 하는 안전장치. 변화량 제한: 한 주기에 목표가 움직일 수 있는 최대량(max_step_rad).
- JUnit 리포트: 테스트 결과를 케이스별 XML 로 내는 표준 형식. CI 화면에 표로 붙일 수 있다.
- 2,000주기: 1 kHz 로 2초. p99 < 900 us: 100번 중 99번은 0.9 ms 안에.

## 4. 쉬운 예시
자동차 정비 비유: 단위 테스트는 부품 하나씩 벤치에서 돌려 보는 것(브레이크 패드만), 통합 테스트는 차를 실제로 조립해 시험 주행, 연기 테스트는 시동이 걸리는지만. 세 층이 다 있어야 "부품은 멀쩡한데 조립하면 안 돈다"(11/05 의 main() 사고)와 "조립은 됐는데 부품 하나가 느리다"를 다 잡는다.

숫자 예시: 20 = C++ 5(4 ctest + 1 MuJoCo) + Python 15(6 + 3 + 6). 통합 1벌과 연기 2개는 '건' 수에 넣지 않았다. 다 돌리는 데 CI 에서 rt_core 잡 약 1분 13초, mujoco 약 25초, fleet_integration 약 1분 52초.

## 6. 자주 하는 오해·함정
- "케이스 등록 시스템이 없으면 관리가 안 된다" — 코드가 곧 목록이고 git 이력이 곧 변경 기록이다. 다만 케이스별 결과표(JUnit)는 없고, 붙이려면 30분이라고 적어 두었다.
- "C++ 5" 를 WSL 에서 ctest 로 돌리면 4 만 보인다 — MuJoCo 테스트는 빌드 옵션이 켜져야 등록된다.
- 단위 테스트 15건이 다 통과해도 진입점이 깨질 수 있다 — 11/05 `request_stop` 삭제 사고. 그래서 main() 스모크가 15건 안에 들어갔다.
- 연기 테스트의 jitter 값은 지연 수치가 아니다. `--no-rt` 2초, '돈다'의 증거.
- 가짜 위의 통과는 "논리는 맞다"이지 "진짜 위에서도 된다"가 아니다 — 그래서 통합(진짜 컨테이너) 잡이 따로 있다(결정 기록 11/03 "CI 는 2단계: 가짜로 빠르게, 진짜로 한 번").

## 7. 면접 한 문장
