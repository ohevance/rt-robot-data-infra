# 장표 031 — 단계 5 — ② 워치독 — 50 ms 동안 명령이 없으면 지금 자리에 멈춘다 (check_watchdog)
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ② 코드 — 워치독*

## 1. 이 장표가 왜 있나
- step()(029)의 다섯 가지 중 **두 번째**, 세 위험 중 **끊김**을 막는 코드다. 상위 프로그램이 죽거나 네트워크가 끊겨 명령이 안 오면, 로봇은 마지막 목표를 향해 계속 간다. 그것이 가장 위험하다고 판단했고(DECISIONS D1), 이 함수가 50 ms 안에 그것을 멈춘다.
- "멈춘다"가 무슨 뜻인지가 중요하다. 급정지도, 0 위치 복귀도 아니고 **지금 있는 자리에 머무는 것**(목표 = 현재 위치)이다. 코드 한 줄 `desired_[j] = position_[j]` 이 그것이다.
- 함수 끝에서 상태 머신을 갱신하므로(`update_state_machine`), 이 함수는 워치독이면서 상태 머신에 사건을 넣는 입구이기도 하다.
- 위치 `rt_control/rt_core/src/control_step.cpp:83-100`.

## 2. 장표를 하나씩 읽기
- `void ControlStep::check_watchdog(std::int64_t now_ns)` — 인자는 step() 이 잰 지금 시각. 바로 앞에 불린 take_latest_command 가 `last_cmd_ns_` 를 갱신해 두었다.
- `bool stale = (last_cmd_ns_ == 0) || (now_ns - last_cmd_ns_ > cfg_.watchdog_ns);` — **끊김 판정 한 줄.** 두 경우가 끊김이다: 아직 명령을 한 번도 못 받았다(`last_cmd_ns_ == 0`, 시작 직후), 또는 마지막 명령으로부터 `watchdog_ns`(50,000,000 ns = 50 ms)가 지났다. 그래서 노드를 켠 직후에는 명령이 올 때까지 "멈춤" 상태로 시작한다.
- `if (stale) {` — 끊긴 경우.
- `if (!tripped_) counters_.watchdog_trips.fetch_add(1, relaxed);` — 지난 주기에는 정상이었는데 이번에 끊김이면 **전환 횟수**를 1 올린다. 끊긴 채로 1,000주기가 지나도 1 이다. "몇 번 끊겼나"를 세는 것이고 "끊긴 주기 수"가 아니다.
- `tripped_ = true;` — 지금 멈춤 상태.
- `for (...) desired_[j] = position_[j];` — 목표를 **현재 위치**로 바꾼다. 다음 단계의 변화량 제한이 `applied_` 를 이 값으로 끌어가므로 로봇은 그 자리에 머문다. 주석: "지금 있는 자리에 머문다".
- `} else { tripped_ = false; }` — 명령이 살아 있으면 정상.
- `counters_.watchdog_tripped.store(tripped_, relaxed);` — 지금 상태(true/false)를 rt_status 로 보이게 한다. rt_status 의 `"watchdog": "tripped"/"ok"` 가 이 값이다.
- `update_state_machine(got_command_this_cycle_, stale);` — 상태 머신에 사건을 넣는다: 끊김 → WATCHDOG_TRIP, 명령 도착 → COMMAND, RECOVERING 에서 정상 100주기 연속 → RECOVERED (`control_step.cpp:103-122`). 그래서 끊기면 RUNNING → FAULT, 명령이 다시 오면 FAULT → RECOVERING, 100 ms 뒤 READY.
- **오른쪽 요점**: stale 의 정의 · 멈춤 = 현재 위치(급정지·0 복귀 아님, D1) · 전환 순간만 센다(11/03 시험 trips 1) · 명령 재개 시 tripped false 지만 상태 머신은 RECOVERING 경유 · 실물에서는 토크 오프까지(Backend::safe_stop 자리, 2주 범위 밖).

## 3. 용어와 단위
- **워치독(watchdog)**: 개가 집을 지키듯 "신호가 끊기면 짖는" 장치. 임베디드에서는 보통 "일정 시간 안에 신호를 안 주면 리셋"이지만, 여기서는 "멈춤"이다.
- **stale**: "신선하지 않다", 즉 명령이 오래됐다는 뜻의 변수명.
- **watchdog_ns = 50,000,000 ns = 50 ms**: 50 Hz 명령(20 ms 간격) 기준으로 두세 개를 연속으로 놓쳐야 걸리는 값. 너무 짧으면 정상 지터에도 걸리고, 너무 길면 멈춤이 늦다.
- **tripped**: 워치독이 "걸렸다"는 상태. `watchdog_trips`(횟수)와 `watchdog_tripped`(지금 상태)는 다른 변수다.
- **멈춤(hold) = 목표 = 현재 위치**: 로봇이 더 움직이려 하지 않는 상태. 서보는 현재 위치를 유지하려 힘을 쓴다.
- **토크 오프(torque off)**: 모터의 힘을 끊는 것. 실물에서는 멈춤 뒤 이것까지 가야 한다(팔이 중력에 처질 수 있으므로 로봇에 따라 다르다). 아직 자리만 있다.
- **RECOVERING**: 끊김 뒤 명령이 돌아왔을 때 바로 RUNNING 으로 가지 않고 100주기(100 ms) 정상인지 확인하는 상태.

## 4. 쉬운 예시
- **엘리베이터 비유**: 조작반에서 1초마다 "정상" 신호를 보내다가 끊기면, 엘리베이터는 마지막 층을 향해 계속 가지 않고 **지금 위치에 서서 문을 유지**한다(멈춤). 급제동(승객이 넘어짐)도, 1층 복귀(움직임 자체가 위험)도 아니다. 신호가 돌아와도 바로 운행하지 않고 몇 초 동안 신호가 안정적인지 본 뒤(RECOVERING) 운행 가능(READY)으로 간다.
- **숫자 예시**: 50 Hz 명령이 정상이면 `now − last_cmd` 는 최대 20 ms 근처라 50 ms 를 넘지 않는다. 상위 프로세스를 죽이면 20 ms, 40 ms … 60 ms 에서 `stale` 이 true 가 되고 `watchdog_trips` 가 1 올라간다. 11/03 시험(E03)에서 발행을 끊자 정확히 trips 1 이었다(`watchdog` tripped → ok → tripped). 상태가 RUNNING → FAULT, 다시 켜면 RECOVERING → READY → (명령 계속) RUNNING 으로 가는 것은 단위 테스트 `test_control_step.cpp:90-113` 이 같은 코드로 확인한다.

## 6. 자주 하는 오해·함정
- "워치독이 걸리면 급정지한다" — 아니다. 목표를 현재 위치로 바꾸는 것뿐이고, 변화량 제한 때문에 `applied_` 가 현재 위치로 **부드럽게** 끌려간다. 급정지는 관성으로 물건을 떨어뜨릴 수 있다.
- "`watchdog_trips` 가 크면 오래 끊긴 것이다" — 아니다. 전환 횟수다. 1,000주기 끊겨도 1, 끊김·복구가 반복되면 그때마다 1 씩 는다. 반복이 많다면 명령 주기와 50 ms 가 너무 가깝다는 신호다.
- "명령이 다시 오면 바로 정상이다" — `tripped_` 는 바로 false 가 되지만 상태 머신은 RECOVERING 을 거쳐 100 ms 뒤에야 READY 다(장표 033·034). 두 개념을 분리한 이유는, 끊김 직후 한 번 온 명령이 진짜 복구인지 알 수 없기 때문이다.
- 시작 직후 `watchdog: tripped` 로 보이는 것은 버그가 아니라 설계다(`last_cmd_ns_ == 0`). 테스트 `test_control_step.cpp:64-68` 이 그것을 확인한다.

## 7. 면접 한 문장
"마지막 명령에서 50 ms 가 지나면 목표를 현재 위치로 바꿔 그 자리에 멈춥니다 — 급정지도 0 복귀도 아닌 '유지'를 택한 이유는 DECISIONS D1 에 있고, 전환 횟수만 watchdog_trips 로 세며, 명령이 돌아와도 상태 머신은 RECOVERING 100주기를 거쳐야 READY 로 돌아갑니다."
