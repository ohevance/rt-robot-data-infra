# 장표 086 — 검증 — 미뤄 둔 시험: 각 단계의 기준을 정말 넘었나
*위치: 3. 검증 — 각 단계의 기준을 정말 넘었나*

## 1. 이 장표가 왜 있나
1부(로봇을 움직이는 길 10단계)와 2부(데이터의 길 8단계)는 **길**을 보여 주는 데 집중했다. 그래서 각 묶음의 들머리(여섯 상자)에서 "결과" 한 줄과 "확인 → 장표 N" 만 적고, 그 숫자가 어떻게 나왔는지 — 측정기는 어떻게 생겼고, 기준을 못 넘었을 때 무엇을 바꿨고, 몇 번을 다시 쟀는지 — 는 전부 뒤로 미뤘다. 이 장표는 그 미뤄 둔 시험을 모아 보는 3부의 첫 장(섹션 표지)이다. 흐름 상자가 1·2부에서 들어온 것 → 3부의 질문 → 3부의 답을 한 줄씩 적고, 아래 차례(agenda)가 14장을 어떤 순서로 보는지 말한다. 발표 때 이 장표에서 "지금까지 본 숫자는 믿어도 되는 숫자인가"로 분위기를 바꾼다.

## 2. 장표를 하나씩 읽기
- 왼쪽 위 큰 번호 "03" 과 제목 "검증 — 미뤄 둔 시험: 각 단계의 기준을 정말 넘었나": 3부의 표지라는 뜻. 1·2부에서 "확인 → 장표 N" 으로 가리킨 번호들이 전부 이 부(087~100)에 있다.
- 부제 "들머리마다 '확인 → 장표 N' 으로 가리켜 둔 실험들을 단계 순서대로 본다. 기준(마름모)을 못 넘은 곳마다 '왜 못 넘었나'가 다음 실험을 낳았다": 3부의 읽는 규칙 두 가지. 첫째, 순서는 1부 단계 번호 순(단계 2 → 4 → 7 → 2부 ⑦⑧). 둘째, 실험은 한 번에 끝난 적이 거의 없고, 기준 미달 → 원인 → 다음 실험의 **사슬**로 되어 있다.
- 흐름 상자 첫 칸 "들어온 것": "1부(로봇을 움직이는 길)와 2부(데이터의 길)의 들머리에 적힌 '결과' 한 줄과 '확인 → 장표 N'". 앞 두 부가 남긴 숙제가 입력이다.
- 흐름 상자 둘째 칸 "질문": "각 단계의 기준을 정말 넘었나? 그 숫자는 어떻게 나왔고, 못 넘었을 때 무엇을 바꿨나?" 세 질문이 겹쳐 있다 — 넘었나(결과), 어떻게 쟀나(측정기), 못 넘었을 때(사슬).
- 흐름 상자 셋째 칸 "답": 네 덩어리를 화살표로 이었다. ① "표② DDS(단계 2: 측정기 · E04 사슬)" — 087 측정기 그림, 088 E04 사슬(1 MB 메시지 손실). ② "표① 1 ms 루프(단계 4: 측정기 · 백분위수 · 실험 사슬 E01→E19d 3장 · 표 · 결론)" — 089 jitter_bench 측정기, 090 백분위수 설명, 091~093 사슬 세 장, 094 표① 핵심 8줄, 095 결론. ③ "물리(단계 7: E15→E16)" — 096 한 장. ④ "표③ 관제(2부 ⑦⑧: E05→E13 '유실 0' 이 가짜였다 → 53 → 0, CI 에서도 0 · 표③-2·③-3)" — 097~099 사슬 세 장, 100 표.
- 차례 첫 줄 "단계 2 검증 2장 → 단계 4 검증 7장 → 단계 7 검증 1장 → 2부 ⑦⑧ 검증 4장": 2 + 7 + 1 + 4 = 14장 = 087~100. 단계 4(1 ms 루프)가 7장으로 가장 길다 — 이 저장소의 핵심 숫자(189 us)가 여기서 나오기 때문이다.
- 차례 둘째 줄 "그림 약속 그대로: 사각형 = 실험, 마름모 = 기준, 화살표 글 = 실제 값, 진한 상자 = 결론, 붉은 상자 = 실패·원인": 3부의 사슬 장표(chain)들이 쓰는 도형 규칙. 마름모에서 "아니오"로 빠지는 붉은 화살표가 다음 실험을 낳는 모양이 반복된다.
- 차례 셋째 줄 "→ 다음: 길과 검증을 다 봤다. 이 길과 숫자가 공고 네 항목을 다 덮나? (4부)": 3부가 끝나면 출발점(공고)으로 돌아간다.

## 3. 용어와 단위
- 검증(verification): "기준을 넘었나"를 실제 숫자로 확인하는 일. 여기서는 측정 → 기준(마름모) 비교 → 못 넘으면 원인 → 다음 실험.
- 들머리: 각 묶음의 첫 장표(여섯 상자: 들어온 것·문제·기준·확인 방법·결과·판단).
- 표①·②·③: 이 저장소의 측정 표 셋. 표① 1 ms 루프의 깨어남 지연(us), 표② DDS 왕복 지연·손실, 표③ 관제의 처리량·장애 유실·복구·OTA 롤백.
- 실험 번호 E01~E20: `docs/experiments/` 의 문서 이름. 3부에 나오는 것은 E01·E02·E04~E13·E15·E16·E18·E19a~d.
- 사슬(chain): 실험 → 기준 → 못 넘음 → 원인 → 다음 실험이 이어진 그림. 3부의 chain 장표가 이 모양.
- us(마이크로초): 100만분의 1초. 1 ms = 1,000 us.

## 4. 쉬운 예시
운전면허 시험 비유: 1·2부는 "차를 이렇게 운전한다"는 교본이고, 3부는 그 교본의 각 항목을 실제 시험장에서 통과했다는 성적표 묶음이다. 성적표에는 "한 번에 합격"보다 "첫 시험에서 왜 떨어졌고 무엇을 고쳐 다음에 붙었나"가 더 많이 적혀 있다 — 그게 사슬이다.

숫자 예시: 단계 4 의 사슬은 WSL 에서 우선순위만 올렸을 때 max 921 → 937 us(안 줄어듦, E01→E02) → Pi 4 일반 커널 781 us(E18) → RT 커널 301(E19-a) → 고정 311(E19-b) → 격리 189 us(E19-c) → "내 측정기가 맞나" 270 vs 274(E19-d). 여섯 번의 "기준 미달 → 다음"이 7장이 된 이유다.

## 6. 자주 하는 오해·함정
- "검증이 뒤에 있으니 덜 중요하다"가 아니다. 뒤로 뺀 이유는 발표 순서(길 먼저, 왕초보 입장)이지 비중이 아니다 — 14장으로 1부 다음으로 길다.
- 3부는 **단계 순서**(2 → 4 → 7 → 2부 ⑦⑧)이고 실험 번호 순(E01, E02, …)이 아니다. E04 가 E01 보다 먼저 나오는 이유.
- "기준을 넘었다"만 보면 안 된다. 이 저장소의 가장 큰 발견 두 개(RT 커널의 비용 p99 146 → 185, '유실 0' 의 거짓)는 기준을 **못 넘었거나 의심한** 자리에서 나왔다.
- 3부의 숫자는 어디서 쟀는지가 다르다 — 표①은 Pi 4(진짜 RT 커널), 표②·③은 WSL2 와 CI 러너(참고값·재현). 어디서 믿을 수 있나는 5부.

## 7. 면접 한 문장
"길을 먼저 보여 드리고 시험은 뒤로 모았습니다 — 3부 14장은 단계 순서로 '기준을 넘었나, 못 넘었을 때 무엇을 바꿨나'의 사슬이고, 핵심 숫자 189 us 와 유실 0 은 모두 처음 값이 아니라 여러 번 못 넘은 뒤의 값입니다."
