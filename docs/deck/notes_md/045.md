# 장표 045 — 단계 7 — 로봇이 이렇게 움직인다 — 목표 [0.3, −0.2, 0.1, 0, 0, 0.5] 를 주면
*위치: 1부 로봇을 움직이는 길 · 단계 7/10 로봇이 움직인다 · ③ 결과 — 실측 숫자*

## 1. 이 장표가 왜 있나
앞 장표(044, 단계 7 들머리)가 "물리는 목표를 따라갔나, 어디까지?"를 물었고, 이 장표가 그 답을 큰 숫자 넷으로 보여 준다. 1부 전체가 "명령 → 움직임"의 길이었으니 여기가 **길의 끝에서 실제로 읽은 값**이다 — 관절 셋의 실제 위치와, 그 값을 읽어 낸 `/joint_states` 토픽이 정말 100 Hz 로 나왔다는 사실. 숫자 아래 글머리표 셋은 "이 숫자가 어떻게 나왔나(단계 1~6 의 결과)", "왜 목표와 다른가(물리)", "다른 측정에서도 같은가(단계 9 의 자동 요약)"를 잇는다. 다음 장표 046 은 같은 결과를 관절 여섯 개 막대 그래프로 본다.

## 2. 장표를 하나씩 읽기
큰 숫자 넷(KPI)이 한 줄, 아래에 글머리표 셋, 맨 아래 출처 각주.

- "−0.181 rad — shoulder_lift(Pitch) 실제 위치, 목표 −0.200 → 0.019 rad(1.1°) 처짐": 팔을 앞뒤로 들어 올리는 어깨 관절. 팔 전체(팔꿈치·손목·그리퍼) 무게가 이 관절에 토크로 걸려 목표보다 0.019 rad 덜 올라간 자리에서 멈췄다. 1.1° = 0.019 × 57.3.
- "0.109 rad — elbow_flex 실제 위치, 목표 0.100 → 0.009 rad(0.5°) 처짐": 팔꿈치. 손목·그리퍼 무게만 걸리므로 처짐이 어깨의 절반 이하. 목표 0.100 보다 0.009 더 간 자리에서 멈췄다(추정: 이 관절은 양의 방향이 중력이 당기는 쪽이어서 부호가 어깨와 반대로 보인다 — 모델의 축 방향을 따로 확인하지는 않았다).
- "0.300 / 0.500 — shoulder_pan · gripper, 목표 그대로 (중력이 안 걸리는 축)": 수평 회전(shoulder_pan)과 그리퍼(Jaw)는 중력이 토크를 만들지 않아 목표에 그대로 닿았다. 자동 요약의 오차 0.0000 / 0.0001.
- "100.0 Hz — /joint_states 실제 발행 주기, 30초 2,964행, 틈 0": 위 숫자를 읽어 낸 토픽이 설계값(100 Hz)대로 나왔다는 증거. 2,964 ÷ 29.6초 = 100.1 → 100.0. 틈 0 = 연속한 두 메시지 사이가 30 ms(3주기) 넘게 벌어진 곳이 없다.
- 글머리표 1 "명령(단계 1)이 1 ms 마다(단계 4) 안전 검사(단계 5)를 거쳐 MuJoCo 액추에이터에 들어가고(단계 6), 물리가 관절을 움직였다. … (11/05 12:35 WSL, ros2 topic echo /joint_states --once --field position)": 1부의 단계들을 한 문장으로 되짚고, 숫자를 읽은 명령을 적었다. `--once` 는 메시지 한 개만, `--field position` 은 위치 배열만 출력.
- 글머리표 2 "SimLag 였다면 전부 목표와 같았을 것이다 — 처짐은 물리(중력 + 유한한 kp 의 position 액추에이터)가 만든 '진짜 로봇스러운' 정상 상태 오차. 다음 단계는 중력 보상(토크 피드포워드) — 2주 범위 밖, 보류 항목": 수식 백엔드에는 중력이 없다. 처짐이 보이는 것 자체가 물리가 들어왔다는 증거이고, 그것을 없애는 일(중력 보상)은 계획 밖으로 미뤘다.
- 글머리표 3 "같은 숫자가 기록 파이프라인의 자동 요약(단계 9)에 추종 오차 표로 다시 나온다: shoulder_lift 0.0191, elbow_flex 0.0094": 눈으로 읽은 값과 30초 기록을 자동 요약한 값이 같다 → 재현. −0.200 + 0.0191 = −0.181, 0.100 + 0.0094 = 0.109.
- 각주 "출처: docs/LOG.md 11/04 MuJoCo WSL, docs/measurements/record_summary_wsl_20261105.md, docs/experiments/E16.md·E20.md. rad → 도: × 57.3. 물리 비용(E15)과 이 처짐(E16)의 실험 사슬은 3부 장표 96": 첫 관찰은 11/04(LOG), 재현과 자동 요약은 11/05(record_summary). 실험 사슬은 3부.

## 3. 용어와 단위
- KPI(핵심 지표): 결과를 대표하는 숫자 몇 개. 여기서는 관절 위치 셋과 발행 주기 하나.
- rad / °: 각도 단위. 1 rad = 57.3°. 0.019 rad = 1.1°, 0.009 rad = 0.5°.
- shoulder_lift(Pitch) · elbow_flex(Elbow) · shoulder_pan(Rotation) · gripper(Jaw): 우리 쪽 관절 이름(괄호는 MuJoCo 모델 안 이름). `robots/so101.yaml` 의 두 목록이 같은 순서로 대응한다.
- 정상 상태 오차 / 중력 처짐 / kp / 중력 보상: 움직임이 멈춘 뒤 남는 목표 − 실제 / 팔 무게가 만드는 그 오차 / position 액추에이터의 스프링 세기 / 자세별 중력 토크를 미리 더해 처짐을 없애는 방법.
- /joint_states: 노드가 100 Hz 로 발행하는 관절 위치·속도 토픽(단계 8). `ros2 topic echo` 는 그것을 터미널에 찍는 명령.
- 틈(gap): 기록에서 메시지 간격이 설계 주기의 3배를 넘은 곳. 0 이면 기록이 한 번도 끊기지 않았다.
- WSL(WSL2): 윈도우 안의 리눅스. 여기 숫자는 실시간 커널이 아닌 PC 참고값이지만, 관절 위치는 물리 결과라 커널과 무관하다.

## 4. 쉬운 예시
- 비유: 선반에 "높이 1 m" 로 올려 둔 팔걸이가 무게 때문에 2 mm 내려가 멈춘 것. 선반(모터)이 단단할수록 덜 내려가지만 0 은 아니다. 옆으로 돌리는 방향(shoulder_pan)에는 무게가 안 걸려 정확하다.
- 숫자 예시: 어깨 처짐 0.019 rad 를 30 cm 팔 끝에서 보면 0.30 × 0.019 ≈ 6 mm. 팔꿈치 0.009 rad 는 팔꿈치 아래 15 cm 라면 약 1.4 mm. 그리퍼로 지름 1 cm 물건을 집는다면 6 mm 는 무시할 수 없다 — 중력 보상이 "다음 할 일"인 이유.

## 6. 자주 하는 오해·함정
- "−0.181 이 틀린 값"이 아니다. 목표 −0.200 에 대한 정상 상태 오차이고, position 제어에 무게가 걸리면 반드시 생긴다. 오차가 0 이면 오히려 물리가 꺼진 것(SimLag)을 의심해야 한다.
- 11/04 (−0.180) 와 11/05 (−0.181) 가 다르다고 재현 실패가 아니다. 0.001 rad(0.06°)는 PD 스프링의 잔여 진동·반올림 수준이다.
- 100.0 Hz 는 "로봇이 움직인 결과"가 아니라 "결과를 읽은 통로가 멀쩡했다"는 숫자다. 둘을 함께 놓은 이유는 위 세 숫자의 신뢰성을 네 번째가 받쳐 주기 때문.
- 이 장표의 숫자는 시뮬레이션(MuJoCo, WSL2) 값이다. 실물 SO-101 의 처짐 크기는 모터의 kp·마찰·백래시에 따라 다르므로 실측 전에는 옮기지 않는다.
- 그리퍼 0.500 은 "목표 그대로"지만, 0 → 0.5 로 가는 동안에는 단계 5 의 변화량 제한이 0.05 rad 씩 10주기(10 ms)에 나눠 보냈다(`step_limited` 10, LOG 11/04).
