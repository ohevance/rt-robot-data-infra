# 장표 032 — 단계 5 — ③ 변화량 제한 — 상위가 1 rad 를 요구해도 한 주기에 0.05 rad 만
*위치: 1부 로봇을 움직이는 길 · 단계 5/10 제어 단계(안전) · ② 코드 — 변화량 제한*

## 1. 이 장표가 왜 있나
- step()(029)의 다섯 가지 중 **세 번째**, 세 위험 중 **튐**을 막는 코드다. 상위 프로그램의 버그, 네트워크 재전송으로 뒤늦게 온 옛 값, 사람의 입력 실수 등으로 목표가 한 번에 크게 뛸 수 있다. 그것을 그대로 서보에 보내면 로봇이 최대 속도로 튀어 자기 몸이나 물건·사람을 친다.
- 이 함수는 "실제로 로봇에 보내는 값" `applied_` 가 한 주기(1 ms)에 `max_step_rad`(0.05 rad) 넘게 바뀌지 못하게 한다. 그래서 단계 5 전체에서 로봇에 쓰는 값은 `desired_` 가 아니라 **`applied_`** 다. 이 구분이 이 장표의 요점이다.
- 로봇에 보내기 직전의 **마지막 안전장치**다. 워치독이 목표를 현재 위치로 바꿔도 그 변화 역시 이 함수를 거치므로 "멈춤"도 부드럽다.
- 위치 `rt_control/rt_core/src/control_step.cpp:126-142`.

## 2. 장표를 하나씩 읽기
- `void ControlStep::limit_step()` — 인자가 없다. 멤버 변수 `desired_`(원하는 목표), `applied_`(실제 보내는 목표), `cfg_.max_step_rad` 만 쓴다.
- `bool limited = false;` — 이번 주기에 어느 관절이든 제한이 걸렸는지 표시.
- `for (std::uint32_t j = 0; j < cfg_.dof; ++j)` — 관절 6개를 하나씩.
- `double delta = desired_[j] - applied_[j];` — "지금 보내는 값에서 원하는 값까지 남은 거리"(rad). 양수면 늘리는 방향, 음수면 줄이는 방향.
- `if (delta > cfg_.max_step_rad) { delta = cfg_.max_step_rad; limited = true; }` — 남은 거리가 0.05 보다 크면 이번 주기에는 0.05 만 간다.
- `else if (delta < -cfg_.max_step_rad) { delta = -cfg_.max_step_rad; limited = true; }` — 반대 방향도 같다.
- `applied_[j] = applied_[j] + delta;` — 한 걸음 옮긴다. 남은 거리가 0.05 이내면 `delta` 그대로여서 바로 목표에 도달한다.
- `if (limited) counters_.step_limited.fetch_add(1, relaxed);` — 관절이 몇 개 걸렸든 **주기당 1** 만 센다. 그래서 11/03 시험의 "10" 은 "10주기 동안 제한이 걸렸다"는 뜻이다.
- **오른쪽 요점**: 마지막 안전장치 · 0.05 rad/주기 × 1,000주기 = 50 rad/s 까지 허용(실물에서는 프로필 `safety.max_step_rad` 로 줄인다) · 걸리면 step_limited(11/03 시험 10회) · 로봇에 보내는 값은 applied_.

## 3. 용어와 단위
- **변화량 제한(step limit / rate limit)**: 값이 한 번에 바뀔 수 있는 최대량을 정하는 것. 속도 제한의 가장 단순한 형태.
- **rad(라디안)**: 각도 단위. 0.05 rad ≈ 2.9°. 1 rad ≈ 57.3°.
- **rad/s**: 각속도. 0.05 rad 를 1 ms 마다 = 50 rad/s ≈ 2,865°/s ≈ 초당 8바퀴. 아주 빠르다. 그래서 "실물에서는 줄인다".
- **desired_ / applied_**: 원하는 목표 / 실제 보내는 목표. 이 함수가 둘 사이를 잇는다.
- **delta(Δ)**: 차이. 여기서는 "남은 거리".
- **step_limited**: 제한이 걸린 주기 수. rt_status 에 실린다. 정상 운전에서 0 이 아니어도 된다(목표가 뛸 때마다 잠시 걸리는 것은 정상). 계속 늘어나면 상위가 너무 빠른 목표를 내고 있다는 신호다.
- **robots/so101.yaml safety.max_step_rad**: 로봇 프로필의 값. 노드는 시작 때 이 값을 파라미터 `max_step_rad` 로 받는다. 기본 0.05.

## 4. 쉬운 예시
- **에스컬레이터 비유**: 목표 층이 10층(desired)이어도 에스컬레이터는 한 번에 한 칸(applied 가 0.05 씩)만 올린다. 10층 가는 데 시간이 걸리지만 아무도 넘어지지 않는다. 중간에 목표가 3층으로 바뀌면 지금 칸에서 내려오기 시작한다 — 이미 지난 10층 지시를 끝까지 따르지 않는다.
- **숫자 예시 1**: 그리퍼 목표를 0 에서 0.5 rad 로 한 번에 바꿨다(11/03 시험). 1주기째 applied 0.05, 2주기째 0.10 … 10주기째 0.50 도달. 10주기 모두 `limited` 였으므로 `step_limited` 10. 11주기부터는 delta 0 이라 안 센다. 걸린 시간 10 ms.
- **숫자 예시 2**: 상위가 실수로 1.0 rad 를 보냈다. 20주기(20 ms)에 걸쳐 도달한다(`test_control_step.cpp` 가 "20 × 0.05" 로 이것을 확인). 변화량 제한이 없었다면 서보는 1 rad 를 한 번에 받아 최대 속도로 움직였을 것이다.
- **숫자 예시 3(워치독과 함께)**: 명령이 끊겨 목표가 현재 위치로 바뀌어도, applied 와 현재 위치의 차이가 0.05 보다 크면 몇 주기에 걸쳐 부드럽게 멈춘다.

## 6. 자주 하는 오해·함정
- "변화량 제한은 속도 제한이다" — 비슷하지만 다르다. 이것은 **목표값**이 바뀌는 속도를 제한한다. 실제 관절 속도는 서보·물리가 정한다. MuJoCo 백엔드에서 어깨가 목표보다 0.019 rad 처지는 것(단계 7)은 이 제한과 무관한 물리 결과다.
- "step_limited 가 0 이 아니면 문제다" — 아니다. 목표가 뛸 때마다 잠시 걸리는 것은 정상 동작이다. 문제는 "계속 늘어날 때"다.
- "관절마다 센다" — 아니다. 주기당 1. 관절 6개가 동시에 걸려도 1.
- "0.05 는 안전한 값이다" — 1 kHz 에서는 50 rad/s 까지 허용하는 꽤 느슨한 값이다. 시뮬레이션용 기본값이고, 실물에서는 로봇 프로필에서 서보 사양에 맞게 줄여야 한다(장표의 "실물에서는 로봇 프로필로 줄인다").
- `applied_` 의 초깃값: 시작 때 0 이고 첫 명령까지는 워치독이 목표를 현재 위치로 두므로, 로봇이 0 위치가 아닌 자세로 켜져도 applied 가 그쪽으로 끌려간다.

## 7. 면접 한 문장
"로봇에 쓰는 값은 desired 가 아니라 applied 이고, applied 는 한 주기에 0.05 rad 넘게 못 움직입니다 — 상위가 1 rad 를 던져도 20 ms 에 걸쳐 따라가고, 걸린 주기는 step_limited 로 세어 rt_status 에 보이며(11/03 시험 10), 실물에서는 로봇 프로필의 safety.max_step_rad 로 서보 사양에 맞춰 줄입니다."
