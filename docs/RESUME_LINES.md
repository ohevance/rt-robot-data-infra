# 이력서·자기소개서용 문장 (포트폴리오 부분) — 숫자는 전부 `docs/measurements/` 에 원본이 있다

작성 원칙: 동사로 시작, 숫자 포함, 환경(가상/러너/RT 커널) 표기, 한 줄에 하나의 주장. [대괄호]는 아직 비어 있는 값.

## A. 이력서 프로젝트 항목 (3~5줄)

**rt-robot-data-infra — 휴머노이드 로봇용 실시간 제어·데이터 인프라 (개인, 2026.11, 2주, GitHub 공개 · CI 운영)**
- ROS 2 와 분리한 순수 C++17 실시간 핵심(SPSC 락프리 링, 절대 시각 타이머, SCHED_FIFO/mlockall)으로 1 kHz 제어 루프를 구현하고 지연 분포(p50/p99/p99.9/max)를 측정·공개 — [Pi PREEMPT_RT 실측 p99.9 __ us / max __ us], WSL 참고값 max 921 us.
- 백엔드 인터페이스(SimLag → MuJoCo)로 제어 코드 변경 없이 물리 시뮬레이션 연결; 물리 한 주기 비용 p99 8.5 us(1 kHz 예산의 0.9%), 중력 처짐 1.1° 를 숫자로 확인.
- MQTT·TimescaleDB·Grafana 관제(가상 50대): 장애 주입 4종(브로커·DB·수집기 중단, 나쁜 펌웨어)에서 **유실 0**, 전 장치 복귀 2.9초, 5% 카나리 롤백 1.0초 — 측정 도구의 맹점을 찾아 고치고 유실 53개의 원인 3가지를 추적해 제거.
- GitHub Actions 3단계 CI(단위·1 kHz 연기 → 컨테이너 통합 장애 주입 → MuJoCo 헤드리스)로 매 푸시마다 재검증. 문서 7종(읽기 가이드·결정 기록·작업 로그 등) 포함.

## B. 자기소개서 단락 (한 문단, 약 400자)

> 지원 직무가 요구하는 네 가지 — 실시간 Linux 미들웨어, 로깅·모니터링·업데이트, 센서 스트리밍 전처리, 시뮬레이션·CI — 를 2주 안에 한 저장소로 증명하는 것을 목표로 했습니다. 실시간 핵심은 ROS 2 와 분리한 순수 C++ 로 두어 어디서나 빌드·테스트되게 했고, 백엔드 인터페이스 덕에 1차 지연 모델을 MuJoCo 물리로 바꿔도 제어 코드는 바뀌지 않았습니다. 관제는 가상 장치 50대에 장애를 일부러 내어 복구와 유실을 숫자로 쟀는데, 처음 "유실 0" 은 측정 방법의 맹점이었습니다. 방법을 고치자 53개가 드러났고, 브로커 재시작 경쟁·수집기 종료 순간·큐 상한이라는 세 원인으로 갈라 둘은 고치고 하나는 설계 수치로 정리했습니다. 숫자를 믿기 전에 숫자를 만드는 방법을 의심하는 습관이, 28년간 통신 소프트웨어를 만들며 얻은 것 중 가장 쓸모 있는 것이라고 생각합니다.

## C. 면접 30초 자기소개 (말로)

> "통신 소프트웨어 28년, [시스템 규모·처리량 한 구절]. 로봇 쪽은 이번 포트폴리오로 2주 만에 실시간 루프부터 관제·OTA·CI 까지 한 벌을 만들었고, 숫자는 전부 GitHub 에 있습니다. 가장 자랑하고 싶은 건 유실 0 이라는 결과가 아니라, 0 이 거짓이었음을 스스로 찾아내 53 으로 고치고 다시 0 으로 만든 과정입니다."
